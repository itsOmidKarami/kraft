Install Kraft, start its server, and register it with Claude Code. At the end
the board loads at `http://127.0.0.1:8765` and `kraft admin doctor` has nothing
to say against your install.

## Before you start

You need:

- macOS or Linux. Windows is not supported, and WSL is untested.
- [uv](https://docs.astral.sh/uv/), or Homebrew: `uv --version` prints a
  version.
- `git` with a commit identity: `git config user.name` and
  `git config user.email` each print a value. Kraft commits the agents' work
  under that identity. If either prints nothing, run
  `git config --global user.name "Your Name"` and the same for `user.email`. A
  repo that sets its own identity is the case in
  [`no user.name configured`](/troubleshooting/why-did-my-item-stop#no-username-configured).
- Claude Code (`claude`), installed and logged in: `claude --version` prints a
  version. The shipped chains run every agent task on it; another agent CLI is a
  [harness](/reference/harnesses) and needs a chain edit.

## Installation methods

Pick one. Each tab says who it suits. Kraft is Apache-2.0 licensed: see
[Licenses](/project/status-and-support#licenses).

::tabs{sync="install"}
:::tabs-item{label="uv"}
For anyone with uv. It is the shortest path, and installs from PyPI. uv uses a
Python 3.12 or newer already on your machine, or fetches one. To choose the
interpreter yourself, add `--python 3.13`.

```bash
uv tool install kraft-sdlc
```

The package is [`kraft-sdlc` on PyPI](https://pypi.org/project/kraft-sdlc/)
because other tools already use the name `kraft` (Unikraft's CLI, for one). The
command it installs is still `kraft`.
:::

:::tabs-item{label="Homebrew (macOS)"}
For a Mac where you manage tools with Homebrew: `kraft admin update` then runs
`brew upgrade kraft`.

```bash
brew tap itsOmidKarami/kraft
brew install kraft
```
:::

:::tabs-item{label="Install script"}
For a machine with neither uv nor Homebrew. The script fetches the newest
release and installs `uv` first if you do not have it:

```bash
curl -fsSL https://raw.githubusercontent.com/itsOmidKarami/kraft/main/install.sh | sh
```

[`install.sh`](https://github.com/itsOmidKarami/kraft/blob/main/install.sh) is
short and worth reading before you pipe it to a shell. It says where it put
`kraft`, and when that directory is not on your `PATH` yet (usually after it
installed uv), it says to run `uv tool update-shell` and open a new terminal.
:::

:::tabs-item{label="From source"}
To run an unreleased commit or to work on Kraft itself. Besides uv and `git`,
you need [just](https://just.systems/) and Node 22 to build the board:

```bash
git clone https://github.com/itsOmidKarami/kraft.git
cd kraft
just setup     # Python and frontend dependencies
just install   # builds the board and installs the `kraft` command
```

To develop Kraft rather than run it, see [Contributing](/project/contributing).
:::
::

## Start the server

```bash
kraft
```

It prints its address and keeps running in this terminal:

```text
kraft: http://127.0.0.1:8765
```

When a newer release exists, a line `kraft: <installed> installed, <new> available - kraft admin update`
comes first; it is only a notice.
Leave the server running and open the address in a browser. With no repo connected, the
board shows **Nothing on the board yet**. Open a second terminal for everything
that follows.

If the command is not found, see
[`kraft`: command not found](/troubleshooting/starting-and-reaching-kraft#kraft-command-not-found).
If it prints `kraft: refusing to start - something is already answering on ...`,
see
[Kraft won't start: port already in use](/troubleshooting/starting-and-reaching-kraft#kraft-wont-start-port-already-in-use).

## Connect your agent

Kraft talks to agents through its MCP server, the command `kraft admin mcp`.
Register it with Claude Code first, then with any other agent you want to drive
Kraft from.

### Claude Code

The shipped chains run every [worker](/concepts/vocabulary#worker) on Claude Code, and Kraft refuses to launch
a Claude worker unless Claude Code knows the `kraft` MCP server: the worker asks
the permission gate through it. So register it even when you drive Kraft from
another agent.

Install the plugin:

```bash
claude plugin marketplace add itsOmidKarami/kraft
claude plugin install kraft@kraft
```

The plugin registers the MCP server itself: do not also run `kraft admin init`.

Without the plugin, register the server and the `/kraft:*` skills from a
terminal instead:

```bash
kraft admin init
```

It prints one `kraft: wrote <path>` line for each file it writes, starting with
the plugin's manifest:

```text
kraft: wrote /home/you/.claude/skills/kraft/.claude-plugin/plugin.json
kraft: wrote /home/you/.claude/skills/kraft/skills/board/SKILL.md
```

If it exits with `kraft admin init: could not register the MCP server
automatically`, it prints the `claude mcp add` command to run yourself. This
happens whenever `claude mcp add` exits non-zero, for example when `claude` is
not on your `PATH`.

Connecting a repo is step 2 of
[Your first work item](/get-started/first-work-item#_2-connect-a-repo).

### Other agents (optional)

To drive Kraft from Codex, Cursor, OpenCode, Amp, Antigravity or Gemini CLI,
register the MCP server with it.
[Use Kraft from your agent](/guides/day-to-day/agent-integration) has the
steps for each agent. [Give a worker its login](/guides/harnesses/give-a-worker-its-login)
covers what a worker needs when a chain runs on it. The
`kraft` command must be on your `PATH` for every agent.

## Check it worked

In the second terminal:

```bash
kraft --version
kraft admin health
kraft admin doctor
```

Each prints a few lines, cut here to the ones that matter. The paths in the
`doctor` rows are your own, and more rows come between them:

```text
$ kraft --version
kraft 2.0.0
$ kraft admin health
status         ok
version        2.0.0
$ kraft admin doctor
ok    server         http://127.0.0.1:8765
ok    agent: claude  /usr/local/bin/claude
ok    kraft on PATH  /home/you/.local/bin/kraft

all <N> checks passed
```

`doctor` prints one line per check, led by `ok`, `warn`, `FAIL` or `skip` (a
check that needs the server, when none is up), and a count at the end. You know
it worked when:

- `http://127.0.0.1:8765` shows the board.
- `kraft admin health` shows a `status` of `ok` and exits 0. It exits 1 when
  the server is down or degraded.
- `kraft admin doctor` ends in `all <N> checks passed`, followed by
  `, <W> warned` when a row warns. While any row reads `FAIL` it exits 1 and
  ends in `<F> of <N> checks failed`.

A `FAIL` row names its cause, and [Doctor failures](/troubleshooting/doctor-failures)
has every row and its fix. Once you connect a repo, `doctor` adds rows about
it. Four `FAIL` rows are common right after an install:

- `mcp server`: nothing registers Kraft's MCP server with Claude Code. Install
  the plugin, or run `kraft admin init`.
- `kraft on PATH`: the `kraft` command is not on your `PATH`. After a uv
  install, run `uv tool update-shell`, then start `kraft` again from a new
  terminal.
- `forge <repo>`: a connected repo has no GitHub or GitLab `origin`, or `gh`
  or `glab` is not on your `PATH`.
- `setup <repo>`: a connected repo has no `setup_command`. See
  [Doctor failures](/troubleshooting/doctor-failures) for both.

## Enable vector search

Search works out of the box in full-text mode. To add vector (semantic) search
to a uv or script install, reinstall the version you run, on the Python it runs
on, with the `vector` extra. It downloads a model of about 130 MB on the first
search.

```bash
uv tool install --force --python 3.X "kraft-sdlc[vector]==X.Y.Z"
```

Name both the Python and the version. Without the version, uv installs the
newest final release, which on a release candidate is an older Kraft that
refuses to start on its database. Without `--python`, uv rebuilds Kraft on its
own default Python. `kraft --version` prints `kraft X.Y.Z`.

`kraft admin doctor`'s `embeddings` row prints this command filled in for your
install. On a pipx or pip install it prints that installer's command instead;
the Homebrew formula does not ship the `vector` extra.

If the model cannot be downloaded (offline, or a proxy refuses Hugging Face),
search keeps working as full-text search and says so in a `note`. A search
that asks for `mode=vector` answers 422 with the reason. `kraft admin doctor`
fails its `embeddings` row, and `/api/health` reports the model's `state` as
`failing`.

On an Intel Mac, or on Apple Silicon before macOS 14, the `vector` extra
installs only on Python 3.12 or 3.13: on 3.14 the package that runs the model,
`onnxruntime`, has no build for those Macs, and the install fails to resolve.
Install Kraft with `--python 3.13` there. A plain `uv tool install` or
`install.sh` can pick 3.14 when the machine has no Python 3.12 or newer.

## Uninstall and where state lives

Uninstalling removes the `kraft` command and nothing else, so stop what runs
first, while the command exists:

```bash
kraft admin stop                # a running server
kraft admin uninstall-service   # only if you installed a service
```

`uninstall-service` deletes the launchd agent or the systemd unit, and a systemd
drop-in you made stays. [Run Kraft as a service](/guides/run/run-as-a-service#remove-the-service)
says what to save before you remove it. Then remove Kraft:

```bash
uv tool uninstall kraft-sdlc   # uv or script install
brew uninstall kraft           # Homebrew install
```

Two things are left:

- **Claude Code's registration.** Remove the plugin with
  `claude plugin uninstall kraft`. If you ran `kraft admin init` instead, remove
  its registration with `claude mcp remove --scope user kraft`, and delete the
  skill files it wrote under `~/.claude/skills/kraft/`. Another agent you
  registered keeps its registration: [Use Kraft from your agent](/guides/day-to-day/agent-integration)
  covers each one.
- **`$KRAFT_HOME`** (default `~/.kraft`), where Kraft keeps its state. Delete that
  directory yourself to discard it.

`config/` holds the YAML you edit, a plain directory you can diff, revert or
`git init`: see [Configuration](/reference/configuration). `run/` holds the
databases, logs, [worktrees](/concepts/vocabulary#worktree) and attachment
copies: see [Secrets and state](/project/data-and-privacy#secrets-and-state). A
second, fully separate instance needs its own `KRAFT_HOME` and its own port: see
[Run two instances](/guides/run/run-as-a-service#run-two-instances).
