Install Kraft, start its server, and register it with Claude Code. At the end
the board loads at `http://127.0.0.1:8765` and `kraft admin doctor` has nothing
to say against your install.

## Before you start

You need:

- macOS or Linux. Windows is not supported, and WSL is untested.
- [uv](https://docs.astral.sh/uv/), or Homebrew. Check uv with `uv --version`.
  uv uses a Python 3.12 or newer already on your machine, or fetches one. To
  choose the interpreter yourself: `uv tool install --python 3.13 kraft-sdlc`.
- `git`, with `user.name` and `user.email` set for the user Kraft runs as:
  `git config user.name` and `git config user.email` each print a value. If
  not, run `git config --global user.name "Your Name"` and the same for
  `user.email`, or set them in each repo you connect. Kraft commits the agents'
  work under that identity, and stops an item before its first task without one.
- Claude Code (`claude`), installed and logged in: `claude --version` prints a
  version. Every agent task in the shipped chains runs on it. Kraft supports
  other agent CLIs as [harnesses](/reference/harnesses), but using one means
  editing the chains.

## Installation methods

Pick one. Each tab says who it suits.

::tabs{sync="install"}
:::tabs-item{label="uv"}
For anyone with uv. It is the shortest path, and installs from PyPI.

```bash
uv tool install kraft-sdlc
```

The package is [`kraft-sdlc` on PyPI](https://pypi.org/project/kraft-sdlc/)
because other tools already use the name `kraft` (Unikraft's CLI, for one). The
command it installs is still `kraft`.
:::

:::tabs-item{label="Homebrew (macOS)"}
For a Mac where you manage tools with Homebrew: `kraft admin update` then runs
`brew upgrade kraft`.

```bash
brew tap itsOmidKarami/kraft
brew install kraft
```
:::

:::tabs-item{label="Install script"}
For a machine with neither uv nor Homebrew. The script fetches the newest
release and installs `uv` first if you do not have it:

```bash
curl -fsSL https://raw.githubusercontent.com/itsOmidKarami/kraft/main/install.sh | sh
```

[`install.sh`](https://github.com/itsOmidKarami/kraft/blob/main/install.sh) is
short and worth reading before you pipe it to a shell. It says where it put
`kraft`, and when that directory is not on your `PATH` yet (usually after it
installed uv), it says to run `uv tool update-shell` and open a new terminal.
:::

:::tabs-item{label="From source"}
To run an unreleased commit or to work on Kraft itself. Besides uv and `git`,
you need [just](https://just.systems/) and Node 22 to build the board:

```bash
git clone https://github.com/itsOmidKarami/kraft.git
cd kraft
just setup     # Python and frontend dependencies
just install   # builds the board and installs the `kraft` command
```

To develop Kraft rather than run it, see [Contributing](/project/contributing).
:::
::

## Start the server

```bash
kraft
```

It prints its address and keeps running in this terminal:

```text
kraft: http://127.0.0.1:8765
```

When a newer release exists, a line `kraft: <installed> installed, <new> available - kraft admin update`
comes first; it is only a notice.
Leave the server running and open the address in a browser. With no repo connected, the
board shows **Nothing on the board yet**. Open a second terminal for everything
that follows.

If the command is not found, see
[`kraft`: command not found](/troubleshooting/starting-and-reaching-kraft#kraft-command-not-found).
If it prints `kraft: refusing to start - something is already answering on ...`,
see
[Kraft won't start: port already in use](/troubleshooting/starting-and-reaching-kraft#kraft-wont-start-port-already-in-use).

## Connect your agent

Kraft talks to agents through its MCP server, the command `kraft admin mcp`.
Register it with Claude Code first, then with any other agent you want to drive
Kraft from.

### Claude Code

The shipped chains run every worker on Claude Code, and Kraft refuses to launch
a Claude worker unless Claude Code knows the `kraft` MCP server: the worker asks
the permission gate through it. So register it even when you drive Kraft from
another agent.

Install the plugin:

```bash
claude plugin marketplace add itsOmidKarami/kraft
claude plugin install kraft@kraft
```

Then, with the server running, open a session in your repo, run
`/kraft:onboard`, and follow what it asks. It connects the repo and checks its
setup and test commands. The plugin registers the MCP server itself: do not
also run `kraft admin init`.

Without the plugin, register the server and the `/kraft:*` skills from a
terminal, then connect the repo:

```bash
kraft admin init
cd ~/code/my-project
kraft repo connect
```

### Other agents (optional)

To drive Kraft from another agent, register the MCP server with it. Each tab
ends by connecting the repo.
[Use Kraft from your agent](/guides/day-to-day/agent-integration) covers each
agent in detail, including what a worker needs when a chain runs on it.

::tabs{sync="agent"}
:::tabs-item{label="Codex"}
Install the plugin:

```bash
codex plugin marketplace add itsOmidKarami/kraft
codex plugin add kraft@kraft
```

It registers the MCP server and adds the Kraft skills. Without the plugin,
register the server alone with `codex mcp add kraft -- kraft admin mcp`.

Then connect the repo:

```bash
cd ~/code/my-project
kraft repo connect
```
:::

:::tabs-item{label="Cursor"}
Add the Kraft marketplace:

```bash
agent plugin marketplace add https://github.com/itsOmidKarami/kraft
```

Then start `agent`, run `/plugins`, open the Marketplace tab, pick `kraft`, and
install it. It registers the MCP server and adds the Kraft skills.

Without the plugin, add the server to `~/.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "kraft": { "command": "kraft", "args": ["admin", "mcp"] }
  }
}
```

and approve it with `agent mcp enable kraft`.

Then connect the repo:

```bash
cd ~/code/my-project
kraft repo connect
```
:::

:::tabs-item{label="OpenCode"}
```bash
opencode mcp add --global kraft -- kraft admin mcp
cd ~/code/my-project
kraft repo connect
```
:::

:::tabs-item{label="Amp"}
```bash
amp mcp add kraft -- kraft admin mcp
amp skill add itsOmidKarami/kraft/plugins/kraft/skills --global   # optional: the Kraft skills
cd ~/code/my-project
kraft repo connect
```
:::

:::tabs-item{label="Antigravity"}
Antigravity imports the plugin from a local copy of the repo. The import copies
it, so the clone can go afterwards:

```bash
clone=$(mktemp -d)
git clone --depth 1 https://github.com/itsOmidKarami/kraft.git "$clone"
agy plugin import "$clone/plugins/kraft"
rm -rf "$clone"
```

It registers the MCP server and adds the Kraft skills. Without the plugin,
register the server alone with `agy mcp add kraft kraft admin mcp`.

Then connect the repo:

```bash
cd ~/code/my-project
kraft repo connect
```
:::

:::tabs-item{label="Gemini CLI"}
Gemini CLI needs an API key or Gemini Code Assist. With an individual Google
account, use Antigravity instead. See [Harnesses](/reference/harnesses).

```bash
gemini mcp add --scope user kraft kraft admin mcp
cd ~/code/my-project
kraft repo connect
```
:::
::

The Kraft plugin, with its skills, installs on Claude Code, Codex, Cursor and
Antigravity. OpenCode and Gemini CLI get the MCP server alone, and Amp adds the
skills with `amp skill add`. The `kraft` command must be on your `PATH` for
every agent.

## Check it worked

In the second terminal, after you connect a repo (most `doctor` rows are about
connected repos):

```bash
kraft --version      # prints the installed version
kraft admin health   # exits 1 if the server is down or degraded
kraft admin doctor   # runs every check; exits 1 if any fails
```

`--version` prints `kraft` and the version:

```text
kraft 2.0.0
```

`health` prints one `label  value` line per field, and begins:

```text
status         ok
version        2.0.0
```

`doctor` prints one line per check, led by `ok`, `warn`, `FAIL` or `skip` (a
check that needs the server, when none is up), and a count at the end. A passing install reads like this, with more rows between (the
paths are your own):

```text
ok    server         http://127.0.0.1:8765
ok    agent: claude  /usr/local/bin/claude
ok    kraft on PATH  /home/you/.local/bin/kraft
ok    forge my-repo  github · gh

all <N> checks passed
```

You know it worked when:

- `http://127.0.0.1:8765` shows the board.
- `kraft admin health` shows a `status` of `ok` and exits 0.
- `kraft admin doctor` ends in `all <N> checks passed`, followed by
  `, <W> warned` when a row warns. While any row reads `FAIL` it exits 1 and
  ends in `<F> of <N> checks failed`.

A `FAIL` row names its cause. [Doctor failures](/troubleshooting/doctor-failures)
has every row and its fix. Four are common right after an install:

- `forge <repo>` fails when the repo has no GitHub or GitLab `origin` remote,
  because no forge is recorded for it. `quick-task` does not need one; the
  `default` chain does. If your repo has no remote and you only run
  `quick-task`, expect this one `FAIL` and exit 1; every other row should pass.
- `setup <repo>` fails when the repo has no `setup_command`.
- `mcp server` fails when nothing registers Kraft's MCP server with Claude Code
  and some chain launches an unsandboxed Claude task. Install the plugin, or
  run `kraft admin init`. It does not check other agents.
- `kraft on PATH` fails when the `kraft` command is not on your `PATH`. After a
  uv install, run `uv tool update-shell`, then start `kraft` again from a new
  terminal.

## Enable vector search

Search works out of the box in full-text mode. To add vector (semantic) search
to a uv or script install, reinstall the version you run, on the Python it runs
on, with the `vector` extra. It downloads a model of about 130 MB on the first
search.

```bash
uv tool install --force --python 3.X "kraft-sdlc[vector]==X.Y.Z"
```

Name both the Python and the version. Without the version, uv installs the
newest final release, which on a release candidate is an older Kraft that
refuses to start on its database. Without `--python`, uv rebuilds Kraft on its
own default Python. `kraft --version` prints `kraft X.Y.Z`.

`kraft admin doctor`'s `embeddings` row prints this command filled in for your
install. On a pipx or pip install it prints that installer's command instead;
the Homebrew formula does not ship the `vector` extra.

If the model cannot be downloaded (offline, or a proxy refuses Hugging Face),
search keeps working as full-text search and says so in a `note`. A search
that asks for `mode=vector` answers 422 with the reason. `kraft admin doctor`
fails its `embeddings` row, and `/api/health` reports the model's `state` as
`failing`.

On an Intel Mac, or on Apple Silicon before macOS 14, the `vector` extra
installs only on Python 3.12 or 3.13: on 3.14 the package that runs the model,
`onnxruntime`, has no build for those Macs, and the install fails to resolve.
Install Kraft with `--python 3.13` there. A plain `uv tool install` or
`install.sh` can pick 3.14 when the machine has no Python 3.12 or newer.

## Uninstall

```bash
uv tool uninstall kraft-sdlc   # uv or script install
brew uninstall kraft           # Homebrew install
```

Neither removes `$KRAFT_HOME`. Delete that directory yourself to discard all
Kraft state.

## Where state lives

Kraft keeps state in `$KRAFT_HOME` (default `~/.kraft`), in two directories:

- `config/` holds the YAML you edit. It is a plain directory of files, so you
  can diff it, revert it, or `git init` it. `access.yaml` and `notify.yaml`
  appear once you save their Settings screens. See
  [Configuration](/reference/configuration).
- `run/` holds the databases, logs, results, worktrees and attachment copies.
  See [Secrets and state](/project/data-and-privacy#secrets-and-state).

A second, fully separate instance needs its own `KRAFT_HOME` and its own port:
see [Run two instances](/guides/run/run-as-a-service#run-two-instances). Kraft
is Apache-2.0 licensed: see [Licences](/project/status-and-support#licences).
