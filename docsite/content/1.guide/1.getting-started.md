This walks through installing Kraft, connecting a repo, running a work item
end to end, and approving the gate that stands in its way. Fifteen minutes, most
of it spent waiting on an agent.

**Before you start**, you need:

- `git`, and a repo to work on.
- `uv` or Homebrew (see [Install](/reference/install)).
- At least one supported coding-agent CLI, installed and logged in. See
  [Harnesses](/reference/harnesses) for the list.

::note{title="Doing this from a coding agent instead"}
Once Kraft is installed (step 1), most of the rest has a `/kraft:*` slash
command twin: `/kraft:onboard` instead of `repo connect`, `/kraft:board` instead
of `view list`, `/kraft:gates` instead of `item approve`. See
[Agent integration](/reference/agent-integration) if that is closer to how you
already work.
::

## 1. Install and start the server

```bash
uv tool install kraft-sdlc
kraft
```

On macOS, `brew tap itsOmidKarami/kraft && brew install kraft` works the same
way. See [Install](/reference/install) for that path and the install script.

Leave that running. It is the server, in the foreground, on
`http://127.0.0.1:8765`. Open that URL; you should see an empty board.

**Open a second terminal** for everything that follows.

Check the install:

```bash
kraft admin doctor
```

It runs every health check and exits 1 if any fails.

## 2. Connect a repo

From inside the repo you want Kraft to work on:

```bash
cd ~/code/my-project
kraft repo connect
```

This adds the repo to `repos.yaml` and probes it for a `setup_command`, a
`test_command`, and `test_scopes`, using the repo's own markers (a `justfile`, a
`package.json`, a `pyproject.toml`). Open the new entry and check all three
before you trust them. See
[Configuration](/reference/configuration#reposyaml-connected-repos).

Confirm the repo is connected:

```bash
kraft repo list    # a * marks the repo you are in
```

## 3. File your first work item

The `quick-task` chain has no gates, which makes it good for confirming the
pipes are connected:

```bash
kraft item create "fix the flaky import test" --chain quick-task \
  --description "It's the datetime import, not the fixture."
```

Copy the item's ID from the output. You can list IDs again any time with
`kraft view list`.

The item lands **paused**, as every work item does, whoever created it. Nothing
has spent a token yet. See [Concepts](/guide/concepts#work-item).

## 4. Start it, and watch

Every command below takes the item's ID. Replace `ID` with the one you copied.
You can leave the ID off only when you run the command inside that item's
worktree.

```bash
kraft item resume ID   # the CLI twin of clicking Start on the board
kraft view watch       # a live board, redrawn on every event
```

![The Kraft board: work items grouped by Needs you, Running, Not started, and Done](/assets/board.png)

`quick-task` runs `implementation`, then `verify`, with no gate. If the agent's
fix is good, the item reaches **Done** on its own. `verify` runs the repo's own
`test_scopes` or `test_command` from `repos.yaml`. If it fails, the item stops
for you with the failing scope named.

You know it worked when the board shows the item under **Done**.

## 5. Try the real chain, and its gates

`default` is the chain most work runs on, and the default for `--chain`, so you
can leave the flag off:

```bash
kraft item create "add a --dry-run flag to the sync command"
kraft item resume ID
```

Before any code is written it stops at three gates, one after another:
`spec_approval`, then `plan_approval`, then `chain_revision_approval`. The last
usually passes on its own. Each gate shows up under *Needs you* on the board:

![Approving a spec_approval gate from the board's side panel](/assets/gate.png)

```bash
kraft view docs ID         # read the spec and plan Kraft wrote
kraft item approve ID      # or Approve on the board
```

To send it back instead, run `kraft item reject ID --note "..."`. The node that
wrote the document runs again with your note.

You know it worked when, after your last approval, the item moves out of
*Needs you* and into *Running*, and the board shows implementation started.

## 6. Review before it merges

Later gates (`local_review`, `final_review`) come with a diff to read first:

```bash
kraft view diff ID --stat   # how big it is
kraft view diff ID          # the full diff
```

What each gate does, and how caps and waits bound the chain, is in
[Concepts](/guide/concepts#gate).

## Troubleshooting

**The first item stops at `verify` with a config error.** The repo declares
neither `test_scopes` nor `test_command` in `repos.yaml`, and Kraft will not
guess a test command. Set one, then run `kraft item retry ID`.

**The first item stops before it starts.** A repo with no `setup_command` stops
its first work item rather than guessing what to run in a fresh worktree. Set it
in `repos.yaml`, then run `kraft item retry ID`.
