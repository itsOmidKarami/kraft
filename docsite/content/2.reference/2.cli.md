description: Every kraft verb, grouped by what it does.

`kraft` with no arguments starts the server. Every other command talks to a
running server. Verbs live in four groups: `item` acts, `view` reads, `repo`
manages repositories and their worktrees, and `admin` runs this machine's
server. Typing an old flat verb (`kraft list`) prints where it moved.

`kraft <group> <verb> --help` is the authoritative list of flags. This page
covers the ones you are most likely to need.

Wherever a command takes a work item ID, you can omit it when you run the
command from inside that item's worktree.

## Output format

Every read and action verb accepts `--json`, which prints the raw API payload,
the same value `kraft admin mcp` hands an agent. These verbs do not:

| Verb | Use instead |
|---|---|
| `view watch` | `kraft view events --json` (`watch` redraws a board rather than returning a value) |
| `repo path` | `kraft view show --json` (`path` prints one plain line meant for `cd`) |
| `admin start`, `stop`, `restart`, `update` | None; these print status lines. |
| `admin install-service`, `uninstall-service` | None. |
| `admin mcp`, `admin permission-hook` | None; these speak a protocol on stdio. |

`kraft view logs --json` prints NDJSON, one object per line, because a stream
has no end on which to close an array.

## Everyday verbs

```bash
kraft view list
kraft view list --all --status=paused
kraft view list --include-abandoned
kraft view show
kraft view search "retry policy"
kraft view search "retry policy" --limit 50
kraft item approve
kraft item reject --note "the plan skips migrations"
kraft item pause
kraft item resume --steer "try the other adapter"
kraft item retry
```

| Command | Effect |
|---|---|
| `view list` | The board, scoped to the repo you are in. `--all` spans every repo. `--include-abandoned` adds abandoned items. |
| `view show` | The work item whose worktree you are in. |
| `view search` | Search the document index. `--limit` caps the result count (default 20). |
| `item approve` | Approves the pending gate. `--gate` names a gate when more than one could apply. `--digest` pins the approval to a chain revision, as `kraft view artifact` printed it. |
| `item reject` | Rejects the pending gate. `--note` records why. `--node N` re-enters the chain at node N instead of the gate's default. |
| `item pause`, `item resume` | Pause stops the whole work item. `resume --steer` gives the paused agent a message. |
| `item retry` | Re-runs the node a stopped item stopped on. It is the only way back onto a stopped item. |

`kraft view show` reports what the item has spent: uncached input, cache
writes, cache reads and output tokens, then cost. A session recorded before
cache tokens were split out has a single input figure, counted under `in`, and
the line says `(cache not split on older sessions)`. A `token_budget` counts
all four kinds.

### Filing a work item

```bash
kraft item create "fix the flaky test" --description "..."
kraft item create "fix it now" --autostart
kraft item create "ship the thing" --spec .engineering/specs/x.md
kraft item create "backport the fix" --base-branch release/1.2
kraft item create "fix the parser" --repo ~/code/app --chain quick-task --auto-gate
kraft item create "small fix" --skip-nodes spec,plan --budget 5
kraft item create "tuned fix" --node-override implementation.attempts=2
```

| Flag | Effect |
|---|---|
| (none) | Files the item paused. A person starts it. |
| `--autostart` | Starts the item at once. A Kraft worker session is refused. |
| `--spec`, `--plan` | Attaches a document and skips the node that would write it. |
| `--base-branch` | Starts from, and merges into, that branch. |
| `--repo`, `--chain` | Targets another connected repo or chain. |
| `--implements ID` | Closes the named issue in your optional issue tracker when the item completes. |
| `--auto-gate` | Has an agent review each gate and auto-escalate before a human is asked. |
| `--skip-nodes` | Skips the named nodes. |
| `--budget USD` | Sets the item's dollar cap. `--budget none` lifts it. |
| `--node-override N.FIELD=VALUE` | Overrides one field on node N. |
| `--policy KEY=VALUE` | Gives the item its own [policy override](#a-work-items-own-policy). Repeatable. |

`--repo` must name a repo you have already connected with `kraft repo connect`.
Kraft refuses any other path and names that command.

### Addressing work by path

Retry, skip and resume address chain work by its path: `node`, `node.step` or
`node.step.task`. A `tasks:` node's one step is `main`, so the path to its
`implement` task is `implementation.main.implement`. `kraft view show --json`
lists every path.

```bash
kraft item retry --path verification.review
kraft item retry --path verification.review.code_review
kraft item retry --path spec
kraft item retry --restart
kraft item resume --steer "keep the old API" --steer-task verification.review.code_review="check the auth module first"
kraft item skip --path verification.review.code_review
```

| Command | Effect |
|---|---|
| `retry --path node.step` | Re-runs that step and everything after it. |
| `retry --path node.step.task` | Re-runs that task. Its finished siblings stand. |
| `retry --path node` | Re-runs a node that already completed, and everything after it. |
| `retry --restart` | Re-runs the whole chain from its first node. |
| `resume --steer` | Sends a message to every paused agent task. |
| `resume --steer-task PATH=TEXT` | Sends a message to one paused agent task. |
| `skip --path` | Skips only that task. Its siblings keep running. |

A retry keeps everything the earlier run did and runs on a new run fork. It
reopens every gate it has to rerun. A gate before the retried work keeps its
decision.

A paused agent task resumes its own session when its harness supports it, and
is told the steer. Otherwise it restarts with its brief and the steer. You see
a refusal when you:

- steer an item that is still running (pause it first);
- steer an item whose pause stopped no agent task, such as a test run or a CI
  wait;
- name a `--steer-task` that is not a paused agent task.

## Following a running item

```bash
kraft view logs -f
kraft view logs --session <id> -n 0
kraft view events
kraft view events -f
kraft view events --type permission_decision
kraft view watch
```

| Command | Effect |
|---|---|
| `view logs` | The current session's log. `-f` follows until the session stops. `-n N` sets the backlog lines shown first (default 50). `--session` picks a session. |
| `view events` | Node transitions, gate decisions and escalations. `--after N` shows only later events. `--type T` filters by type. `-f`/`--follow` streams until the item completes or is abandoned. |
| `view watch` | A live board, redrawn on every event. Needs a terminal. |

`-n 0 -f` prints only lines written after it starts.

## Reviewing before you approve

```bash
kraft view diff --stat
kraft view diff --name-only
kraft view diff
kraft view diff --no-pager
kraft view docs
kraft view doc <id> --open
kraft view artifact <id>
```

| Command | Effect |
|---|---|
| `view diff` | The coloured diff, through `$PAGER`. `--no-pager` prints straight to the terminal. |
| `view diff --stat` | Size of the change. |
| `view diff --name-only` | Changed and untracked paths. |
| `view docs` | Specs, plans and summaries linked to the item. |
| `view doc ID` | One document. `--open` opens it in an editor on the server's machine. |
| `view artifact` | The document the pending gate is about. |

A truncated diff always says so on its last line. Files the agent wrote
without `git add` are listed separately, because a unified diff does not show
them.

## Less common item verbs

```bash
kraft item skip --note "already fixed upstream"
kraft item escalate --message "the fix loop keeps missing the same edge case"
kraft item escalate --message "..." --new-thread
kraft item set-chain --template quick-task
kraft item set-attachments --spec specs/x.md
kraft item set-attachments --drop spec
kraft item set-overrides --model opus --effort high
kraft item set-overrides --clear
kraft item mr-label --id <id> release::patch
kraft item abandon --yes
kraft item complete --reason "shipped by hand"
kraft item cancel --reason "superseded by #412"
```

| Command | Effect |
|---|---|
| `skip` | Advances past the current node or gate without running it. |
| `progress N` | Called by a worker session to report it started plan task N. You do not run it by hand. |
| `escalate` | The manual counterpart of the board's auto-escalation. Asks an agent to help resolve a `needs_human` stop. `--new-thread` starts a fresh agent session instead of continuing the latest thread. |
| `set-chain` | Switches a not-yet-started item's chain. |
| `set-attachments` | Revises a not-yet-started item's spec or plan. `--drop KIND` removes it and restores its gate. |
| `set-overrides` | Sets the item-wide model and effort. `--clear` returns to the template's own binding. |
| `mr-label` | Relabels the merge request. This re-creates its pipeline. |
| `abandon` | Drops the item and reclaims its worktree. It destroys uncommitted work, so `--yes` is required. |
| `complete` | Ends the item as completed. Requires `--reason`. Add `--close-beads` to close its linked issues. |
| `cancel` | Ends the item as cancelled. Requires `--reason`. The worktree stays. |

`complete` and `cancel` stop whatever is running and record the reason on the
item's timeline.

### One node's agent tasks

`kraft item set-node-override --node N` changes one node of one item until
that node starts. After that, Kraft refuses the change.

```bash
kraft item set-node-override --node verify --auto-escalate-stuck
kraft item set-node-override --node implementation --model opus --effort high
kraft item set-node-override --node implementation --extra-prompt "Keep the migration backwards compatible."
```

Besides the auto-escalate settings, `attempts` and `wall_clock_s`, it accepts:

- `--model`, `--effort`: what every agent task in the node launches with. From
  highest precedence to lowest: this node override, the item-wide
  `set-overrides`, the task's own `model:` and `effort:` in the library, the
  repo's `models:` (model only), then the harness profile's `defaults:`. A
  value the node's harness does not accept is refused when you set it, not at
  launch. A gate's `auto_review` uses the item-wide values only.
- `--extra-prompt TEXT`: appended to the instruction of every agent task the
  node runs, after the task's own prompt and brief. It never replaces them. It
  does not reach a gate's `auto_review` or the interactive escalation turn.
  At intake, `N.extra_prompt=...` is taken as written, not read as YAML.

The override is stored on the item. It does not edit the chain.

### A work item's own policy

`kraft item create --policy KEY=VALUE` (repeatable) and `kraft item
set-policy` give one work item its own policy override, without touching its
chain or any other item. `FIELD=VALUE` applies item-wide. `PATH.FIELD=VALUE`
applies to one node, step or task and everything under it. Values are read as
YAML, so `deny_tools=[WebFetch]` is a list.

```bash
kraft item create "quick fix" --policy time_cap_minutes=45 --policy merge_request_feedback.ci.await_ci.total_time_cap_minutes=60 --policy verification.max_attempts=4
kraft item set-policy --policy merge_request_feedback.ci.await_ci.total_time_cap_minutes=60
kraft item set-policy <id> --policy max_attempts=2
kraft item set-policy --clear
```

`set-policy` replaces the whole override. The fields are those described in
[Configuration](/reference/configuration#policyyaml-caps-budget-archiving):

| Fields | Behaviour |
|---|---|
| `timeout_minutes`, `max_attempts`, `allowed_harnesses` | Move within the administrator `maxima` and win over what the chain set. `max_attempts` applies to execution nodes only. |
| `allowed_tools`, `deny_tools`, `sandbox` | Only tighten. A list intersects with what each task already allows. |
| `time_cap_minutes`, `total_time_cap_minutes`, `token_budget`, `budget_usd` | Item-wide caps. Raise one above the chain's, up to `maxima.work_item`, to unstick a capped item before a retry. |

On a path, you can pass that level's default up to its level's maximum. Kraft
refuses a value above what the chain or the item already gives that scope,
naming both. A wait task's total cap is its timeout.

`wait_timeout_minutes` is retired. Kraft refuses it and names
`total_time_cap_minutes`. Kraft also refuses a value past its maximum, a path
the chain does not have, and a key that is not a policy field, naming the
field.

`set-policy` works on any item that has not ended. On a running or waiting
item it takes effect from the next node the item enters and from the next
check of a wait it is parked on. The new timeout counts from when the wait
started.

## Repos and worktrees

```bash
kraft repo list
kraft repo connect
kraft repo disconnect
cd "$(kraft repo path <id>)"
kraft repo path --shell
kraft repo open <id>
kraft repo open <id> --editor cursor
```

| Command | Effect |
|---|---|
| `repo list` | The connected repos. `*` marks the one you are in. |
| `repo connect [PATH]` | Connects a repo (safe to repeat). It proposes a setup command and a test command from the repo's files. Check both before you trust them. |
| `repo disconnect [PATH]` | Forgets the repo. Work items are untouched. |
| `repo path [ID]` | Prints the item's worktree path. `repo cd` is an alias. `--shell` prints a shell function that does the `cd` for you. |
| `repo open [ID]` | Opens the worktree in an editor. `--editor` picks `code`, `cursor`, `zed` or `obsidian`. The default is the system's. |

For each repo's settings (`setup_command`, `env`, `test_scopes` and the rest),
see [Configuration](/reference/configuration#reposyaml-connected-repos). You
edit them in the Settings screens or in `repos.yaml`, not with the CLI.

## Service and admin

```bash
kraft admin start --port 9000
kraft admin start --detach
kraft admin stop
kraft admin restart
kraft admin health
kraft admin doctor
kraft admin reindex --repo <path>
kraft admin reload
kraft admin update --restart -y
kraft admin install-service
kraft admin uninstall-service
kraft admin templates lint
kraft admin templates lint --dir PATH
kraft admin templates show ID
kraft admin templates show ID --resolved
kraft admin templates library
kraft admin templates library ID
kraft admin harnesses
kraft admin harnesses ID
kraft admin init --repo
kraft admin mcp
kraft admin permission-hook cursor --fail-closed
```

| Command | Effect |
|---|---|
| `start` | Runs the server in the foreground; the same as bare `kraft`. `--host` and `--port` override `access.yaml`. `--detach`/`-d` forks it into its own session and returns once it is up. |
| `stop` | Sends SIGTERM to the process in `run/kraft.pid`. |
| `restart` | Stops, then starts again the same way it was running: through the service manager if one is installed, back into the background if it was detached. A server running attached to a terminal is stopped, with a note that only that terminal can bring it back. |
| `health` | Exits 1 when the server is degraded, with the reasons on stdout. |
| `doctor` | Runs every check in one pass. Exits 1 if any fails. |
| `reindex` | Rescans documents into the search index. `--repo` limits it to one repo. |
| `reload` | Rereads the template library and `policy.yaml` from disk, with no restart. |
| `update` | Installs the newest release, or runs `brew upgrade` if you installed with Homebrew. `--force` installs even when current. `--restart` also restarts a running server. `-y` accepts the [template migration](#migrating-a-pre-v1-template-configuration) without asking. |
| `install-service`, `uninstall-service` | Register or remove Kraft as an OS service (a launchd agent on macOS, a systemd user unit on Linux) that restarts if it exits. Stop a running server first. |
| `templates lint` | Checks every chain in the library and exits 1 on any error. `--dir PATH` checks that directory in-process, with no server and no `$KRAFT_HOME`. |
| `templates show ID` | One chain as written. `--resolved` expands its library components. |
| `templates library [ID]` | Every library component, its kind and the chains using it. With an ID, one component's definition, users and lint issues (`tasks.implementer`, or a unique bare name). |
| `harnesses [ID]` | Every `harnesses.yaml` profile, its provider and the tasks selecting it. With an ID, one profile in detail. |
| `init [--repo]` | Registers the MCP server and skills with an agent. `--repo` installs into this repo, not your user config. See [Agent integration](/reference/agent-integration). |
| `mcp` | Serves the MCP tools over stdio. |
| `permission-hook HARNESS` | What a Cursor or Codex worker's pre-tool hook runs. You do not run it by hand. `--fail-closed` denies rather than giving no opinion when Kraft cannot answer. See [Permission gate](/reference/permissions). |

Kraft refuses to start on a non-loopback address without a password. It also
refuses a second start against the same run directory while the first is
alive. The foreground server stops on Ctrl-C. Use `kraft admin stop` for one
you started elsewhere.

Agent registrations run `kraft admin mcp` by name, so they get whichever
`kraft` is first on your `PATH`. An older second install ahead of this one (a
Homebrew formula beside a `uv tool` install, say) keeps every MCP session on
its code after an update. `kraft admin update` warns when that happens, and
`kraft admin doctor` fails its `kraft on PATH` row.

The semantic-search embedder is an opt-in extra. An installed embedder whose
model will not load is reported as available with the failure reason beside
it, and `kraft admin doctor` fails its `embeddings` row until a later encode
succeeds.

### Migrating a pre-V1 template configuration

A Kraft home that still holds the pre-V1 template configuration (a
`registry.yaml` and no `library.yaml`) is not converted or overwritten. The
server starts degraded and refuses new work until you run
`kraft admin update`. That command says what will change, asks, and then moves
the whole `templates/` directory to a `templates.pre-v1-<time>` backup beside
it and installs the V1 configuration.

- `-y` accepts without the question. With no terminal and no `-y`, it changes
  nothing.
- `access.yaml`, `notify.yaml`, `theme.yaml`, `repos.yaml`, `intake.yaml`,
  `steering/` and `harnesses/` carry across. The next start folds
  `steering/*.md` into `library.yaml` as
  [steering profiles](/reference/configuration#repository-steering).
- `policy.yaml` starts from the V1 default and keeps your value for every key
  V1 still has. Kraft prints each key it drops, with its old value.
- Your old chains and registry stay only in the backup. There is no migration
  helper.

An update interrupted mid-swap is finished by the next start or the next
`kraft admin update`.

## Shell completion

`kraft` completes verbs with [`argcomplete`](https://github.com/kislyuk/argcomplete).
For zsh, add this line to `~/.zshrc`:

```zsh
eval "$(register-python-argcomplete kraft)"
```

After you open a new shell, `kraft it<TAB>` completes to `kraft item`, and
`kraft item <TAB>` lists every `item` verb. Completion follows the verb tree
down. It works in any shell `argcomplete` supports.
