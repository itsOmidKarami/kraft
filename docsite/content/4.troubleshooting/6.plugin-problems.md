---

Start here when a `kraft admin plugin` verb refuses, or `validate` reports a problem in a [Kraft plugin](/concepts/vocabulary#kraft-plugin) you are writing. A refused verb leaves `plugins.yaml`, the lock and the store as they were, so run it again once you have fixed the cause.

A `plugins` or `plugin updates` row of `kraft admin doctor` is on [Doctor failures](/troubleshooting/doctor-failures#doctor-rows). A work item that stopped with `plugin ... could not be read` is under [Stop reasons in detail](/troubleshooting/stop-reasons-in-detail#plugin-could-not-be-read).

To confirm a fix, run the verb again, then `kraft admin plugin list`. `kraft admin doctor` does not report a refused install or update: its `plugins` row reports what is installed, and `plugin updates` only the last auto-update.

## Adding, installing, updating and removing

The first column is the text the command prints after its prefix. `...` stands for text that varies, and a path is shortened.

- `install` and `update` print `PLUGIN@COLLECTION: refused: ...` when the plugin or your instance is the problem, and `PLUGIN@COLLECTION: failed: ...` when git, the lock or the store is.
- Every other refusal starts with `error:`.

### Adding a collection

| The message says | What happened | Fix |
|---|---|---|
| `` <address>: fatal: '/nonexistent/repo.git' does not appear to be a git repository `` and `fatal: Could not read from remote repository.` | git could not reach the address. | Check the address, and that this machine can reach it. |
| `<address>: ...` and one of `Permission denied (publickey)`, `Authentication failed`, `could not read Username` or `terminal prompts disabled` | `collection add`, `install` and `update` run git in your shell, and Kraft runs it without prompting, so a password or passphrase prompt fails. GitHub answers a missing or private `owner/repo` over https this way too. | Load your key into your shell's SSH agent, or set a git credential helper, then run the verb again. For GitHub, check the name and your access. |
| `` <address>: fatal: transport 'file' not allowed `` | The address is a path that is not a directory, so Kraft tried it as a git address, and a path is not one. | Check the path. For a git repository on this machine, give `file:///abs/path`. |
| `` <address>: fatal: couldn't find remote ref nonexistent `` | The ref names no branch, tag or commit. | After a failed `collection add` nothing was added: run it again with a ref that exists. For a collection added earlier, fix its `ref:` in `plugins.yaml`, then run `kraft admin plugin update`. |
| `` <commit>: no regular file .kraft/collection.json `` | A git collection has no `.kraft/collection.json` at the ref Kraft read, so it is not a collection. | Check the address and `--ref`. The author lays one out in [Publish a collection](/guides/customize/share-chains-with-plugins#publish-a-collection). |
| `` [Errno 2] No such file or directory: '<dir>/.kraft/collection.json' `` | A directory collection has no `.kraft/collection.json`. | Check the path you gave, or add the file as in [Publish a collection](/guides/customize/share-chains-with-plugins#publish-a-collection). |
| `` collection acme is already added from <source>; remove it first to add it from another source `` | `plugins.yaml` already holds a collection of that name, from a different address or directory. | Add it from the source it has. To change source, uninstall its plugins and run `kraft admin plugin collection remove NAME` first. |

Auto-update runs in the server, which as a service may lack your SSH agent or credential helper: see [`plugin ... could not be read`](/troubleshooting/stop-reasons-in-detail#plugin-could-not-be-read).

### Installing and updating

| The message says | What happened | Fix |
|---|---|---|
| `` plugins.yaml: release@acme: no collection 'acme' under collections `` | The plugin's collection is not added on this instance. | Run `kraft admin plugin collection add SOURCE`, then install again. |
| `` collection acme has no plugin nope `` | The collection does not list a plugin of that name. | Compare the name with `kraft admin plugin collection list`, and check the collection's `ref`. |
| `declined release@acme: no terminal to ask at; pass -y to accept` | `install` and `update` show a review and ask first. With no terminal, as in a script, they decline. | Read the review in a terminal, then pass `-y` in the script. |
| `` release@acme is already installed; `update` it, or pass --re-install to take the newest commit `` | `install` refuses a plugin the lock already holds. | Run `kraft admin plugin update release@acme`, or `install release@acme --re-install` to take the commit the ref names now. |
| `` requires agent profile 'ghost', which harnesses.yaml does not define ``, or the same with `requires harness` | The plugin needs an agent profile or a harness this instance does not define. | Define it in [`harnesses.yaml`](/reference/harnesses/agent-profiles#define-an-agent-profile), or ask the author to drop it from `requires`. |
| `` 1.0.0 needs Kraft 3.x; this is Kraft 2.4.1 `` | The plugin's `requires.kraft` names a Kraft this one is not. The message reads `needs Kraft 3.x` for a major, or `needs Kraft 2.9 or later` for a minimum. | Run a Kraft the plugin supports, or ask the author for a version that supports yours. |
| `` plugins.yaml: release@other: namespace 'release' is taken by release@acme; install one under another name with --as `` | Two plugins would share a [namespace](/reference/configuration/plugins#names). | Install it again under another [alias](/reference/configuration/plugins#names): `--as ALIAS`. |
| `` its namespace 'release' is now a repository id `` | An `id` in `repos.yaml` is the plugin's namespace. `validate` prints the same line after the path. | Install it with `--as ALIAS`, choosing an alias that no `id` in `repos.yaml` uses. |
| `` chain mine would stop resolving: ...: extends no task named 'release:implementer' `` | The new version drops something one of your own files uses. `update --check` exits 2 for it. | Edit the chain the message names so it stops extending the removed task, or ask the author to keep it. The locked version keeps running. |
| `` its chain release:ship does not resolve: ...: extends no task named 'release:implementor' `` | The plugin's own chain names something the plugin does not declare. | Ask the author to correct the chain; `validate` finds it before publishing. |
| `` is not in plugins.yaml; install it first `` | `update` named a plugin this instance has not installed. | Run `kraft admin plugin install PLUGIN@COLLECTION`. |
| `` release@acme: current: version 1.0.0 unchanged, but its files changed at <commit>; --re-install to take it `` | Not a refusal: `update` exits 0. A new commit at the same version is not an update. | Ask the author to raise `version`, or run `kraft admin plugin install PLUGIN@COLLECTION --re-install`. |
| `plugins changed while you reviewed; run update again` | `plugins.yaml` or `plugins.lock` changed while the review was open. Nothing was written, and an install's new entry is not kept. | Run the same `install` or `update` again. |

### Removing

| The message says | What happened | Fix |
|---|---|---|
| `` cannot uninstall release@acme: its namespace 'release' is still referenced by `` and a list of files | `uninstall` and `disable` refuse while your own files name the plugin's namespace. | Edit each file listed, or copy what you use into your library, then run the verb again. |
| `` collection acme still has plugins installed: release@acme; uninstall them first `` | `collection remove` refuses while a plugin of that collection is installed or locked. | Run `kraft admin plugin uninstall PLUGIN@COLLECTION` for each one listed, then remove the collection. |

### Any verb that writes

| The message says | What happened | Fix |
|---|---|---|
| `another plugin change is running; try again` | Another `kraft admin plugin` command, or an auto-update, held the plugin lock while this one waited 5 seconds. | Wait for it to finish, then run the verb again. |
| `a worker does not change the instance's plugins` | A work item's agent ran a verb that changes plugins. A worker may not. | Run the verb yourself, from a terminal. |

## Writing a plugin

`kraft admin plugin validate PATH` prints each problem as `error: <file>: <message>`, and exits 1. A line that starts with `warning:` does not fail it. `<file>` is an absolute path, shortened below.

### Manifests and layout

| The message says | What happened | Fix |
|---|---|---|
| `` <path>: holds neither .kraft/collection.json nor .kraft/plugin.json `` | `PATH` is not a collection or a plugin directory. | Point `validate` at the directory that holds `.kraft/`. |
| `` .kraft/plugin.json: is not JSON: ... `` | A manifest is not valid JSON. The message gives the line and column. | Fix the syntax. JSON allows no trailing comma and no comment. |
| `` .kraft/plugin.json: 'requires': Field required `` | `plugin.json` has no `requires`. | Add `"requires": { "kraft": "2" }`. |
| `` .kraft/plugin.json: 'version': String should match pattern ... `` | `version` is not `MAJOR.MINOR.PATCH`. | Write `1.0.0`, or `1.0.0-rc.1` for a pre-release. |
| `` .kraft/plugin.json: 'name': 'kraft' is Kraft's own namespace `` | `kraft` is reserved for what Kraft ships. | Give the plugin another name. |
| `` plugins/release: .kraft/plugin.json: name 'release' differs from its collection entry 'other' `` | `plugin.json` and the collection's `plugins` entry name the plugin differently. | Make the two names the same. |
| `` plugins/release: plugin 'release' holds none of library.yaml, chains/, skills/ or profiles.yaml; it would add nothing `` | The directory holds nothing but `plugin.json`, or the entry's `source` points at the wrong one. | Add a file, or correct `source`. |
| `` .kraft/plugin.json: release 1.0.0 needs Kraft 3.x; this is Kraft 2.4.1 `` | `requires.kraft` names a Kraft this one is not. An install or update refuses it too, without the name. | Set `requires.kraft` to the Kraft you run, or upgrade Kraft. A source build skips the check. |
| `` warning: .../chains/Ship.yaml is not part of the plugin layout and is ignored `` | Kraft reads only lowercase names in the fixed layout. | Rename the file, for example `chains/ship.yaml`. |

### What the files may hold

| The message says | What happened | Fix |
|---|---|---|
| `` library.yaml: tasks.implementer: harness 'codex' is not listed in requires.harnesses (['claude']) `` | A task names a harness the manifest does not list. | Add the harness to `requires.harnesses`, or use a listed one. |
| `` plugins/release: requires harness 'ghosty', which harnesses.yaml does not define `` | Checked on a machine with a Kraft home: this instance lacks a harness or agent profile the manifest requires. | Define it in [`harnesses.yaml`](/reference/harnesses/agent-profiles#define-an-agent-profile), or remove it from `requires`. |
| `` library.yaml: tasks.lint: a plugin may not carry a subprocess task; a shell command runs outside the permission gate an agent works under `` | A plugin cannot run commands. | Use an `agent` or `builtin` task. A command belongs in the repo's own configuration. |
| `` library.yaml: tasks.implementer: policy.allowed_tools is not a limit; a plugin may set only budget_usd, deny_tools, ... `` | A plugin's `policy:` takes limits only, never permissions. | Remove the key. The instance's `policy.yaml` sets permissions. |
| `` chains/ship.yaml: ...: extends 'other:implementer' reaches outside the plugin; a plugin is self-contained `` | A reference names another plugin. | Copy what you need into this plugin and extend that. |
| `` plugins/release: its chain release:ship does not resolve: ...: extends no task named 'release:implementor' `` | A reference in the chain names nothing the plugin declares, often a typo. With no Kraft home, `validate` prints the lint message without `its chain ...:`. | Correct the name the message gives. |
| `` ...: selects skill 'release:release-notes', which resolves to no method: ...: plugin 'release' has no skill 'release-notes' at .../skills/release-notes/SKILL.md; a method Kraft ships is written kraft:release-notes `` | The skill's directory or its `SKILL.md` is missing or misnamed. | Create `skills/release-notes/SKILL.md`. The directory name is the skill's name. |

[A plugin's files](/reference/configuration/plugins#a-plugins-files) and [What a plugin may set](/reference/configuration/plugins#what-a-plugin-may-set) have the rules behind these.
