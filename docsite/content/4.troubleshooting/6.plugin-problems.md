Start here when a `kraft admin plugin` verb refuses, or `validate` reports a problem in a [Kraft plugin](/concepts/vocabulary#kraft-plugin) you are writing. A refused verb writes nothing, so it is safe to run again once you have fixed the cause.

A `plugins` or `plugin updates` row of `kraft admin doctor` is on [Doctor failures](/troubleshooting/doctor-failures#doctor-rows). A work item that stopped with `plugin ... could not be read` is under [Stop reasons in detail](/troubleshooting/stop-reasons-in-detail#plugin-could-not-be-read).

## Adding, installing, updating and removing

The first column is the text the command prints, after `error:` when it starts with that. `...` stands for text that varies.

| The message says | What happened | Fix |
|---|---|---|
| `` plugins.yaml: release@acme: no collection 'acme' under collections `` | The plugin's collection is not added on this instance. | Run `kraft admin plugin collection add SOURCE`, then install again. |
| `` nope@acme: refused: collection acme has no plugin nope `` | The collection does not list a plugin of that name. | Compare the name with `kraft admin plugin collection list`, and check the collection's `ref`. |
| `` <address>: fatal: '/nonexistent/repo.git' does not appear to be a git repository `` and `fatal: Could not read from remote repository.` | git could not reach the address, or the login it uses has no access. A server run as a service may lack your shell's SSH agent or credential helper. | Fix the address, or give git on the machine that runs the server access to it. [`plugin ... could not be read`](/troubleshooting/stop-reasons-in-detail#plugin-could-not-be-read) covers the service case. |
| `` <address>: fatal: couldn't find remote ref nonexistent `` | The collection's `--ref` names no branch, tag or commit. | Run `kraft admin plugin collection remove NAME`, then add it again with a ref that exists, or with none. |
| `` <commit>: no regular file .kraft/collection.json `` | The repository has no `.kraft/collection.json` at the ref Kraft read, so it is not a collection. | Check the address and `--ref`. The author lays one out in [Publish a collection](/guides/customize/share-chains-with-plugins#publish-a-collection). |
| `declined release@acme: no terminal to ask at; pass -y to accept` | `install` and `update` show a review and ask first. With no terminal, as in a script, they decline. | Read the review in a terminal, then pass `-y` in the script. |
| `` release@acme: refused: requires agent profile 'ghost', which harnesses.yaml does not define ``, or the same with `requires harness` | The plugin needs an agent profile or a harness this instance does not define. | Define it in `harnesses.yaml`, or ask the author to drop it from `requires`. |
| `` plugins.yaml: release@other: namespace 'release' is taken by release@acme; install one under another name with --as `` | Two plugins would share a namespace. A `repos.yaml` entry with the same `id` clashes too. | Install it again with `--as ALIAS`. |
| `` release@acme: refused: chain mine would stop resolving: ...: extends no task named 'release:implementer' `` | The new version drops something one of your own files uses. `update --check` exits 2 for it. | Change the chain so it stops using what the new version removes, or ask the author to keep it. The locked version keeps running until you update. |
| `version 1.0.0 unchanged, but its files changed at <commit>; --re-install to take it` | A new commit at the same version is not an update. | Ask the author to raise `version`, or run `kraft admin plugin install PLUGIN@COLLECTION --re-install`. |
| `another plugin change is running; try again` | Another `kraft admin plugin` command, or an auto-update, held the plugin lock for 5 seconds. | Wait for it to finish, then run the verb again. |
| `plugins changed while you reviewed; run update again` | `plugins.yaml` or `plugins.lock` changed while the review was open. Nothing was written. | Run `kraft admin plugin update` again. |
| `` cannot uninstall release@acme: its namespace 'release' is still referenced by `` and a list of files | `uninstall` and `disable` refuse while your own files name the plugin's namespace. | Edit each file listed, or copy what you use into your library, then run the verb again. |
| `a worker does not change the instance's plugins` | A work item's agent ran a verb that changes plugins. A worker may not. | Run the verb yourself, from a terminal. |

## Writing a plugin

`kraft admin plugin validate PATH` prints each problem as `error: <file>: <message>`, and exits 1. A line that starts with `warning:` does not fail it.

| The message says | What happened | Fix |
|---|---|---|
| `` <path>: holds neither .kraft/collection.json nor .kraft/plugin.json `` | `PATH` is not a collection or a plugin directory. | Point `validate` at the directory that holds `.kraft/`. |
| `` .kraft/plugin.json: is not JSON: ... `` | A manifest is not valid JSON. The message gives the line and column. | Fix the syntax. JSON allows no trailing comma and no comment. |
| `` .kraft/plugin.json: 'requires': Field required `` | `plugin.json` has no `requires`. | Add `"requires": { "kraft": "2" }`. |
| `` .kraft/plugin.json: 'version': String should match pattern ... `` | `version` is not `MAJOR.MINOR.PATCH`. | Write `1.0.0`, or `1.0.0-rc.1` for a pre-release. |
| `` .kraft/plugin.json: 'name': 'kraft' is Kraft's own namespace `` | `kraft` is reserved for what Kraft ships. | Give the plugin another name. |
| `` plugins/release: .kraft/plugin.json: name 'release' differs from its collection entry 'other' `` | `plugin.json` and the collection's `plugins` entry name the plugin differently. | Make the two names the same. |
| `` plugins/release: plugin 'release' holds none of library.yaml, chains/, skills/ or profiles.yaml; it would add nothing `` | The directory is empty, or the entry's `source` points at the wrong one. | Add a file, or correct `source`. |
| `` library.yaml: tasks.implementer: harness 'codex' is not listed in requires.harnesses (['claude']) `` | A task names a harness the manifest does not list. | Add the harness to `requires.harnesses`, or use a listed one. |
| `` plugins/release: requires harness 'ghosty', which harnesses.yaml does not define `` | Checked on a machine with a Kraft home: this instance lacks a harness or agent profile the manifest requires. | Define it there, or remove it from `requires`. |
| `` library.yaml: tasks.lint: a plugin may not carry a subprocess task; a shell command runs outside the permission gate an agent works under `` | A plugin cannot run commands. | Use an `agent` or `builtin` task. A command belongs in the repo's own configuration. |
| `` library.yaml: tasks.implementer: policy.allowed_tools is not a limit; a plugin may set only budget_usd, deny_tools, ... `` | A plugin's `policy:` takes limits only, never permissions. | Remove the key. The instance's `policy.yaml` sets permissions. |
| `` chains/ship.yaml: ...: extends 'other:implementer' reaches outside the plugin; a plugin is self-contained `` | A reference names another plugin. | Copy what you need into this plugin and extend that. |
| `` plugins/release: its chain release:ship does not resolve: ...: extends no task named 'release:implementor' `` | A reference in the chain names nothing the plugin declares, often a typo. | Correct the name the message gives. |
| `` ...: selects skill 'release:release-notes', which resolves to no method: ...: plugin 'release' has no skill 'release-notes' at .../skills/release-notes/SKILL.md `` | The skill's directory or its `SKILL.md` is missing or misnamed. | Create `skills/release-notes/SKILL.md`. The directory name is the skill's name. |
| `` warning: .../chains/Ship.yaml is not part of the plugin layout and is ignored `` | Kraft reads only lowercase names in the fixed layout. | Rename the file, for example `chains/ship.yaml`. |

[A plugin's files](/reference/configuration/plugins#a-plugins-files) and [What a plugin may set](/reference/configuration/plugins#what-a-plugin-may-set) have the rules behind these.
