title: Remote access
description: Approve or reject a gate from a phone, over Tailscale or a tunnel, using the same password auth as the local board.
---


Reach the Kraft board from a phone or another machine by binding it off
loopback and turning on password auth. You need a password, an
`allowed_hosts` entry for the hostname you will type, and a non-loopback bind.

## Before you start

Kraft binds `127.0.0.1` by default and skips auth for local clients. Any other
bind makes Kraft require the password from every client, local ones included,
and check browser Host headers against `allowed_hosts`.

Pick the narrowest bind that works:

- **Tailscale (recommended).** Bind the machine's Tailscale address. Only
  devices on your tailnet can reach the board, and your LAN cannot.
- **Local network.** Bind `0.0.0.0`, which listens on every network this
  machine is on. Use it only on a network you trust.
- **Cloudflare Quick Tunnel.** Put the board on the public internet. Use it
  only if you cannot use Tailscale.

The port is 8765 unless you set `port` in `access.yaml` or pass `--port`. Use
your port wherever this page says 8765. `access.yaml` lives in
`$KRAFT_HOME/templates/` (by default `~/.kraft/templates/`).

## Set a password

Kraft refuses any bind off loopback until a password is set, both at
`kraft admin start` and on the Settings › Access screen. On `127.0.0.1` the
screen lists the password under **Not used on 127.0.0.1**, and picking
**Local network** asks for one: **Set and switch** saves the password and the
`0.0.0.0` bind in one step (on a phone, a **Set a password** sheet does the
same). Once the bind is off loopback, every browser signs in, including one on
the machine itself. Kraft stores only the password's hash, in `access.yaml`. Once Kraft is
off loopback, the Access screen's **Password** card changes it.

## On your local network

1. Open Settings › Access and choose **Local network** (`0.0.0.0`). The
   screen asks for what is missing: a password if none is set yet, and the
   name or address your phone will type, filled in with this machine's LAN
   address (`192.168.1.20`). Click **Set and switch**. The bind, the password
   and the host are saved at once, and the bind waits for a restart. The
   **Allowed hosts**, **Password** and **Sessions** cards appear.
2. Under **Allowed hosts**, add any other name or address you will type in
   the phone's browser. The list is for the names other devices use: on the
   machine itself the board keeps working at `http://127.0.0.1:8765`, behind
   the same sign-in. An empty list refuses every other device's browser, and
   the card then offers this machine's address.
3. Restart Kraft so it binds the new address. When Kraft runs as a service,
   the screen offers **Restart Kraft**. Otherwise run `kraft admin restart`,
   which reads the new bind from `access.yaml`. A server running in a
   terminal only stops, so start it again there with `kraft`. A restart ends
   the agent of every active item, and each stops as failed until you retry
   it. The dialog says how many are active. Pause them first to avoid that:
   see [A restart ends running agents](/get-started/install#a-restart-ends-running-agents).
4. From the phone, open `http://192.168.1.20:8765/` and log in. The traffic
   is plain HTTP, so anyone on the network can read it.

## Over Tailscale

The Access screen offers only `127.0.0.1` and `0.0.0.0`, so set a Tailscale
bind in `access.yaml` by hand. Set a password first, as in
[Set a password](#set-a-password): picking **Local network** writes
`bind: 0.0.0.0`, and the host it asks for, pre-filled with the machine's LAN
address, goes on `allowed_hosts`. Replace that host with your tailnet name
there (step 2 sets it in the file anyway), and step 2 replaces the bind before
any restart.

1. Find the machine's Tailscale address and name:

   ```bash
   tailscale ip -4        # e.g. 100.101.102.103
   tailscale status       # the first line names this machine
   ```

2. In `access.yaml`, set `bind` to that address and add the machine's tailnet
   name to `allowed_hosts`:

   ```yaml
   bind: 100.101.102.103
   allowed_hosts:
     - mybox.tailnet-name.ts.net
   ```

   Setting `bind` in the file, rather than passing `--host`, keeps the
   `kraft` CLI in your other shells pointed at the same address, and keeps
   the bind across a restart. Run `kraft admin doctor` to confirm the file
   parses. The Access screen then shows **Local network** as chosen, since
   the bind is off loopback. Do not click it: that writes `0.0.0.0` over
   your address. Don't change anything on the Access screen until you
   restart: any save there rebuilds `access.yaml` from what the running
   server holds, and reverts your hand-edited `bind` and `allowed_hosts`.
3. Restart Kraft, as in [On your local network](#on-your-local-network), so
   it reads the new bind.
4. From a device on your tailnet, open `http://mybox.tailnet-name.ts.net:8765/`.
   Tailscale encrypts the traffic between your devices.

Start Tailscale before Kraft: the Tailscale address does not exist until
Tailscale is up, and the bind fails without it.

## Over a Cloudflare Quick Tunnel

::warning
A Quick Tunnel puts the board on the public internet. Anyone who finds the
`*.trycloudflare.com` URL reaches the login page, and the password is the
barrier. Kraft locks an address out for 15 minutes after 5 failed logins, but
if the tunnel does not pass on the visitor's address, every visitor counts as
one address and a stranger's guesses can lock you out too. See
[Login](/project/security#login). Open only the tunnel's `https://` URL, so the
session cookie is marked `Secure`. The tunnel also needs a `0.0.0.0` bind,
which listens on every interface, your LAN included. If your LAN is
untrusted, block the port at your firewall for other interfaces.
::

1. Run `cloudflared tunnel --url http://localhost:8765`. It prints a
   `*.trycloudflare.com` URL. The URL changes every time `cloudflared`
   starts: after the first time, add each new hostname under **Allowed
   hosts**, where it applies at once, with no restart.
2. On the Access screen, choose **Local network**, setting the password if
   it asks. The phone's host field is pre-filled with the machine's LAN
   address: replace it with the tunnel's hostname. Or, with a password
   already set, write `bind: 0.0.0.0` and the hostname under `allowed_hosts`
   in `access.yaml`.
3. Restart Kraft, as in [On your local network](#on-your-local-network).

Keep the bind in `access.yaml`, not in `kraft admin start --host 0.0.0.0`.
`kraft admin restart` starts the server from `access.yaml` alone, so a bind
you passed with `--host` is gone after a restart. The tunnel then reaches a
server on `127.0.0.1`, which skips auth for local clients. Only the hostname
check stands between it and the internet: Kraft refuses a request addressed
to any name but `127.0.0.1`, `localhost` or `[::1]`.

## Verify

1. From the phone or other machine, request the health endpoint, which needs
   no login:

   ```bash
   curl -s https://<your-tunnel-hostname>/api/health
   ```

   Over Tailscale, use `http://mybox.tailnet-name.ts.net:8765/api/health`. A
   JSON status confirms the request reaches Kraft.
2. Open the same address without `/api/health` in a browser. You should see the
   login page. Log in with your password.
3. If the browser shows a page saying Kraft does not answer to the name you
   opened, the hostname is missing from `allowed_hosts`. The page names it.
   A script gets a 403 with "unexpected Host" instead. Add it in `access.yaml` and restart, or on the Access
   screen from an address already on the list, where it applies at once. Enter
   the name alone, as `mybox.tailnet-name.ts.net`. Kraft drops a port or an
   `http://` you type with it, and refuses a wildcard.
4. On a computer, the sidebar reads **live** next to **Kraft** once the
   board's event connection is open, and the board updates without a reload.
   If it stays on **reconnecting…**, check that anything between the browser
   and Kraft, such as a reverse proxy, passes WebSocket connections through
   and keeps the `Host` header the browser sent.

## On the phone

Kraft switches to a phone layout on its own when the window is narrower than
768 pixels, with no setting to turn on. It is the same app at the same address,
signed in the same way, so a link copied on one opens on the other. Widening
the window brings the desktop layout back on the same page. A phone screen
the desktop has no page for opens the nearest one: **More** opens the board,
and one harness, profile, schedule or notification channel opens its list,
with the harness or profile selected.

A bar at the bottom holds **Board**, **Search**, **Analytics** and **More**.
**More** lists everything else: Chains, Library, Harnesses and Repos, then
Policy, Auto-intake, Notifications, Access, Appearance and About, then
Analytics and **Archived**. An archived item opens from there, and **Restore**
on the item puts it back on the board.

- On the board, a card that needs you carries its own buttons: **Approve** and
  **Reject…** for a gate, **Answer…** for a question, **Retry…** for a failed
  item, and **Open** for a cap or dollar cap, whose raise is on the item. Tap
  the card for the item. **Approve** asks first, naming the node the item
  moves on to, since a passed gate is not taken back; **Open the review**
  there reads the gate's document instead.
- An item opens as its chain, node by node; tap a node for its tasks, a task
  for its log. **Review and decide** opens the gate's document and diff.
  Comments you added there and have not sent are counted as pending, and
  **Approve** asks before it sends them with the approval.
- **New work item** files an item from the phone. An item that has not
  started offers **Start**. A spec or plan attached when it was filed is
  listed under its title; tap one to read it.
- A stopped item's bar offers two actions, by why it stopped:
  - a failed item, or most other stops: **Escalate** and **Retry**;
  - a question: **Escalate** and **Answer**;
  - a merge conflict: **Cancel…** and **Review the conflicts**;
  - a closed merge request: **Cancel…** and **Reopen MR**;
  - a cap: **Steer** and **Retry**. When the cap names its limit, the card
    also offers **Raise the** followed by that limit, such as **Raise the
    running time cap…**;
  - a dollar cap: **Steer** and **Raise budget** when the item can raise it
    (its own cap, or the item-wide `budget_usd`). For a daily, token or
    node-level cap, **Steer** and **Retry**: the card says the item can't
    raise that cap, so raise it in the policy or the chain first.
