Where Kraft's logs are and how to read them, and how to reclaim the disk space
that worktrees take. Read [Before you start](/guides/run/operations#before-you-start) first.

## Find the logs

All logs are in `run/logs/`.

| File | Holds |
|---|---|
| `server.log` | The server's own output: startup, shutdown and its reason, errors. A foreground `kraft` writes here as well as to the terminal. Kraft moves it to `server.log.1` at start once it passes about 8 MB, replacing the last one. |
| `<session id>.log` | One worker session: everything an agent or command printed. Kraft never deletes these. |
| `<session id>.times.jsonl` | When each line of that session's log was written, one JSON object per line: `{"n": <line number>, "t": <timestamp>}`. [How Kraft uses it](#line-times-in-a-session-log) |

Read a session's log through Kraft rather than by file name:

```bash
kraft view logs ID                    # the newest session; while stopped, the one that stopped it
kraft view logs ID --session SESSION  # one session
kraft view logs ID -f                 # follow a running session
```

While the item is stopped, a bare `kraft view logs ID` shows the session that
stopped it, and names the newest one, such as an auto-escalation, on stderr.
With `-f` it follows the newest one instead, and names on stderr the session
that stopped the item.
`kraft view events ID --type worker_session_created --json` lists the item's
session ids.

### Line times in a session log

`kraft view logs` and the item page's log take a line's time from
`<session id>.times.jsonl` when the line carries none of its own.

## Reclaim disk space

Each work item gets a git worktree in `run/worktrees/<item id>/`, a full
checkout of its repo, plus any dependencies its setup command installed. That
adds up.

A worktree is removed when the item is abandoned or archived:

- **Abandon** a work item you no longer want: `kraft item abandon ID --yes`.
  It removes the worktree, and deletes the item's local branch and its
  attachment copies in `run/attachments/`. Uncommitted work is lost, and so
  are commits you never pushed.
- **Archive** a completed or abandoned item from the board's Done group, or
  with `POST /api/work-items/ID/archive`. It removes the worktree and keeps
  the item's record and its attachment copies, so you can still duplicate
  it.
  - It deletes the local branch only when every commit on it is somewhere
    else too: another branch such as the base, a remote-tracking branch, a
    tag, or what Kraft pushed. Otherwise the branch stays, and the archive
    event says how many commits it kept.
  - Commits on a detached HEAD in the worktree are kept on a new branch,
    `kraft/rescued/<item id>`. If Kraft cannot make that branch, it archives
    the item but leaves the worktree, and the archive event's `worktree_kept`
    says why.
  - Uncommitted changes in the worktree are lost: commit them, or copy them out
    from `kraft repo open ID`, before you archive.
- **Auto-archive.** `archive.after_days` in `policy.yaml` archives completed
  and abandoned items that old. The shipped file sets `30`. Lower it to
  reclaim space sooner. See [Policy](/reference/configuration/policy).

`kraft item complete` and `kraft item cancel` keep the worktree until the
item is archived. A cancelled item that never pushed keeps its branch after
that too. Delete it by hand once you are done with it:
`git branch -D <branch>`.

Session logs in `run/logs/` and result files in `run/results/` stay after
archiving. Delete old ones by hand if they grow, with the server stopped.

To see what uses space:

```bash
du -sh ~/.kraft/run/*
```
