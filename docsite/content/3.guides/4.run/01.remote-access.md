---
title: Remote access
description: Approve or reject a gate from a phone, over Tailscale, a tunnel or a reverse proxy you run, using the same password auth as the local board, get back if Kraft does not restart, and rotate the token.
---

Reach the Kraft board from a phone or another machine by binding it off
loopback and turning on password auth. You get the real board, with the same
auth, at an address you choose.

## Before you start

- A password. Kraft refuses any bind off loopback until one is set.
- The hostname or address you will type in the other device's browser. It goes
  in `allowed_hosts`.
- The port. It is 8765 unless you set `port` in `access.yaml` or pass `--port`.
  Use your port wherever this page says 8765.
- `access.yaml`, which lives in `$KRAFT_CONFIG_DIR` when you set it, else in
  `$KRAFT_HOME/config/` (by default `~/.kraft/config/`).

Which of these you need depends on the way in you pick. [Choose a way](#choose-a-way)
comes next.

## Choose a way

Kraft binds `127.0.0.1` by default and skips auth for local clients. Any other
bind makes Kraft require the password from every client, local ones included,
and check browser Host headers against `allowed_hosts`.

Pick the narrowest way that works, then follow only its section. The first
four end at [Restart Kraft](#restart-kraft) and [Check it worked](#check-it-worked).
The last, the webhook proxy, needs no restart of Kraft.

| Way | Choose it when | It needs |
|---|---|---|
| [Over Tailscale](#over-tailscale) (recommended) | Your devices are on one tailnet. Only they can reach the board, and your LAN cannot. | Tailscale running before Kraft, a hand edit of `access.yaml`, and a restart. |
| [On your local network](#on-your-local-network) | The phone and this machine share a network you trust. | A `0.0.0.0` bind, which listens on every network this machine is on, and a restart. |
| [Over a Cloudflare Quick Tunnel](#over-a-cloudflare-quick-tunnel) | You cannot use Tailscale, and accept the board on the public internet. | `cloudflared`, a `0.0.0.0` bind, a long random password, and a restart. |
| [Behind a reverse proxy you run](#behind-a-reverse-proxy-you-run) | You run Caddy, nginx or another proxy, and want the board at a name of your own. | A `0.0.0.0` bind, a password, the name in `allowed_hosts`, a proxy that passes `Host`, `Origin` and the WebSocket on, and a restart. |
| [Put a proxy in front of Kraft](/guides/run/put-a-proxy-in-front-of-kraft) | A tunnel or reverse proxy on this machine gets a `403` for every request, and what must pass through is webhooks or scripts, not the board. | The proxy's `Host` setting, a password, and an `X-Forwarded-For` the proxy sets itself. |

The path a request takes in each way:

```text
Tailscale      phone -> tailnet -> 100.101.102.103:8765
Local network  phone -> your LAN -> 192.168.1.20:8765
Quick Tunnel   phone -> *.trycloudflare.com -> cloudflared -> :8765
Reverse proxy  phone -> proxy (Host: kraft.example.com) -> 127.0.0.1:8765
Webhook proxy  webhook -> proxy (Host: localhost) -> 127.0.0.1:8765
```

## Set a password

Kraft refuses any bind off loopback until a password is set, both at
`kraft admin start` and on the Settings › Access screen. On `127.0.0.1` the
screen lists the password under **Not used on 127.0.0.1**, and picking
**Local network** asks for one: **Set and switch** saves the password and the
`0.0.0.0` bind in one step (on a phone, a **Set a password** sheet does the
same). The button reads **Switch** when a password is already set.

Once the bind is off loopback, every browser signs in, including one on the
machine itself. Kraft stores only the password's hash, in `access.yaml`. The
Access screen's **Password** card changes it once Kraft is off loopback.

To set a password and leave the bind alone, send it by itself while Kraft is
still on `127.0.0.1`. This reads it without echo and passes it through pipes
between built-in and `jq` commands, so it stays out of your shell history and
the process list. It needs `jq`. Run `read` first, type the password, and press
Enter:

```bash
IFS= read -rs PW
```

Then send it and clear it:

```bash
printf '%s' "$PW" | jq -Rs '{password: .}' | curl -X PUT http://127.0.0.1:8765/api/access \
  -H 'Content-Type: application/json' --data @-
unset PW
```

You know it worked when the reply shows `"password_set":true`.

## Over Tailscale

The Access screen offers only `127.0.0.1` and `0.0.0.0`, so set a Tailscale
bind in `access.yaml` by hand. Start Tailscale before Kraft: the Tailscale
address does not exist until Tailscale is up, and the bind fails without it.

1. Set a password with the commands in [Set a password](#set-a-password).
   They leave the bind on `127.0.0.1`. Picking **Local network** on the Access
   screen would also set one, but it writes `bind: 0.0.0.0` with it.
2. Find the machine's Tailscale address and name. `tailscale ip -4` prints the
   address, such as `100.101.102.103`:

   ```bash
   tailscale ip -4
   ```

   The first line of `tailscale status` names this machine:

   ```bash
   tailscale status
   ```

3. Pause any active item. Once you edit `bind` in the next step, the `kraft`
   CLI dials the new address, where nothing listens yet, so
   `kraft admin restart` cannot list the agents it is about to end.
4. In `access.yaml`, set `bind` to that address and add the machine's tailnet
   name to `allowed_hosts`:

   ```yaml [config/access.yaml]
   bind: 100.101.102.103
   allowed_hosts:
     - mybox.tailnet-name.ts.net
   ```

   Setting `bind` in the file, rather than passing `--host`, keeps the `kraft`
   CLI in your other shells pointed at the same address, and keeps the bind
   across a restart. Run `kraft admin doctor` and read its `access.yaml` row to
   confirm the file parses. Its `server` row fails until the restart.

   From here until the restart, change nothing on the Access screen. Opening
   it, or using its **Restart Kraft** button, is safe. A change made there
   rewrites `access.yaml` from what the running server holds, which reverts
   your hand-edited `bind` and `allowed_hosts`.
5. [Restart Kraft](#restart-kraft) so it reads the new bind.
6. From a device on your tailnet, open `http://mybox.tailnet-name.ts.net:8765/`.
   Tailscale encrypts the traffic between your devices.

After the restart the Access screen shows **Local network** as chosen, since the
bind is off loopback. Do not click it: that writes `0.0.0.0` over your Tailscale
address.

## On your local network

1. Open Settings › Access and choose **Local network** (`0.0.0.0`). The screen
   asks for what is missing: a password if none is set yet, and the name or
   address your phone will type, filled in with this machine's LAN address
   (`192.168.1.20`).
2. Click **Set and switch**, which reads **Switch** when a password is already
   set. The bind, the password and the host are saved at
   once, and the bind waits for a restart. The **Allowed hosts**, **Password**
   and **Sessions** cards appear.
3. Under **Allowed hosts**, add any other name or address you will type in the
   phone's browser. The list is for the names other devices use: on the machine
   itself the board keeps working at `http://127.0.0.1:8765`, behind the same
   sign-in. An empty list refuses every other device's browser, and the card
   then offers this machine's address.
4. [Restart Kraft](#restart-kraft) so it binds the new address.
5. From the phone, open `http://192.168.1.20:8765/` and log in. The traffic is
   plain HTTP, so anyone on the network can read it.

## Over a Cloudflare Quick Tunnel

::warning
A Quick Tunnel puts the board on the public internet. Anyone who finds the
`*.trycloudflare.com` URL reaches the login page, and the password is the
barrier.

Kraft locks an address out for 15 minutes after 5 failed logins, but
if the tunnel does not pass on the visitor's address, every visitor counts as
one address and a stranger's guesses can lock you out too. See
[Login](/project/security#login).

Open only the tunnel's `https://` URL, so the
session cookie is marked `Secure`. The tunnel also needs a `0.0.0.0` bind,
which listens on every interface, your LAN included. If your LAN is
untrusted, block the port at your firewall for other interfaces.
::

1. Run `cloudflared tunnel --url http://localhost:8765`. It prints a
   `*.trycloudflare.com` URL. The URL changes every time `cloudflared` starts:
   after the first time, add each new hostname under **Allowed hosts**, where it
   applies at once, with no restart.
2. On the Access screen, choose **Local network**, setting the password if it
   asks. The phone's host field is pre-filled with the machine's LAN address:
   replace it with the tunnel's hostname. Or, with a password already set, write
   `bind: 0.0.0.0` and the hostname under `allowed_hosts` in `access.yaml`.
3. [Restart Kraft](#restart-kraft) so it binds the new address.

Keep the bind in `access.yaml`, not in `kraft admin start --host 0.0.0.0`.
`kraft admin restart` starts the server from `access.yaml` alone, so a bind you
passed with `--host` is gone after a restart. The tunnel then reaches a server
on `127.0.0.1`, which skips auth for local clients. Only the hostname check
stands between it and the internet: Kraft refuses a request addressed to any name
but `127.0.0.1`, `localhost` or `[::1]`.

## Behind a reverse proxy you run

Caddy, nginx or another proxy you run can serve the board at a name of your own
while Kraft listens on a network bind behind it. Kraft listens on plain http, so
the proxy serves https. Off loopback, Kraft asks every client for the password or
a token before any API call, a proxy on this machine included. `/api/health`, the
page and its assets are open. Kraft also checks the `Host` and `Origin` the proxy
passes on.

1. Set a password with the commands in [Set a password](#set-a-password).
2. In `access.yaml`, set `bind` off loopback and add the name your browser will
   type to `allowed_hosts`:

   ```yaml [config/access.yaml]
   bind: 0.0.0.0
   allowed_hosts:
     - kraft.example.com
   ```

   Bind `0.0.0.0`, not `127.0.0.1`, even when the proxy runs on this machine. On a
   loopback bind Kraft ignores `allowed_hosts` and answers only a loopback `Host`,
   so the board's sign-in and every change would be refused as cross-site. That is
   why [Put a proxy in front of Kraft](/guides/run/put-a-proxy-in-front-of-kraft)
   serves webhooks and scripts only.

   Until the restart, change nothing on the Access screen: a change there
   rewrites `access.yaml` from what the running server holds and undoes this edit.
3. Block port 8765 at your firewall for every address but the proxy's, before you
   restart. The wider bind listens on every network this machine is on, and a
   request that reaches the port directly meets only the password, over plain
   http.
4. Set the proxy to pass what the table lists, with the setting your proxy uses
   for each. The first four rows are what the board needs. The last one keeps the
   sign-in lockout per client.

   | The proxy must | What Kraft does with it | Without it |
   |---|---|---|
   | Pass `Host` as the browser sent it, port included. Do not set it to `localhost` or to Kraft's own address. | Checks the name against `allowed_hosts` for a browser request, and compares the `Host` with the `Origin` of every write and of the live-update socket. | An unlisted name gets a `403` that names it. A `Host` rewritten to `localhost` or `127.0.0.1` (nginx's default) loads the page, but Kraft refuses the sign-in, every change and the socket as `cross-site request refused`. |
   | Pass `Origin` through unchanged. | Refuses a write (any request but `GET` or `HEAD`) or a socket whose `Origin` names another host and port than `Host`, unless it names this machine. | An `Origin` the proxy changes gets the `403`, `cross-site request refused`. One it drops turns the cross-site check off for writes. |
   | Pass the WebSocket upgrade for `/ws/events`. | Applies the same checks and the sign-in to the socket, and closes it when one fails. | No live updates: the sidebar shows **reconnecting…** instead of **live**. |
   | Send `X-Forwarded-Proto: https` when it serves https. | Marks the session cookie `Secure` when the request is https or this header says `https`. | The cookie is not marked `Secure`. |
   | Append the client's address to `X-Forwarded-For`. Do not pass a caller's own header through as sent. | Takes the client from the last address in the header that is not `127.0.0.1` or `::1`, and counts failed logins per client. | Every visitor counts as one address: 5 failed logins from anyone lock everyone out for 15 minutes. A header passed through as sent lets a caller pick its own address, so it is never locked out. |

   Kraft takes the client address from `X-Forwarded-For` only when the peer is at
   `127.0.0.1` or `::1`, which is uvicorn's default list. A proxy on another
   machine connects from its own address, so Kraft takes every client for that
   proxy and the lockout is shared. `FORWARDED_ALLOW_IPS` in the server's
   environment replaces the list: set it to that proxy's address only, never `*`.

   The hop from a proxy on another machine to Kraft is plain http, so the password
   crosses that network in the clear.
5. [Restart Kraft](#restart-kraft) so it binds the new address.
6. Check it as [Check it worked](#check-it-worked) says, at the proxy's own name,
   including the two requests for this way.

## Restart Kraft

The first four ways end here, and so does [Rotate the token](#rotate-the-token).
Kraft binds a new address, and writes a new token, only when it starts. Pick the
option that matches how Kraft runs:

- When Kraft runs as a service, the Access screen offers **Restart Kraft**.
- Otherwise run `kraft admin restart`, which reads the new bind from
  `access.yaml`.
- A server running in a terminal only stops, so start it again there with
  `kraft`.

A restart ends the agent of every active item, and each stops as failed until
you retry it. The dialog says how many are active. Pause them first to avoid
that: see [A restart ends running agents](/guides/run/restart-kraft#a-restart-ends-running-agents).
When Kraft is back, resume what you paused with `kraft item resume ID`.

### If Kraft does not come back

A restart stops the old server first, then starts one on the new bind. If
Tailscale is down or the address is mistyped, the start fails, and the `kraft`
CLI dials the new address, where nothing answers. For a server started with
`--detach`, `kraft admin restart` prints the error and where the whole log is:

```text
kraft: detached start failed: <the last error line of the log>
<the end of the server's output>
kraft: the whole log is /home/you/.kraft/run/logs/server.log
```

The first line names the cause only when the log has a last line that looks
like `SomeError: text`, and then it is that line. Otherwise the cause is in the
end of the output. A server you ran in a terminal is only stopped: `kraft admin restart`
prints `kraft: was running attached to a terminal - start it again there: kraft`
and exits 1, and the error shows in that terminal when you run `kraft`.

If the server does not answer within 10 seconds, it prints
`kraft: detached start did not come up within 10s - check <the log's path>`.
A service is restarted through its manager instead: when the board stays
unreachable, read the end of `run/logs/server.log`.

1. Fix the cause, or put the old bind back: set `bind` in `access.yaml` to what
   it was before your edit (`127.0.0.1` if you never changed it).
2. Start Kraft again: `kraft admin start --detach`, or `kraft admin restart`
   when it runs as a service, or `kraft` in the terminal where you ran it.

You know it worked when the `status` row of `kraft admin health` says `ok`.

## Check it worked

For the first four ways:

1. From the phone or other machine, request the health endpoint, which needs no
   login:

   ```bash
   curl -s http://mybox.tailnet-name.ts.net:8765/api/health
   ```

   Replace the address with your way's: `http://192.168.1.20:8765` on a local
   network, `https://<your-tunnel-hostname>` through a Quick Tunnel,
   `https://<your-proxy-name>` behind a reverse proxy. A JSON
   status confirms the request reaches Kraft.
2. Open the same address without `/api/health` in a browser. You should see the
   login page. Log in with your password.
3. On a computer, the sidebar reads **live** next to **Kraft** once the board's
   event connection is open, and the board updates without a reload. If it stays
   on **reconnecting…**, check that anything between the browser and Kraft, such
   as a reverse proxy, passes WebSocket connections through and keeps the `Host`
   header the browser sent.

Behind a reverse proxy you run, also check that Kraft asks for credentials and
that the port is closed:

4. Request an API route with no credentials. Put your proxy's name in `name`:

   ```bash
   name=kraft.example.com
   curl -s -o /dev/null -w '%{http_code}\n' "https://$name/api/work-items"
   ```

   It must print `401`. A `403` means Kraft still binds `127.0.0.1`, so restart it,
   or no password is set. A `200` means Kraft took the request for a local one:
   it still binds `127.0.0.1`, behind a proxy that sends `Host: localhost`. That
   is the webhook setup, not this one. Any other answer comes from the proxy
   itself, such as a `502` when it cannot reach Kraft.
5. From a machine other than the proxy's, request the health endpoint at Kraft's
   own port. Put this machine's address in `machine`:

   ```bash
   machine=192.168.1.20
   curl -m 5 "http://$machine:8765/api/health"
   ```

   With the port blocked, this must fail: it times out, or is refused. A JSON
   status means the port is still open to the sign-in over plain http: block it
   before you go on.

The webhook proxy way has its own check, at the end of [its page](/guides/run/put-a-proxy-in-front-of-kraft#check-it-worked).

### The browser says Kraft does not answer to the name you opened

The hostname is missing from `allowed_hosts`. The page names it.

- The list is held to browsers only: `curl`, the `kraft` CLI and MCP are not
  checked against it.
- Add the name in `access.yaml` and restart, or on the Access screen from an
  address already on the list, where it applies at once.
- Enter the name alone, as `mybox.tailnet-name.ts.net`. Kraft drops a port or an
  `http://` you type with it, and refuses a wildcard.

## Rotate the token

`$KRAFT_HOME/run/mcp-token` and `$KRAFT_HOME/run/trigger-token` stay the same
until you delete them. The commands below follow `KRAFT_RUN_DIR` when it is
set, and `kraft admin doctor` prints each token's path. Rotate one when a copy
has leaked, or when someone who held it should no longer have it. [The bearer token](/project/security#the-bearer-token)
says what each one grants. A server accepts the old value until it restarts.

1. Pause any active item. A restart ends their agents, and once the
   `mcp-token` is gone a server bound off loopback refuses the `kraft` CLI, so
   `kraft admin restart` cannot list them.
2. Delete the file you are rotating, or both. Run only the lines you need:

   ```bash
   rm "${KRAFT_RUN_DIR:-${KRAFT_HOME:-$HOME/.kraft}/run}/trigger-token"
   rm "${KRAFT_RUN_DIR:-${KRAFT_HOME:-$HOME/.kraft}/run}/mcp-token"
   ```

3. [Restart Kraft](#restart-kraft). Kraft writes a new token on start, with mode
   `0600`.
4. Resume the items you paused: `kraft item resume ID`.
5. Put the new value wherever you keep a copy. A CI secret or a webhook sender
   holds the `trigger-token`. A script, or a client on another machine, holds the
   `mcp-token`. The `kraft` CLI and the MCP server on this machine read the file
   on every call, so they need no setup.

You know it worked when the file's modification time is the time of the restart:

```bash
ls -l "${KRAFT_RUN_DIR:-${KRAFT_HOME:-$HOME/.kraft}/run}/trigger-token"
ls -l "${KRAFT_RUN_DIR:-${KRAFT_HOME:-$HOME/.kraft}/run}/mcp-token"
```

A file you failed to delete keeps its old time. `kraft admin doctor` also shows
the `mcp token` and `trigger token` rows with the file's path and mode `0600`.
