Each [work item](/concepts/vocabulary#work-item) gets a git worktree in `run/worktrees/<item id>/`, a full checkout of its repo, plus any dependencies its setup command installed. That adds up.

## Before you start

- `$KRAFT_HOME` is `~/.kraft` unless you set it; see
  [Environment variables](/reference/configuration/environment-variables). The
  commands find `run/` as Kraft does: `$KRAFT_RUN_DIR` when you set it, else
  `run/` under `$KRAFT_HOME`.
- Deleting old session logs needs the server stopped. If Kraft runs as a
  service, stop it as [Stop a service](/guides/run/run-as-a-service#stop-a-service)
  says.

## Reclaim disk space

1. See what uses space:

   ```bash
   run="${KRAFT_RUN_DIR:-${KRAFT_HOME:-$HOME/.kraft}/run}"
   du -sh "$run"/*
   ```

   With `storage.worktrees.limit` set, `kraft view storage` lists the worktrees item by item instead. `kraft item archive --reclaimable` archives every finished one, after showing what each loses.

2. Remove the worktrees you no longer need. A worktree is removed when its item
   is abandoned or archived:
   - **Abandon** a work item you no longer want: `kraft item abandon ID --reason "..." --yes`.
     It removes the worktree, deletes the item's local branch, and removes its
     folder in `run/items/` (and an older item's attachment copies in
     `run/attachments/`). Uncommitted work is lost, and so are commits you
     never pushed.
   - **Archive** a completed or abandoned item from the board's Done group,
     with `kraft item archive ID` (it previews first and needs `--yes`), or
     with `POST /api/work-items/ID/archive`. It removes the worktree, the
     sandbox home and the step outputs, and keeps the item's record, documents, session logs and
     attachment copies, so you can still read and duplicate it. Commit uncommitted changes in the worktree first, or copy them out from
     `kraft repo open ID`: archiving loses them.
   - **Auto-archive.** `archive.after_days` in `policy.yaml` archives completed
     and abandoned items that old. The shipped file sets `30`. Lower it to
     reclaim space sooner. See [policy.yaml](/reference/configuration/policy).
3. Delete an archived item's folder, `run/items/<item id>/`, by hand, with the
   server stopped, to drop its documents and session files. Sessions from
   before one folder per item left their logs in `run/logs/` and result files
   in `run/results/`; delete those the same way. All of them stay after
   archiving.

You know it worked when `du -sh "$run"/*` shows `worktrees` smaller, and
`ls "$run/worktrees"` no longer lists the item.

### What archive does to the branch

- It deletes the local branch only when every commit on it is somewhere else
  too: another branch such as the base, a remote-tracking branch, a tag or what
  Kraft pushed. Otherwise the branch stays, and the archive event says how many
  commits it kept.
- Commits on a detached HEAD in the worktree are kept on a new branch,
  `kraft/rescued/<item id>`. If Kraft can't make that branch, it archives the
  item but leaves the worktree, and the archive event's `worktree_kept` says
  why.

An in-place item's archive deletes no folder, and keeps its branch when it holds
commits nowhere else or when the
checkout is on it: see
[Abandon or archive an in-place item](/guides/run/run-items-in-place#abandon-or-archive-an-in-place-item).

`kraft item complete` and `kraft item cancel` keep the worktree until the
item is archived. A cancelled item that never pushed keeps its branch after
that too. Delete it by hand once you are done with it:
`git branch -D <branch>`.

## Clean up from the Storage page

_Added in 2.1_

**Settings › Storage** shows what each worktree uses and archives the finished ones for you. Use it when worktrees are over the limit, or when you want the space back.

![Settings › Storage: the usage bar at 24.7 GB against a 40 GB quota and a 50 GB limit, a Where it goes table by category, and the top of the Worktrees list with Clean up selected and Clean up all](/assets/storage.png)

1. Open **Settings › Storage**. The bar shows the figure against the quota and the limit. **Refresh** measures again; the figure on the page is the last measurement, with its age beside the title.
2. Tick the rows you want to free. Only completed and abandoned items that aren't archived have a box. **Clean up all** takes every one of them.
3. Press **Clean up selected** or **Clean up all**, and read the confirmation. It lists what is freed, where usage lands against the quota and limit, and per item the uncommitted files that are lost and whether the branch stays.
4. Press **Clean up N items and free X**. Each row turns to **Cleaned up** as its worktree goes, and a bar under the list counts the items done and the space freed so far.

Each item moves to **Archived**, and what archiving removes and keeps is as [Reclaim disk space](#reclaim-disk-space) says. You can restore the item from Archived as a record without its worktree. Held starts go within seconds of the clean-up.

You know it worked when the bar drops below the limit and the archived rows leave the list.

Saved copies of a repo's [`carry`](/reference/configuration/repos#carry) files sit in `run/carried/` and show under **other** on this page, outside the quota.

From a shell, `kraft view storage` prints the same breakdown and `kraft item archive --reclaimable` archives after showing the same confirmation. See [View verbs](/reference/cli/view).

## Limit the disk worktrees use

_Added in 2.1_

Without a limit, worktrees use disk until you notice. Set one in `policy.yaml`
and Kraft tells you before the disk is full, and holds new starts at the limit:

```yaml [config/policy.yaml]
storage:
  worktrees:
    limit: 10G
    quota: 8G   # optional; defaults to 80% of limit
```

Run `kraft admin reload` to apply it, or edit **Settings › Policy ›
Housekeeping › Storage**. A size is a whole number and a unit: `1000M`, `10G`,
`1T`. A bare `10` is refused. See [policy.yaml](/reference/configuration/policy#storage-keys).

| State | When | What Kraft does |
|---|---|---|
| `ok` | Usage is at or under `quota`. | Nothing. |
| `over_quota` | Usage is over `quota`, and what archiving can free is at or under `limit`. | Warns in `kraft admin doctor` and `kraft admin health`. |
| `held` | What archiving can free is over `limit`. | Queues starts that need a new worktree, and the instance reads `degraded`. |

The figure is the disk the worktrees, sandbox stores and homes, and each item's
`docs/`, session summaries and step outputs take, measured every 10 minutes and
at startup.
A start that creates a worktree counts an estimate for it at once, so starts
released together can't all pass the limit before the next measurement.

What archiving can free is all of it but the documents and session summaries,
which archiving keeps: they count toward `quota` but never hold a start on
their own. Step outputs are freed by archiving, so they count toward the limit. Kraft deletes nothing for the limit on its own unless
you turn on [automatic clean-up](#let-kraft-make-room).

See where you stand:

```bash
kraft admin doctor
kraft admin health
```

Over the limit, make room in any of these ways, then wait about 10 seconds for
the queue to start what is held:

- **Archive finished items**, from [Settings › Storage](#clean-up-from-the-storage-page) or the board's Done group, as [Reclaim disk space](#reclaim-disk-space) describes.
  Archiving removes the worktree and any uncommitted changes in it, keeps a
  branch with unpushed commits, and leaves the item restorable under Archived.
- **Finish or abandon live work.**
- **Raise `limit`.**

A start that is held shows as `queued` with `work_item_storage_held` on its
timeline. An item that already has its worktree is never held, so finishing it
is always possible.

You know it worked when `kraft admin doctor` reports the storage line as `ok`,
and a held item leaves `queued`.

An item that [runs in place](/guides/run/run-items-in-place), in the repo's
own checkout, has no worktree: the limit never measures it, holds it or
archives it to make room, the Storage page doesn't list it, and a clean-up
preview refuses one: it has no worktree to reclaim.

### Let Kraft make room

An instance left running unattended can sit held with nobody to clean up. Add
`auto_cleanup` and Kraft archives finished items itself when worktrees pass
the limit:

```yaml [config/policy.yaml]
storage:
  worktrees:
    limit: 10G
    auto_cleanup:
      min_age: 24h   # the default; the block being there is what turns it on
```

Over `limit`, Kraft archives completed and abandoned items, oldest first, until
the part of usage archiving can free is at or under `quota`. It never takes an item that ended less than
`min_age` ago, a number of hours or days (`12h`, `24h`, `2d`). The floor is
there because an item that just ended, or a cancelled one you kept to salvage,
may hold uncommitted work, and archiving removes it. A branch with unpushed
commits is kept. `auto_cleanup` needs a `limit`.

An item's documents and session summaries count toward the quota but archiving
keeps them, so they are no reason to archive more, and they hold no start. If
they keep usage over the limit, the server log names the item holding them,
and the Storage page shows them under **Documents**. Abandoning that item
removes them.

If every finished item is newer than `min_age`, nothing is archived and starts
stay held. `kraft admin doctor` then says how many finished items were too
recent, and you make room as above.

Automatic clean-up frees an item's step outputs only through this: it needs a
`limit` and `auto_cleanup`, and archives only items that have a worktree. An
[in-place item](/guides/run/run-items-in-place) has none, so its step outputs
are freed only when you archive it yourself.

You know it ran when an item's timeline has `work_item_archived` with
`reason: storage`, and the Archived view shows it as archived by `auto`.
