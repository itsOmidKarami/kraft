You will be on 2.0, coming from 1.4, and you will know which of its changes need something from you. An upgrade between 2.x releases needs only [Upgrade Kraft](/guides/run/upgrade-kraft). A release candidate, a 0.x home or an install from before the `kraft-sdlc` rename follows [Upgrade from 0.x or a release candidate](/guides/run/upgrade-from-0-x-or-a-release-candidate).

- **On 1.4:** follow [Update from 1.4](#update-from-14), then read [What changed](/reference/changes-from-1-4) for the changes that need something from you.
- **Already ran 1.4's own update:** go to [If you used 1.4's update anyway](#if-you-used-14s-update-anyway).

## Before you start

- You know how Kraft was installed: with uv or `install.sh`, with Homebrew, or with pipx. Step 4 differs for each.
- On uv or pipx, you know the Python Kraft runs on and whether you use vector search. `"$(uv tool dir)/kraft-sdlc/bin/python" -V` prints the Python. The `embeddings` line of `kraft admin health` says `unavailable (the 'vector' extra is not installed` when you don't have the extra.
- `sqlite3` or `python3` is on your `PATH`, for the backup in step 1.
- You can pick a moment when no agent runs, or you will pause the running items first (step 3).

## Update from 1.4

Do not update with 1.4's own `kraft admin update`. That command runs in the
release you have installed, and 1.4's mishandles a uv install and a pipx
install, as step 4 says. Use your package manager:

1. Back up the database, as step 1 of [Upgrade](/guides/run/upgrade-kraft#upgrade) says. 1.4 cannot open
   the database 2.0 migrates. Keep the file name that step prints: a rollback to
   1.4 needs it, and a later upgrade's backup never replaces it.
2. Do what has to come first. Each item names its change below:
   - On a network bind, add each name you use to `allowed_hosts`
     ([Network access](/reference/changes-from-1-4#network-access)).
   - Behind a tunnel or reverse proxy on a loopback bind, make it send a
     loopback `Host` ([Network access](/reference/changes-from-1-4#network-access)).
   - On a repo entry with `test_command: ""`, set a real test command or
     `enabled: false` ([Items and repos](/reference/changes-from-1-4#items-and-repos)).
   - On a repo whose `sandbox:` has no `network:`, add one, or set
     `unrestricted_network: true` ([Items and repos](/reference/changes-from-1-4#items-and-repos)).
   - On a schedule with day of week `7`, change or remove it unless you want it
     to fire on Sundays ([Config directory and files](/reference/changes-from-1-4#config-directory-and-files)).
3. Pause the running items, or wait until none run: 1.4 ends its agents when it
   stops. See [A restart leaves local steps running](/guides/run/restart-kraft#a-restart-leaves-local-steps-running).
4. Install 2.0 with the tool you installed Kraft with:
   - **uv or `install.sh`:** run
     `uv tool install --force --python 3.X "kraft-sdlc[vector]==<version>"`,
     with the Python you installed Kraft with for `3.X` and the release for
     `<version>`: the number without the `v`, as the newest tag on the
     [releases page](https://github.com/itsOmidKarami/kraft/releases/latest) shows
     it (tag `v2.0.0` is `2.0.0`). For example,
     `uv tool install --force --python 3.13 "kraft-sdlc[vector]==2.0.0"`. Leave out
     `[vector]` if you don't use vector search.

     1.4's update installs the new release without the `[vector]` extra and on
     uv's default Python, and leaves `uv tool upgrade` pointing at a file it has
     deleted.
   - **Homebrew:** run `brew update`, then `brew info kraft`. It shows the version
     the tap offers, and `brew info` alone does not refresh the tap.
     - If it still shows 1.4, the tap has no 2.0 yet, and `brew upgrade kraft`
       changes nothing: wait, or run `brew uninstall kraft` and install 2.0 with
       uv as above.
     - Otherwise run `brew upgrade kraft`. 1.4's `kraft admin update` runs the same
       command, and loses nothing: the formula has no `[vector]` extra.
   - **pipx:** run
     `pipx install --force --python python3.X "kraft-sdlc[vector]==<version>"`,
     with `<version>` as above.
     1.4's `kraft admin update` doesn't update a pipx install: it puts a second
     Kraft beside it with uv.
5. Restart the server with `kraft admin restart`. That restart is 2.0's: it
   lists the running items and asks before it ends their agents.

## Check it worked

- `kraft --version` and `kraft admin health` print the release you installed, as step 5 of [Upgrade](/guides/run/upgrade-kraft#upgrade) shows.
- `kraft admin doctor` has a `keys`, `moved keys`, `tests` and `config` row. Each names what 2.0 found in your files: [What changed](/reference/changes-from-1-4) says what to do about it.

## If you used 1.4's update anyway

On a uv install, an update run by 1.4 drops the `vector` extra and moves Kraft to
uv's default Python. Restart right after it, and do not act on the board before:

1. Run `kraft admin restart` as soon as the update finishes.
2. Reinstall `[vector]` with the uv command above, if you use vector search.
   Without it, vector search stops working: see
   [Enable vector search](/reference/web-ui/sidebar-search-and-keyboard#vector-search).
3. If you reinstalled the extra, run `kraft admin restart` once more, to be
   safe. The reinstall replaced files under the server you just restarted, as any
   update does, and a restarted server reads them fresh. The `embeddings` line of
   `kraft admin health` then says `available`.

Before the restart you may see:

- Items under the wrong heading, and a footer that names the new release. 1.4's
  server keeps running and serves 2.0's interface, which misreads its board.
- A banner over the board saying so, from 2.0.0. A 1.5.0rc14 or earlier
  interface had none. `kraft admin doctor`'s `restart` row warns that the
  server runs a release older than the one installed.
- `Internal Server Error` instead of the board, if Kraft ran on a Python other
  than uv's default. 1.4's update moved Kraft to another Python and deleted the
  files the running server serves, though its API still answers.

If you ran `kraft admin update --restart` (or restarted a service), 1.4
restarted the server without asking, which ended the agents of running items.
Pause them first next time.
