---
title: Use the console from another machine
description: Open the terminal UI against a Kraft on another machine, sign in once, and end the session.
---

_Added in 2.6_

`kraft console --server URL` opens the terminal UI against a Kraft on another
machine. Give it the address you would open in a browser. The first time, it
asks for the password you [set](/guides/run/remote-access#set-a-password), then
keeps a session for that address, the same kind a phone gets:

```bash
kraft console --server https://kraft.example.com
```

The session is named `Kraft console on <this machine's name>` in the signed-in
list of the web UI's settings, where you can sign it out. Changing the password
ends it, and it expires on the `session_expiry_days` you set in `access.yaml`.
The console keeps it in `console-sessions.json` in the run directory, readable
by you only. When it ends, the console says so and tells you to run the command
again.

The address must start with `http://` or `https://` and name no path:
`https://proxy.example.com/kraft/` isn't supported. Over plain `http://` to
another machine, the console warns that the password crosses the network
unencrypted, and asks before it goes on. Use
[Tailscale](/guides/run/remote-access#over-tailscale) or TLS. For a certificate
your system doesn't trust, set `SSL_CERT_FILE` to the file that holds its
authority. An SSH forward works like any other address:
`ssh -L 9000:localhost:8765 host`, then `--server http://localhost:9000`.

Some things need the server's own machine, so a remote console hides or
refuses them: [From another machine](/reference/console#from-another-machine)
lists them.

## Check it worked

You know it worked when the console opens on the remote board and the session
`Kraft console on <this machine's name>` shows in the web UI's signed-in list.
