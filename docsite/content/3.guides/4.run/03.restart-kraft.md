---
title: Restart Kraft without ending running steps
description: Stop, restart or update the server while its local steps keep running, and what still ends a step.
---

The server restarts, the local steps it was running carry on, and
`kraft view list --all --status=active` lists the items again. Steps of items
that run in place are the exception: pause those items first.

## A restart leaves local steps running

<!-- renamed from: A restart ends running agents -->

Stopping Kraft leaves the steps it runs on this machine for worktree items
running. That holds for Ctrl-C on a foreground `kraft`, `kraft admin stop`,
`kraft admin restart`, `kraft admin update --restart` within a major version,
and a stop or restart of the
[service](/guides/run/run-as-a-service#run-kraft-as-a-service). The steps
belong to the [local worker](/reference/configuration/workers#the-local-worker),
a process of its own, and it keeps running. When Kraft starts again it picks
the steps up and the items carry on.

Until then nothing answers a step's permission prompts or enforces its time
cap and idle limit. A step that asks for a decision waits, and one that
finishes meanwhile is read when Kraft is back. `kraft admin stop` says how
many steps it leaves running, and `kraft admin stop --now` stops them.

Four things still end a step:

- **An item that runs in place.** Its step runs in your own checkout, so a stop
  ends it. When Kraft starts again the item stops with
  `reattach: running session, PID identity unconfirmed, no result (pid N is not alive)`
  and the board shows it as failed. `kraft item retry ID` is all it needs.
- **`kraft admin stop --now`.** It stops every step, as stopping did before this
  release, and each of those items stops the same way when Kraft is back.
- **A step on another machine.** A stop ends it, as before.
- **An update to a new major version.** It waits until nothing is running. See
  [Update when Kraft is free](/guides/run/upgrade-kraft#update-when-kraft-is-free).

`kraft admin restart` lists the in-place items first and, in a terminal, asks
before going on (`-y` skips the question). With none, it asks nothing.
`kraft admin stop` only lists them.

A stop that finds a `git rebase` under way undoes it before the server exits,
which can take over a minute with a slow checkout filter. `kraft admin stop`
and `kraft admin restart` then print `still stopping: a git rebase is being
undone` and wait for it instead of giving up at 15 seconds. The service's
stop timeout (`TimeoutStopSec`, `ExitTimeOut`) allows for it too: reinstall
the service to get the new value.

## The worker after a stop

_Added in next_

The worker ends on its own a few seconds after Kraft is gone and nothing runs.
Each installed Kraft has a worker of its own: after an update within a major
version the new server starts a new one and takes over the running steps,
while the old worker finishes the processes it started and exits.
`kraft admin uninstall-service` says if a worker is still finishing its steps.

Under a systemd service the worker starts in a scope of its own, outside the
unit's cgroup, so stopping the unit does not end it. Its output goes to
`run/logs/local-worker.log`.

## Restart without ending an agent

To restart without ending the step of an item that runs in place, restart when
nothing is running, or pause the running items first and resume them
afterwards:

1. List the items that may have an agent running:

   ```bash
   kraft view list --all --status=active
   ```

2. Pause each of them: `kraft item pause ID`.
3. Restart the server: `kraft admin restart`, or `kraft admin update --restart`
   when you are also updating. Updating from 1.4 is the exception: use neither
   `update` nor `update --restart`. `kraft admin update` runs in the release you
   have installed, so it would run 1.4's `update --restart`, which neither lists
   the running items nor asks. Follow
   [Update from 1.4](/guides/run/upgrade-from-1-4#update-from-14) instead.

   `kraft admin restart` stops the server and starts it again. For a server
   started with `--detach`, it prints:

   ```text
   kraft: stopped (pid 48213)
   kraft: http://127.0.0.1:8765 (pid 48390, detached - kraft admin stop)
   ```

   When Kraft runs as a service, it prints `kraft: restarted the service`. A
   server running in a terminal only stops: it prints
   `kraft: was running attached to a terminal - start it again there: kraft` and
   exits 1.
4. Resume each item you paused: `kraft item resume ID`.

## Restart when nothing is running

_Added in 2.3_

To restart without pausing anything, ask for the restart at the next free moment:

```bash
kraft admin restart --when-free
```

Kraft restarts once no agent session runs and no item is `active`, `waiting`, `queued` or `rate_limited`, inside any [allowed hours](/reference/configuration/update). It needs a running server, and a service or a server started with `--detach`: a server started in a terminal cannot restart itself. [Update when Kraft is free](/guides/run/upgrade-kraft#update-when-kraft-is-free) has the whole picture.

## Check it worked

`kraft view list --all --status=active` lists the items you resumed.
