Drive Kraft from a coding-agent session over MCP to file work, read the board,
and act on gates without switching to the browser. Install the Claude Code
plugin, then use the `/kraft:*` slash commands instead of remembering CLI flags.

Two things make this work: the `/kraft:*` skills, and the MCP server whose
tools they call (`create_work_item`, `approve_gate`, and so on). The plugin
installs both. For an agent without the plugin, `kraft admin init` and
`kraft admin mcp` set up the same surface by hand.

`kraft` must be on your `PATH` for either route. See [Install](/get-started/install).

## Install the plugin

Kraft publishes a [Claude Code plugin marketplace](https://docs.claude.com/en/docs/claude-code/plugin-marketplaces).
Add it and install the plugin:

```text
/plugin marketplace add itsOmidKarami/kraft
/plugin install kraft@kraft
```

The plugin manifest bundles `kraft admin mcp` as an `mcpServers` entry, so one
install registers the MCP server and the skills. `/plugin update kraft` picks
up new skills, and `/plugin uninstall` removes them.

Then run `/kraft:onboard` in a repo. It connects the repo, runs
`kraft admin init --repo` for a repo-scoped copy of the MCP setup and skills, and
checks that the setup matches what the repo actually contains.

To check that the install worked, start the server (`kraft`) and run
`/kraft:board` in the agent session. It lists the board for the repo you are
in.

## Install by hand without the plugin

Use this route when your agent isn't Claude Code, when you want a `.mcp.json`
that other tools read straight out of the repo, or when you want plain files
instead of Claude Code plugin state:

```bash
kraft admin init          # register the MCP server for your user, install the skills
kraft admin init --repo   # or write .mcp.json + .claude/skills/ into this repo
```

- **User scope** (no flag) runs `claude mcp add --scope user kraft -- kraft admin mcp`,
  then writes the skills under `~/.claude/skills/kraft/`. Every repo you open
  sees Kraft's tools. Kraft shells out rather than editing `~/.claude.json`,
  which is large, shared, agent-owned state. If `claude` is missing or the
  command fails, `kraft admin init` stops and prints that command for you to
  run, and writes no skill files until you rerun it.
- **Repo scope** (`--repo`) writes `.mcp.json` in the current repo, merging
  into any existing one, and the skills under `.claude/skills/kraft/`.

Both forms write the skills directly, with nothing in Claude Code's managed
plugin state, so you remove them by deleting the directory. Both produce the
same `/kraft:*` commands. To check either form, run `kraft admin doctor`: its
`mcp server` row passes once Kraft is registered in `~/.claude.json` or a
connected repo's `.mcp.json`.

For an agent that isn't Claude Code, point its MCP configuration at the
command `kraft admin mcp`, which serves the tools over stdio.

## The skills

Each skill is one moment you'd reach for Kraft, not one skill per tool:

- **`/kraft:onboard`** — Connect a new repo: runs `repo connect`,
  `admin init --repo`, `admin doctor` in sequence, then checks each step
  actually matches the repo.
- **`/kraft:board`** — See what's running, what's blocked or waiting on a
  person, or the state of one work item.
- **`/kraft:prepare`** — Define a spec (and optionally a plan) for
  non-trivial work, then decide whether it runs inline in this session or
  hands off to Kraft.
- **`/kraft:handoff`** — File the work Kraft should run, after a spec and
  plan are agreed.
- **`/kraft:status`** — Report where a work item has got to: phase, next
  node, any gate it's waiting on.
- **`/kraft:gates`** — Approve or reject the gate a work item is waiting on,
  or pause/resume one heading the wrong way.
- **`/kraft:review`** — Read what a gate is about (the document, the spec
  and plan, the diff) and recommend approve or reject, with reasons. It acts
  on the gate only once the person has answered it.
- **`/kraft:steer`** — Redirect a work item: revise a not-yet-started item's
  spec or plan, or pause/resume or retry a started one with a steer that
  stands alone.
- **`/kraft:triage`** — Find why a work item stopped and route it: retry with
  a steer, raise a cap, or hand it to a person. Retries only when told to.
- **`/kraft:doctor`** — Diagnose the server with `admin health` and `admin
  doctor`, apply the fix each failing line names, and verify with a clean
  doctor run.
- **`/kraft:check`** — Check whether a repo's Kraft config has drifted from
  what this version ships: a chain missing a node, a chain that no longer
  resolves, a task naming a skill that isn't installed. Report-only unless
  asked to fix.

## MCP tools

Most skills call MCP tools, which `kraft admin mcp` serves over stdio. The
tools talk to the running Kraft server. `onboard` and `check` instead run
`kraft admin doctor` and `kraft admin init` as shell commands. A skill that
can't reach `kraft` or the server says so instead of reporting a generic
connection error.

The tools you use most:

| Kind | Tools |
|---|---|
| Read | `list_work_items`, `get_work_item`, `search` |
| Write | `create_work_item`, `ensure_repo`, `set_work_item_policy` |
| Act | `approve_gate`, `reject_gate`, `pause_work_item`, `resume_work_item`, `retry_work_item`, `skip_work_item`, `complete_work_item`, `cancel_work_item` |

This is the everyday subset, not the full tool list. Every `kraft`
subcommand (see the [CLI reference](/reference/cli)) has an MCP twin, so hooks
and agents without MCP get the same surface from the command line.

## What an agent cannot do

**An agent cannot start work.** Everything an agent creates lands paused, and the
board shows it as *Not started* with a single Start button. Nothing spends
tokens until a person clicks it.

**A worker cannot act on itself.** Sessions Kraft starts carry
`KRAFT_WORK_ITEM_ID`, and any attempt to approve, reject, pause, resume, retry,
or abandon the work item running that session is refused before a request is
sent. A gate is where a human decides. An agent approving its own would make
the gate decorative.

## Without the orchestrator

[Kraft Lite](/guides/kraft-lite) runs a chain inside a single agent session
with no service and no MCP server.
