title: Use Kraft from your agent
description: Driving Kraft with /kraft:* slash commands from a coding agent instead of the browser.
---

Drive Kraft from a coding-agent session: file work, read the board, and approve
or reject gates without switching to the browser. In Claude Code you do this
with `/kraft:*` slash commands.

**Before you start**, you need Kraft installed with `kraft` on your `PATH`, and
the server running (`kraft`). See [Install](/get-started/install).

## Install the plugin

In Claude Code, add the Kraft marketplace and install the plugin:

```text
/plugin marketplace add itsOmidKarami/kraft
/plugin install kraft@kraft
```

Then, in each repo you want Kraft to work on, run `/kraft:onboard` and follow
what it asks.

To check that it worked, run `/kraft:board`. It lists the board for the repo
you are in.

`/plugin update kraft` picks up new skills. `/plugin uninstall kraft` removes
them.

## Set up without the plugin

Use this when your agent isn't Claude Code, or when you want plain files
instead of a managed plugin.

For Claude Code, run one of:

```bash
kraft admin init          # for every repo you open
kraft admin init --repo   # for this repo only
```

The first registers Kraft with Claude Code for your user and writes the skills
to `~/.claude/skills/kraft/`. It needs the `claude` command; without it, it
prints the command to run instead. The second writes a `.mcp.json` and
`.claude/skills/kraft/` into the current repo, where other tools can read them
too. Either way you get the same `/kraft:*` commands. To remove them, delete
the skills directory.

For any other agent, add an MCP server to its configuration that runs the
command `kraft admin mcp`.

To check either setup, run `kraft admin doctor`. Its `mcp server` row passes
once Kraft is registered.

## The skills

| Skill | Use it to |
|---|---|
| `/kraft:onboard` | Connect the repo you are in and check its setup and test commands. |
| `/kraft:board` | See what is running, blocked, or waiting on a person, or search specs and plans. |
| `/kraft:prepare` | Write a spec (and a plan, if you ask), then decide whether the work runs in this session or in Kraft. |
| `/kraft:handoff` | File work with Kraft, with any agreed spec and plan attached. |
| `/kraft:status` | Report where a work item has got to, or watch it until it ends. |
| `/kraft:gates` | Approve or reject the gate a work item is waiting on, or pause and resume it. |
| `/kraft:review` | Read what a gate is about and recommend approve or reject, with reasons. It acts only once you answer. |
| `/kraft:steer` | Redirect a work item that is heading the wrong way. |
| `/kraft:triage` | Find out why a work item stopped, and retry it, raise a cap, or hand it to you. |
| `/kraft:check` | Report where a repo's Kraft config has drifted from this Kraft version. |
| `/kraft:doctor` | Diagnose an unhealthy Kraft server and fix what it can. |

## What an agent cannot do

**An agent cannot file work and start it in one step.** Everything an agent
creates lands paused, and the board shows it as *Not started* with a single
Start button. Nothing spends tokens until a person starts it, either by
clicking that button or by asking your agent to resume the item
(`/kraft:gates`).

**A worker cannot act on itself.** An agent session that Kraft started cannot
approve, reject, pause, resume, retry, or abandon its own work item. Kraft
refuses the request. A gate is where a human decides; an agent approving its
own would make the gate pointless.

## MCP tools

For an agent without the skills, these are the tools `kraft admin mcp` serves
that you use most:

| Kind | Tools |
|---|---|
| Read | `list_work_items`, `get_work_item`, `search` |
| Write | `create_work_item`, `ensure_repo`, `set_work_item_policy` |
| Act | `approve_gate`, `reject_gate`, `pause_work_item`, `resume_work_item`, `retry_work_item`, `skip_work_item`, `complete_work_item`, `cancel_work_item` |

Every MCP tool is also a `kraft` subcommand (see the
[CLI reference](/reference/cli)), so a hook or an agent without MCP gets the
same surface from the command line.

## Without the Kraft server

[Kraft Lite](/guides/kraft-lite) runs a chain inside a single agent session
