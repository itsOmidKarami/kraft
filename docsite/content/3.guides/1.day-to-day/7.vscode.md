---
title: Kraft for VS Code
description: Install the Kraft extension to clear gates, review a branch's diff, and edit Kraft config files without leaving VS Code.
---

You end with the board in VS Code's sidebar, and errors in Kraft's YAML config
files flagged as you type.

## Before you start

- Kraft running on the same machine. `kraft admin start` holds the terminal; add
  `--detach` to run it in the background.
- A Kraft of the extension's own major release and at least its minor. Against
  any other, the extension is read-only: see
  [If the extension is read-only](#if-the-extension-is-read-only).

## Install

1. Install **Kraft** (publisher `kraft-sdlc`) from the
   [VS Code Marketplace](https://marketplace.visualstudio.com/items?itemName=kraft-sdlc.kraft),
   or from [Open VSX](https://open-vsx.org/extension/kraft-sdlc/kraft), the
   registry VSCodium and Cursor install from. Or search for `kraft-sdlc.kraft` in
   the Extensions view.
2. Optionally, for completion and instant structure checks in config files,
   install
   [Red Hat YAML](https://marketplace.visualstudio.com/items?itemName=redhat.vscode-yaml).
   The extension offers it once if it is missing.

Every release also attaches the extension as `kraft-<version>.vsix`. To install
one by hand, download it from the
[GitHub release](https://github.com/itsOmidKarami/kraft/releases/latest) and run:

```bash
code --install-extension kraft-<version>.vsix
```

## Check it worked

Open the Kraft view in the sidebar: it lists your work items in the groups the
web board uses: Needs you, Running, Not started and Done. Each row shows the
item's title, then why it is there, such as "agent asks: …" or "failed at
implementation". A running row also says where it is in its chain, such as
"implementation · step 2 of 5". Hovering a row shows its id and the full reason.
Cancelled items stay under Done.

Icons carry the state in colour and shape. An item waiting on you (a gate, a
question, a budget stop) has a yellow icon, and a failed or capped item a red
one, a different shape each. A running item has a plain play icon. Screen
readers read each row as its title, state and reason, and each group with its
count, such as "Needs you, 3 items".

Below the reason, the hover shows what the item has spent and how long it has
run, each against its cap, such as "Spent $2.41 of $5.00" and "Ran 1h 12m of
2h", or "(no cap)" when it has none.

The status bar shows a check mark beside `Kraft` while the extension is
connected and nothing waits on you, and `Kraft (read-only)` when the versions do
not match or the workspace is in [Restricted Mode](#in-restricted-mode).

While connected, the status bar also shows how many items in scope wait on you,
such as `Kraft 2`, the same count as the Needs you group. When something waits,
it shows a bell in place of the check mark on VS Code's warning background. It
leaves the number out when nothing waits.

While connected, hovering `Kraft` shows what Kraft has spent today against its daily cap, such
as "Today: $1.20 of $20.00" or "Today: $0.500 (no daily cap)". It reads the
figure on connect and again at most every 30 seconds while the board changes,
and leaves the line out when the server does not answer.

Click `Kraft` in the status bar for **Show Log**, **Open Web UI**, **Start
Kraft** (only while it is disconnected) and **Retry Now**. **Kraft: Show Log**
in the Command Palette opens the same log: it records each connect, disconnect
and retry with its delay, every request Kraft refused, and every command that
failed.

While the extension cannot connect, hovering `Kraft` says why, and an empty
Kraft view shows one row:

| Row | Meaning | Clicking it |
| --- | --- | --- |
| Kraft isn't running — Start | Nothing answers at `kraft.url`. | Starts Kraft in the background: `kraft admin start --detach`, from `kraft.path`. |
| Kraft refused the token — check kraft.url | Kraft answered but rejected the token: `kraft.url` points at another Kraft, or the token changed. | Opens the `kraft.url` setting. |
| Kraft error: … — Show log | Kraft answered with another error. | Opens the log. |

The extension retries on its own, waiting 1 second, then 2, 4 and so on up to
30 seconds between tries. **Retry Now** tries again at once.

**Start Kraft** runs from your home folder and shows "Starting Kraft…" until
Kraft answers, then connects. A Kraft that is already running is said so, and
the extension reconnects to it. When the binary is not found, **Get Kraft**
opens the [install page](/get-started/install) and **Open Settings** opens `kraft.path`. Any other failure shows Kraft's own error, with the full
output in **Show Log**. Clicking again while one start runs says "Kraft is already starting."

## Which items the board shows

_Added in next_

The board, the count on its icon and the notifications cover the repos of the
window's folders. A folder matches its repo the way Kraft matches it, so these
all show the repo's items:

- A subfolder of the repo.
- A symlinked path to it.
- A linked worktree of it.
- A submodule or nested repo under a connected repo.

A window opened on an item's worktree shows that item's repo.

Archived items sit under **Archived**, the last group, collapsed. Expand it to
list them, then right-click one, or select several, and run **Restore** to put
them back under Done. The group reads its items from Kraft when you expand it,
when the extension connects, and after an item is archived or restored. If that
read fails, the group shows one row saying why.

**Archived** shows only while the board has other items. When it has none,
restore from the Command Palette with **Kraft: Restore**, which lists the
archived items to pick from, or from the web UI.

**Show All Repos**, in the view's title bar, widens the board, the count and the
notifications to every repo Kraft has work in. **Show This Repo**, in the same
place while all repos show, goes back to this window's repos. Both are also in
the Command Palette.

The choice is kept per workspace: reopen the folder, or reload the window, and
the board shows the repos it showed when you left it.

When this window's repos have no Kraft work, the view says "No Kraft work in
this repo." with a **Show all repos** link.

When a folder's repo isn't connected to Kraft at all, the view says "This repo
isn't connected to Kraft." instead, after one sentence on what Kraft is and what a
gate is, with a **What is Kraft?** link to the docs and a **Connect this repo** link (also
**Kraft: Connect This Repo** in the Command Palette). It connects the repo with
the commands Kraft detects, and the board then reads the connected repos again.

To set the test or setup command yourself, connect from the web UI or with
`kraft repo connect`. Connecting from VS Code needs Kraft on this machine: when
`kraft.url` points elsewhere, neither the link nor the command is offered, and
you connect the repo from the web UI or with `kraft repo connect` on Kraft's
machine. A read-only window doesn't offer them either.

To work in an item's worktree, right-click the item and run **Open Worktree in
New Window**. It appears only while the item's worktree is on disk: not before
the item has run, and not once its worktree is reclaimed.

## File work from VS Code

_Added in next_

Four commands file a work item without leaving the editor:

- **Kraft: File Work Item…**, in the Command Palette and as `+` in the Kraft
  view's title bar.
- **File as Kraft Spec…** and **File as Kraft Plan…**, on a `.md` file in the
  Explorer: the file is attached as the item's spec or plan.
- **File Selection as Kraft Work…**, on a selection in the editor: its first
  line is the title and the whole selection is the description.

Each asks, in order:

1. The title, and an optional description. From a selection, only the title:
   the selection, line breaks and all, is the description.
2. Which documents to attach: none, the open `.md` file as spec or plan, or
   files you pick.
3. The chain: the repo's default, or one of the chains this repo can run.
4. How to file it. The picker's title previews what will run, such as
   `default · 4 of 6 nodes run · 1 gate · skips spec (spec attached)`.
   **File paused** files it without starting it, so nothing spends tokens until
   you start it. **File and start** starts it, or queues it when every slot is
   busy. **More options…** opens Kraft's web page with what you entered, for the
   settings these steps do not ask.

The item is then selected on the board, and a notification says how it was
filed.

- The repo must be connected to Kraft and enabled. Otherwise the command says
  so before it asks anything: run `kraft repo connect` in the repo.
- An attached file must be saved, and inside the repo or one of its worktrees:
  Kraft commits it on the item's branch. An unsaved change asks you to save
  first.
- Filing works only with Kraft running on the same machine as the window's
  files. When `kraft.url` points at another host, the commands say so: file the
  item from the web UI instead.
- When Kraft warns about the item it filed, such as an open item with the same
  title, the warning appears after filing, with **Open item** and **Abandon**. **Abandon** asks first, and says so instead when the item has started
  since.

## Clear a gate

When a gate opens, VS Code shows a notification with **Open** and **Reject…**,
or **Open** only while the extension is read-only. It names the item by its
title and says what the gate asks, such as "Design the caching layer: approve
spec". A notification for an item that failed or hit a cap or budget is a
warning; a question or a gate is not.

- **Open** shows the gate's document rendered, in a locked Markdown preview. The
  tab ends with the item's id, as in `[Preview] Spec (K-12).md`.
- **Approve**, **Reject…**, **Review Changes** and **Submit Review** are in that
  tab's title bar; Approve and Reject are on the item in the sidebar too.
  Approve sends the version that preview showed. On an older preview of the
  item, such as the spec's once the plan gate is up, it opens the latest
  document instead.
- The preview's own **Open Source** button shows the Markdown as text, to search
  or copy from.
- Approving a gate whose document you have not opened opens it instead
  ("Read <gate> first: the document is open."); approve again once you have read it.
- If a chain revision changed since you read it, the tab reloads with the new one
  and the approval is refused; read it and approve again.

A message says what was approved ("Approved: <title> · approve spec"), and where
the item went when Kraft already knows. A gate that is followed by a merge or a
push asks first ("Approve and merge <title> into the target branch?"); every
other gate is one click. Kraft sends no flag for this, so the extension reads
the item's chain: a `merge` or `push` node or task between this gate and the next.

The item leaves the Needs you group in the sidebar.

Approve is not offered while the gate has unresolved must-fix review threads.

## Act on an item

_Added in next_

Right-click an item in the Kraft view. The menu lists only what Kraft would
accept for that item now, the same doors the web interface offers:

| Command | What it does |
|---|---|
| **Pause**, **Resume…**, **Retry…** | Stop the item, or start it again. Resume and Retry take an optional steer. |
| **Skip** | Pass the node the item stands on, or its pending gate, without running it. Asks first. |
| **Raise Budget…** | Raise the spend cap that stopped the item, and retry it. Enter a positive number of dollars, or `none` for no cap. |
| **Unblock** | Stop the item coming after the items it still waits on. |
| **Escalate…** | Ask an agent to help. Not offered on a spend-cap stop, since the agent would hit the same cap. |
| **Complete…**, **Cancel** | End the item. Both need a reason, which is recorded on the item. |
| **Archive**, **Restore** | Move a finished item to the archive and back. Archiving asks first while the item has a worktree, since it is deleted. |

### Act on several items

Select several items with Ctrl-click or Shift-click (Cmd-click on macOS), then
right-click one of them. The menu shows a command only when the row you
right-clicked allows it. **Pause**, **Resume…**, **Archive** and **Restore**
act on the whole selection; every other command acts only on the item you
clicked. Archiving asks first, since worktrees are
deleted.

A row's **Resume…** button, clicked on a selected row, also acts on the whole
selection, with no steer. Click it on an unselected row to resume just that
item with a steer.

Items Kraft would not accept the command for are left alone. Resume sends no
steer, and leaves out an item that asked a question: answer it on its own.
One message then says how many items the command reached, and names each item
it did not, with the reason.

### Row buttons

An item that waits on you shows one button on its row when you hover it, the
same action the web board's row offers:

| Item | Button |
|---|---|
| At a gate | **Open Gate Document** |
| Asking a question | **Answer…**: resumes it. The input box shows the question, and your answer steers the item. |
| Stopped by its spend cap | **Raise Budget…** |
| Failed, or stuck in a loop | **Retry…** |
| Paused mid-chain | **Resume…** |
| Stopped by a loop cap, or another stop | **Open in Web UI** |

The notification for an item that asks a question offers **Answer** (the same
as the row's button) instead of **Retry**, and only while Kraft would accept a
resume. Other stops keep **Retry**. While the extension is read-only, the
notification offers only **Open in Web UI**.

A button shows only while Kraft would accept it. Answer, Raise Budget, Retry
and Resume are hidden while the extension is read-only.

Clicking an item at a gate opens its gate document. Clicking any other item
only selects it.

### Watch a worker

Right-click an item and run **Show Worker Log**. A terminal named
`Kraft: <id>` opens on one of the item's agent sessions: while the item is
stopped, the session it stopped on; otherwise the newest.

- The terminal shows the recent lines first, then new ones as the agent writes
  them. Each line has its time, its source and its text.
- When the session ends, a closing line gives the session's status, such as
  `— session done —`, and the terminal stays open.
- If the connection drops, the log reconnects without repeating lines. After
  three failed tries in a row it stops with `— stream lost: <reason> —`. A
  refusal such as an unknown session or a rejected token stops it at once.
- Close the terminal to stop following. Running the command again on the same
  item replaces its terminal.

An item that has not run an agent yet has no log: VS Code says so instead of
opening a terminal.

### Open the merge request, spec or plan

Right-click an item to open what it links to. Each entry shows only on an item
that has one:

| Entry | What it opens |
|---|---|
| **Open Merge Request** | The item's merge request, in your browser. Only an `http` or `https` link is offered. |
| **Open Spec**, **Open Plan** | The spec or plan the item was filed with, as Kraft stored it at intake, in a read-only editor tab. Editing the original file since does not change it. |

A long document is cut short, and the tab ends with a line saying so: open it
in the web UI for the whole of it. If Kraft no longer has its copy of the
document, VS Code shows the server's message instead.

## From the Command Palette

_Added in next_

While VS Code is connected to Kraft, the Command Palette has two entries of
its own:

- **Kraft: Approve Next Gate…** lists the items waiting at a gate, the
  longest-waiting first. Pick one to open its gate document, then approve or
  reject it from the tab's title bar.
- **Kraft: Open Item…** lists every item the board shows. Pick one to select it
  on the board: an item at a gate opens its gate document, any other opens in
  the web UI.

Most commands on an item's right-click menu are in the palette too, such as
**Kraft: Pause** or **Kraft: Show Worker Log**. Run from there, it first asks
which item, listing only the items it applies to now. **Kraft: Restore** lists
the archived items. When none applies, VS Code says so instead, such as
"Nothing here can pause now."

Some stay where their item is already known. **Kraft: Approve** and **Kraft:
Reject** show only while a gate document is open. **Review Changes**, **Submit
Review** and **Discard Review Comments** are not in the palette: they act on the
item of the row or review tab you run them from. Commands that change an item are hidden while the extension is read-only,
except Approve and Reject, which then say why they cannot run.

## Search

_Added in next_

Run **Kraft: Search…** from the Command Palette while VS Code is connected to
Kraft. Type what you are looking for: VS Code searches Kraft's documents (specs,
plans, gate documents and session summaries) once you stop typing, and lists
each hit with its kind, its repo and the passage that matched.

| You pick | What happens |
|---|---|
| A hit that belongs to a work item | The item is selected on the board. If the board does not show it (it is archived, or in a repo outside this window), it opens in the web UI instead. |
| A hit with no work item | The document opens in a read-only editor tab. |

If Kraft cannot run the search, or can only run a text search because vector
search is failing, the reason shows in the search box's title.

## Review a branch

1. Right-click the item in the Kraft view and run **Review Changes**, or run it
   from a gate document's title bar. The branch opens in the multi-file diff
   editor.
2. Read the findings from the review agents. They show on the lines they name,
   as a colored bar with the message beside the line, and in the Problems panel.
3. Add a comment on any line, on either side. It asks for a label: **Must fix**,
   **Question**, **Nit** or none.
4. Run **Submit Review**. Pick the outcome, then add an optional note for the
   agent.

Comments are Kraft's review threads: the same ones the web UI's review and
`kraft view threads` show, with their label, lines and side. Every comment is a
draft until you submit a review, wherever it was written, and a draft's title
says **Draft**.

Edit or delete your drafts from the comment's title bar. Resolve or reopen a submitted thread from the thread's title bar. A draft
must-fix thread blocks Approve: change its label or delete it. Threads come
back fresh when an agent replies and when the window regains focus.

Threads on the whole change, and threads on files this review does not show,
are listed in one document: **Show Threads Not on a File in This Review**, in
the diff's title bar.

What **Submit Review** offers depends on the item:

| The item | Outcomes |
|---|---|
| At a gate | **Request changes** (the threads go to the fix node), **Comment** (an agent answers in the threads; the gate stays open) or **Approve**. |
| Not at a gate | **Request changes** only. On a paused item the request is queued, and the item stays paused until you resume it. |

Approving a gate while drafts are waiting asks to send them with the approval.
No agent acts on comments sent with an approval.

**Request changes** asks where the work restarts. The default is Kraft's own
choice. You can pick an earlier node instead, or, with no gate, the current one.
Once a fix loop is out of rounds, Request changes is not offered at that gate.

**Approve** with a must-fix thread open lists the threads that block it; pick
one to go to it. A draft must-fix thread can only be relabelled or deleted.

**Submit Review** and **Discard Review Comments** show on an item with draft
comments, once its threads are loaded: at a gate, stopped on you (paused,
failed or out of budget), or after **Review Changes**. **Discard Review Comments** deletes every draft on the item, the web
UI's and the CLI's included.

After updating from a 1.x extension, comments you had not submitted move to the
item's review as drafts the first time Kraft connects. Each lands on the whole
change and names its file and line. If the item has nothing to review any more,
the extension shows their text instead.

## Edit config files

Files under `$KRAFT_HOME/config` (`policy.yaml`, `harnesses.yaml`, `chains/*.yaml`
and the rest) get completion from Kraft's JSON Schemas, and the running Kraft
checks each edit and flags the line at fault. On a chain file, **Show Resolved
Chain** previews the chain after inheritance. On save, the extension asks the
running Kraft what the file needs:

- **Reload Kraft**, when Kraft can reread the file live: the library, chains,
  `policy.yaml`, `intake.yaml` and `addons.yaml`.
- **Restart Kraft**, when Kraft reads it only at startup: `notify.yaml` and
  `access.yaml`. Restarting ends running agents.
- Nothing, for files Kraft reads each time it needs them, such as
  `harnesses.yaml` and `repos.yaml`.

A Kraft started by a service manager restarts itself. One started from a
terminal opens a terminal in your home folder running `kraft admin restart`
with the binary **Start Kraft** runs (`kraft.path`).

If that restart fails, as it does for a Kraft running attached to a terminal,
which it stops, a notification says so and offers **Start Kraft**. If Kraft
still answers, as when you answer no to its question about running agents,
the notification says Kraft is still running and offers nothing.

A reload that Kraft partly refuses names each refused file and its reason.

## Settings

| Setting | What it does |
|---|---|
| `kraft.url` | Where Kraft listens. Empty reads `KRAFT_HOST` and `KRAFT_PORT`, then `bind` and `port` from `access.yaml`. Set in your user or Remote settings only: a workspace's settings cannot change it. |
| `kraft.path` | The `kraft` binary **Start Kraft** runs. Empty runs `kraft` on your `PATH`; a leading `~` means your home folder. Set in your user or Remote settings only. |
| `kraft.notifications` | `all`, `gates` or `off`: `all` notifies when an item needs you or fails, `gates` only when a gate opens. Pausing an item yourself never notifies. |

## In Restricted Mode

_Added in next_

In a workspace you have not trusted, the extension runs read-only. The board,
gate documents and **Review Changes** work. Every action, from Approve to
**Submit Review** and **Start Kraft**, shows "Kraft is read-only in Restricted
Mode: trust this workspace to act." The status bar item reads
`Kraft (read-only)`, with the reason in its tooltip.

Config checks, schema completion, **Show Resolved Chain** and **Lint Template
Library** start once you trust the workspace, with no reload.

## If the extension is read-only

The extension works with a Kraft of its own major release and at least its
minor: the 2.0 extension needs Kraft 2.0 or a later 2.x. Against any other, it
turns read-only. The board still updates, every action is disabled, and its
status bar item reads `Kraft (read-only)`.

| The extension | The server | The fix |
|---|---|---|
| 2.0 | 1.4 | [Upgrade from 1.4](/guides/run/upgrade-from-1-4#update-from-14). |
| 1.4 | 2.0 | Update the extension. |

### An extension newer than Kraft

- When it connects, it shows a warning that says which to update, and the status
  bar item's tooltip repeats it: against a 1.4 server, "This extension (2.0.0)
  needs Kraft 2.0 or later; this server runs 1.4.0. Update Kraft. Actions are
  disabled until they match."
- When you then try an action, it shows "Kraft is read-only: this server's
  version does not work with this extension. Hover Kraft in the status bar to see
  which one to update."

VS Code updates the extension on its own, so after a new major release this is
what you see until you [update Kraft from 1.4](/guides/run/upgrade-from-1-4#update-from-14).

### An extension older than Kraft

The rule holds the other way too: an extension from 1.4, one whose updates are
off or that you pinned, is read-only against a 2.0 server. The 1.4 extension
has no tooltip and says less. When it connects, it shows "Kraft 2.0.0 does not
match this extension (1.4.0); actions are disabled until they match." When you
try an action, it shows "Kraft is read-only: the daemon's version does not match
this extension." Update the extension as well.
