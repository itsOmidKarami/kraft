---
title: Get notified when an item needs you
description: "Set up a webhook or alerts in your browser, so Kraft tells you when a work item waits at a gate or stops, and check that a test reaches you."
---

Set up one channel and send a test through it, so Kraft tells you when a [work item](/concepts/vocabulary#work-item) needs a decision or has stopped and you don't have to watch the board.

## Before you start

- Kraft running, with the board open in a browser. See [Install](/get-started/install).
- Nothing else for a browser alert. For a webhook, the URL of a service that accepts a JSON `POST`.
- For a webhook, know that Kraft sends one fixed JSON body and can't reshape it. A service that needs another format needs a receiver in between that translates it. [Events](/reference/events#notifications) shows the body.

![Settings › Notifications: a Webhook channel, active and This browser, blocked, each with the events it sends and Send a test, beside a preview of what a notification looks like](/assets/notifications.png)

## Choose a channel

| | Webhook | This browser |
|---|---|---|
| Sent by | The Kraft server, so no browser has to be open. | The Kraft page, so a Kraft tab has to be open. |
| Reaches you | In the service behind the URL. | As a system notification, while that tab is hidden. |
| Kept | For the whole install, in `config/notify.yaml`. | In that browser only. |

You can turn on both. Each sends only for the events you chose on it. Settings offers three events: a gate waiting, an item stopped for a person and a start held for storage. [Which events send](/reference/events#which-events-send) lists them with the alert text and the message body.

::tabs{sync="channel"}
:::tabs-item{label="Webhook"}
1. Open **Settings › Notifications** and select the **Webhook** card. Its pane opens on the **Config** tab.
2. Paste the service's URL into **Webhook URL**. It must start with `http://` or `https://`. It usually carries a token, so Kraft never shows it back. A message names the item's title, so see [Data and privacy](/project/data-and-privacy) before you point it at a service you don't run.
3. Set **Link back** to an address the device reading the message can open, such as `http://192.168.1.20:8765`. Left empty, the link uses the address and port Kraft is bound to: `http://127.0.0.1:8765` by default, which opens only on the machine Kraft runs on, and `http://0.0.0.0:8765` on a server bound to `0.0.0.0`, which opens nowhere.
4. Move focus out of the field, or press Enter. Everything on this pane saves when you change it, with no **Save** button: Kraft writes `config/notify.yaml` with mode `0600`, and says `Saved · writes notify.yaml`.
5. Turn on **Webhook notifications**. It saves as you switch it.
6. Under **Notifies**, switch off an event you don't want. Each row says what it means, with the event's ID under it. Both are on until you do.
7. Under **Test**, select **Send a test**. The button works only while the webhook is on; when it is off, the text beside it says what to set first. While a URL is typed but not yet saved, it says to press Enter to save it.

The line beside the button then reads like this, with the status the service answered and the time it took:

```text
last delivered just now · 200 · 123 ms
```

The test sends `"type": "test"` and no item. The service receives the title `Send a test`. Kraft doesn't follow a redirect.
:::

:::tabs-item{label="This browser"}
1. Open Kraft in the browser you want the alerts in. Open **Settings › Notifications** and select the **This browser** card. Its pane opens on the **Config** tab.
2. Read the first thing in the pane, under **Permission**. If it says `Allow notifications`, select that button and allow them in the browser's prompt.
3. Turn on **Alerts on this device**. It stays dimmed, with the reason beside it, until the browser allows notifications.
4. Under **Notifies**, switch off an event you don't want, named as on the webhook. This browser keeps its own choice. Both are on until you do.
5. Under **Test**, select **Send a test**. The button works only while the switch is on and the browser allows notifications.

The test shows an alert titled `Test alert` with the text `a decision is waiting`, and the line beside the button reads `last shown just now`.

Keep a Kraft tab open. Alerts come from that page, and only while it is hidden, for example behind another tab or with the window minimised. Selecting an alert brings the window forward and opens the item.
:::
::

On a phone, open **More › Notifications**. The channels are **Webhook** and **This browser**, and each field saves when you edit it, with no **Save** button. **This browser** has the same **Notifies** switches as on a desktop. The phone words some results differently, such as `failed 1m ago: ConnectError`. This guide's quoted texts are the desktop's.

## When Kraft's own chains need attention

_Added in 2.6_

Kraft's own chains are the built-in `kraft-default`. When a release changes it in a way that touches your setup, `kraft admin doctor` says so in its `kraft-default` row. You don't have to run it to find out:

- The board shows a banner, "Kraft's own chains need attention", with the first three lines and **Hide until it changes**.
- A browser alert with the same title arrives once per new state, when the tab is hidden and **Alerts on this device** is on.
- The webhook gets one message, once per new state, unless `kraft_default: false` is in `notify.yaml`.

Run `kraft admin doctor` for the fix. None of this makes the server `degraded`.

## Check it worked

- **Webhook.** The line beside **Send a test** reads `last delivered` with a status from `200` to `299`, and the message arrives in the service. The next time an item reaches a gate, a `POST` arrives whose `title` is the item's title and whose `url` opens the item. `kraft view show ID` names the same stop. A status outside that range is explained in [If nothing arrives](#if-nothing-arrives).
- **This browser.** The line beside **Send a test** reads `last shown`, and an alert titled `Test alert` appears.

## If nothing arrives

The texts are the desktop's. On a phone, the webhook's dimmed button says `Turn on the webhook and set a URL first.`, and a failed test reads `failed 1m ago: ConnectError`.

| What you see | What it means | Fix |
|---|---|---|
| **Send a test** is dimmed, with `set a webhook URL first` | No URL is stored. | Do steps 2 to 5 of the webhook tab. |
| **Send a test** is dimmed, with `set the channel active first` | A URL is stored, but the switch is off. | Turn on **Webhook notifications**. |
| `url must be an http or https URL`, or the same for `base_url` | The address has another scheme, such as `file:`. Kraft refuses a URL that doesn't start with `http://` or `https://` beside the field and doesn't send it. | Use a full `http://` or `https://` address. |
| Kraft answers `set a webhook URL before enabling notifications` | The URL isn't saved yet. | Do step 4 of the webhook tab first, then turn on **Webhook notifications**. |
| `last attempt 1m ago, failed: ConnectError` | Kraft couldn't reach the URL. The line names the kind of error, never the address. | Check the URL and that the server can reach the service. |
| `last delivered` with a status that isn't 2xx | The service answered, and didn't take the message. The test says `delivered`, and a toast says `Test sent to the webhook`, for any answer, a redirect or a `404` included. | Read the status: the service didn't accept the URL or the body. A service that wants its own format needs a receiver in between. |
| The test works, but no message comes for an item | Kraft sends one message per item every 10 seconds, a sliced item and its slices counting as one, only for the events you chose, and never for events from while the server was down. | Check **Notifies**. After a failed send, the item's timeline holds a `notification_failed` event: `kraft view events ID --type notification_failed`. |
| A hand edit of `notify.yaml` changes nothing, though Settings shows it | A running server reads the file only when a setting is saved or at start, and Settings shows what is on disk meanwhile. | Change a setting that saves on its own, such as switching an event off and back on, or run `kraft admin restart`. The URL and link back save as you leave each field. |
| The log says `notify.yaml: ... -- notifications disabled until it is fixed` | Kraft couldn't use the file, so it sends nothing. The text before the dashes is `not valid YAML`, `cannot be read`, or a key and its problem, such as an unknown key or an unknown event type. | Settings can't open or save a file it refuses. Edit the file by hand, fix or remove the bad name, then run `kraft admin restart`. [Find the logs](/guides/run/find-the-logs#find-the-logs) says where the log is. |
| The browser pane's first line says `Notifications are blocked` | The browser refused notifications for this site, and Kraft can't ask again. | Follow the pane's steps in the browser's own site settings, then select **Check again**. |
| The browser pane says `This browser can't show notifications` | This browser has no notifications to turn on. | There is no switch to turn on: use the webhook. |
| The browser's **Send a test** is dimmed, with no hint | It works only while **Alerts on this device** is on and the browser allows notifications. | Do steps 2 and 3 of the browser tab. On a phone, only the permission is needed. |
| No browser alert, though the test worked | Alerts show only while the Kraft tab is hidden, and only while it is open. | Switch to another tab or window, and leave the Kraft tab open. |
