_Added in next_

[Herdr](https://herdr.dev/) is a terminal workspace manager that tracks coding agents in its sidebar. The Kraft plugin puts every live [work item](/concepts/vocabulary#work-item) there as an agent of its own, with a tab that follows the item's log. Kraft still runs the workers. Herdr only shows them.

## Before you start

- Kraft running, with at least one repo connected. See [Install](/get-started/install). It must have `kraft view events --all`, which arrived with this guide: with an older Kraft, the `kraft bridge` tab keeps printing `unrecognized arguments: --all`.
- Herdr 0.9.2 or newer. The plugin is checked against Herdr 0.9.5.
- `python3` 3.9 or newer on the machine, so the macOS system Python is enough. Herdr restarts a tab with the first `python3` it finds, whatever you have installed besides. The plugin needs nothing else.
- `kraft` on the `PATH` that Herdr starts with. Set `kraft` in [the options](#options) when it isn't.

## Install the plugin

```bash
herdr plugin install itsOmidKarami/kraft/plugins/herdr
```

Herdr shows what the plugin runs and asks you to confirm. Its startup hook runs each time Herdr starts, so restart Herdr once after installing. A `Kraft` workspace then appears, holding one tab named `kraft bridge` and one tab per live work item.

## What you see

Each item's tab is named `<short id> <title>`. It shows the log of the item's newest worker session, then the next session's when that one ends. Before an item has run, its tab says it is waiting for a worker session. After the item ends, the tab prints `finished: <status>` and stays open until you close it.

The sidebar shows the item as an agent named `kraft`. The state comes from the item's [status](/reference/cli/view#reading-the-board), and the label beside it says more:

| Item status | Herdr state | Label |
|---|---|---|
| `running` | working | the current node |
| `escalated` | working | `helper agent` |
| `needs_you` | blocked | the gate that waits |
| `failed` | blocked | `failed` |
| `paused` | idle | `paused` |
| `waiting` | idle | `waiting` |
| `queued` | idle | `queued` |
| `blocked` | idle | `after another item` |
| `done`, `cancelled`, `archived` | idle | `merged`, `cancelled`, `archived` |

Herdr's *blocked* means a person is needed, so it shows only for `needs_you` and `failed`. Kraft's own `blocked`, an item that comes after another item, needs nobody, so Herdr shows it as idle with the label `after another item`.

The bridge reads the board again whenever Kraft reports an event, and every minute regardless. An item that leaves the board because it was archived or abandoned is marked finished once and doesn't reopen. Closing the tab of a live item doesn't stop the item, but the bridge opens the tab again on its next pass.

## Take over an item from its tab

With an item's tab focused, run the **Take over this Kraft item** action from Herdr's action list. It opens a pane beside the tab and runs [`kraft item takeover`](/guides/day-to-day/take-over-an-item) for that item. The same rules apply: the item must be `paused` or `needs_human`. The tab keeps following the log. On any other pane the action says it isn't a Kraft item tab and does nothing.

## Options

Create `config.json` in the plugin's config directory, which Herdr gives to the plugin as `HERDR_PLUGIN_CONFIG_DIR`. Every key is optional.

```json
{
  "notify": true,
  "kraft": "/usr/local/bin/kraft"
}
```

| Key | Default | Meaning |
|---|---|---|
| `notify` | `false` | When an item moves into `needs_you` or `failed`, show a Herdr notification titled with the item's title, with its stop reason as the body. An item already waiting when the bridge starts doesn't notify. |
| `kraft` | `kraft` | The command to run, for an install that isn't on the `PATH`. |

Changes apply the next time the bridge starts: close the `kraft bridge` tab and start Herdr again.

## Check that it works

```bash
kraft view events --all -f --json
```

Every event of every item arrives as one line, from now. The bridge reads this same stream. `--all` needs `-f`, because there's no backlog to print.

If the sidebar shows no Kraft agents, open the `kraft bridge` tab. It prints each error it meets and carries on, and a second bridge started by a Herdr handoff says so and exits.
