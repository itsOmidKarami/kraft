title: Raise a cap on a stopped item
description: "Clear a time, attempts or dollar stop from the interface or the command line, with no config edit."
---

Raise the cap that stopped a [work item](/concepts/vocabulary#work-item) and retry it from where it stopped. Its own cap can exceed the chain's, up to `maxima.work_item`, so you need no config edit.

## Raise the cap and retry

You need a work item that a cap stopped. The board shows it under **Needs you**, and `kraft view show ID` names the limit it hit. `kraft view list` shows its ID.

In the interface:

1. Open the item. Its banner names the limit it hit.
2. Select **Raise cap**. On a phone, a dollar stop offers **Raise budget** instead.
3. Enter a higher value, or pick +$5, +$10 or no cap for a dollar cap, then select **Save & retry**. The editor shows the current value and the [policy](/concepts/vocabulary#policy)'s maximum, if there is one.

From the command line, for a dollar cap:

```bash
kraft item raise-budget ID --usd 25
```

```text
raised the cap on <id> to $25 and retried it; the item is now running
```

On the item-wide `budget_usd`, `raise-budget` sets the item's policy override and keeps every other field the override sets. It raises whichever dollar cap stopped the item.

For a time or attempts cap:

```bash
kraft item set-policy ID --policy time_cap_minutes=240
kraft item retry ID
```

You know it worked when the item has left **Needs you** and sits under **Running**, and the header's **N NEED YOU** count is one lower. The command ends by saying the item is running: `kraft item retry ID` prints `retried <id>; the item is now running`. If it says the item is "stopped for a person", the item stopped again: `kraft view show ID` says why.

Not every stop offers a raise: [which stop offers what](#which-stop-offers-what) says which do. For what the caps are, and why a raise is bounded, see [Caps and budgets](/concepts/caps-and-budgets).

## Which stop offers what
<!-- not new: moved from the web UI reference's cap stops page -->

| What stopped it | In the interface | From the command line |
|---|---|---|
| A [fix loop](/concepts/vocabulary#fix-loop) out of attempts (`max_attempts`) or time (`timeout_minutes`) on its node | **Raise cap** opens that limit's editor | `set-policy`, then `retry` |
| The item's `time_cap_minutes` or `total_time_cap_minutes` | **Raise cap** opens that limit's editor | `set-policy`, then `retry` |
| The item-wide `budget_usd` | **Raise cap** (phone: **Raise budget**) opens a one-number editor and writes the item's policy | `raise-budget ID --usd N` |
| The item's own dollar cap, the one `kraft item create --budget` sets | **Raise cap** (phone: **Raise budget**) opens the budget editor on the Config tab | `raise-budget ID --usd N` |
| Any other cap, such as a gate's timeout or a `loops:` entry in `policy.yaml` | **Open config**: raise it as for the time caps | as for the time caps |
| The daily cap, a `token_budget`, or a node, step or task's `budget_usd`, which names no limit | No raise: the item says why and offers **Retry** | [below](#if-the-stop-has-no-raise) |

The editor shows the limit's current value and the policy's maximum. **Save & retry** sets the value in the item's policy, keeping its other overrides. A refusal, such as a value past the maximum, shows beside the field, and nothing is retried. A dollar cap's editor offers +$5, +$10, no cap or an amount you type.

On a phone, the bar's **Raise cap**, beside **Steer**, opens the same editor as a sheet titled for the limit, such as **Raise the running time cap**.

On the board, a row's **Raise cap** for a time or attempts cap opens the side panel on its Config tab, which has no editor for it. Select the panel's own **Raise cap** there. A row for any budget stop reads **Raise budget**, and what it opens depends on the stop:

- **The item-wide `budget_usd`**: the side panel's Overview, with the **Raise budget cap** dialog open.
- **The item's own cap**: the Config tab, with the budget editor open.
- **A budget the item can't raise**, the day's cap for one: a banner (on a phone, a card) that says why not and offers **Retry**.

## What limits a raise
<!-- not new: moved from the web UI reference's cap stops page -->

`set-policy` replaces the item's whole override, so repeat every `--policy` you set earlier, or they are dropped. Read what the override holds in `policy_override` in `kraft view show ID --json`. `--clear` removes it.

A cap on one path, such as `verification.time_cap_minutes=90`, may exceed that scope's level default up to its level's maximum. It may not exceed what the chain, the item's cap or an enclosing path already gives it. Kraft refuses a larger value and names both scopes.

A change to `budget_usd` or `token_budget` in `policy.yaml` reaches only items filed after it. If every slot is busy, `raise-budget` and the MCP `raise_budget` tool raise the cap and queue the retry. `kraft item pause` takes the item out of the queue, as **Remove from queue** does in the web UI.

## A stop on unknown spend

A `budget_usd` stop on unknown spend is different: no higher cap passes it, since Kraft still can't show the scope is under the new one. Clear the item-wide cap instead. This also retries the item:

```bash
kraft item raise-budget ID --usd none
```

`budget_usd=none` means no dollar cap for the work item, and none for each node, step or task the chain set no `budget_usd` on. It is item-wide only, and refused when `maxima.work_item.budget_usd` is set. A cap the chain set on a node, step or task still binds.

## If the stop has no raise

The daily cap, a `token_budget` and a node's `budget_usd` aren't raised with **Raise cap** or `raise-budget`. The item says so and offers **Retry**.

- **`token_budget`:** `kraft item set-policy ID --policy token_budget=N`, then `kraft item retry ID`.
- **A node's `budget_usd`:** skip the node with `kraft item skip ID`, or raise the cap in the chain and file the item again.
- **`budget.daily_usd`:** raise it in `policy.yaml`, or wait for local midnight. Then run `kraft item retry ID`.

A node's `budget_usd` is the per-scope cap in [Caps and budgets](/concepts/caps-and-budgets#the-per-scope-cap).
