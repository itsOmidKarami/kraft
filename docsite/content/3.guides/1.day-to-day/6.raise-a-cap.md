---
title: Raise a cap on a stopped item
description: "Raise the cap that stopped a work item, from the interface or the command line, and retry it from the same place."
---

A cap or budget that stops a [work item](/concepts/vocabulary#work-item) can be raised for that item, and the item retried. This guide raises it from the interface or the command line and checks that the item left **Needs you**. For what the caps are, and why a raise is bounded, see [Caps and budgets](/concepts/caps-and-budgets).

A work item's own cap can exceed the chain's, up to `maxima.work_item`. You need
no config edit.

## Before you start

- A work item that a cap stopped. The board shows it under **Needs you**, and
  `kraft view show ID` names the limit it hit.
- Its ID, for the command line: `kraft view list`.

## Which cap stopped the item

The stop decides what the item offers.

| What stopped it | In the interface | From the command line |
|---|---|---|
| A [fix loop](/concepts/vocabulary#fix-loop) out of attempts (`max_attempts`) or time (`timeout_minutes`) on its node | **Raise cap** opens that limit's editor | `set-policy`, then `retry` ([below](#raising-a-time-or-attempts-cap-from-the-command-line)) |
| The item's `time_cap_minutes` or `total_time_cap_minutes` | **Raise cap** opens that limit's editor | `set-policy`, then `retry` |
| The item-wide `budget_usd` | **Raise cap** (phone: **Raise budget**) opens a one-number editor | `kraft item raise-budget ID --usd N` |
| The item's own dollar cap | **Raise cap** (phone: **Raise budget**) opens the budget editor on the Config tab | `kraft item raise-budget ID --usd N` |
| Any other cap, such as a gate's timeout or a `loops:` entry in `policy.yaml` | **Open config**: raise it as for the time caps | as for the time caps |
| The daily cap, a `token_budget`, or a node's `budget_usd` | No raise. The item says why and offers **Retry** | `set-policy` for the last two; the daily cap is [refused](#raising-a-budget-from-the-command-line) |

## Raising a cap in the interface

An item that a time or attempts cap stopped names the limit it hit and offers
**Raise cap**: an editor for that one limit, showing its current value and the
policy's maximum, if there is one. **Save & retry** sets the new value in the
item's policy, keeping the item's other policy overrides, and retries the item.

- **On a phone**, the bar's **Raise cap**, beside **Steer**, opens the same
  editor as a sheet titled for the limit, such as **Raise the running time
  cap**.
- **On the board**, a row's **Raise cap** for these caps opens the side panel
  on its Config tab, which has no editor for them. Click the panel's own
  **Raise cap** there: its main button at the bottom, or the one in Overview's
  banner.

The table above says which stops name a limit. For a stop that offers **Open
config** instead, you raise the cap as for the time caps. A refusal, such as a
value past the maximum, shows beside the field and nothing is retried.

## Raising a time or attempts cap from the command line

```bash
kraft item set-policy ID --policy time_cap_minutes=240
kraft item retry ID
```

`set-policy` replaces the item's whole override, so repeat every `--policy` you
set earlier, or they are dropped. `--clear` removes the override.

A cap on one path, such as `verification.time_cap_minutes=90`, may exceed that
scope's level default up to its level's maximum. It may not exceed what the
chain, the item's cap or an enclosing path already gives it. Kraft refuses a
larger value and names both scopes.

## The two dollar caps

An item has two dollar caps, and each has its own way up.

### The per-scope cap

`budget_usd` in the item's policy is a per-scope cap, like the time caps. Item-wide
it may exceed the chain's up to `maxima.work_item`. On a path it only tightens.

So this item cannot raise a `budget_usd` that the chain sets on a node, step or
task. Skip that node with `kraft item skip ID`, or raise the cap in the chain
and file the item again.

- **From the command line.** When the item-wide `budget_usd` stopped the item,
  `kraft item raise-budget ID --usd N` raises it and retries, keeping the rest
  of the item's policy. `set-policy` sets it too, but replaces the whole
  override.
- **In the interface.** A stop on the item-wide `budget_usd` names it as its
  limit, so the item's **Raise cap** (on a phone, **Raise budget**) opens the
  one-number editor above and writes the item's policy for you. A stop on a
  node, step or task's `budget_usd` names no limit.
- **What it replaces.** An item-wide `budget_usd` from `set-policy` replaces the
  level defaults on every scope the chain set none on. A cap the chain set on a
  node, step or task still binds: skip that node with `kraft item skip`
  instead.

### The item's own dollar cap

The item's own dollar cap is the one `kraft item create --budget` sets in place
of `budget.work_item_usd`. No `maxima` bounds it.

- **From the command line.** `kraft item raise-budget ID --usd N` (or the MCP
  `raise_budget` tool) raises it and retries the item. `--usd none` lifts the
  cap.
- **In the interface.** The item's **Raise cap** opens the budget editor on the
  item's Config tab, and a phone offers **Raise budget**. Each offers +$5, +$10,
  no cap, or an amount you type. The amount opens with the cap in force
  selected, so what you type replaces it.

### Which one the interface shows

Whichever of the two is lower stops the item first, so that is the one the
item's **Budget** shows, on its Config tab and in the side panel. An item-wide
`budget_usd` in the item's own policy, such as one **Raise cap** wrote, is
listed under **Changed for this item**. While it is the lower cap, the pencil
beside **Budget** changes it rather than the item's own cap.

## Budget stops and what the interface offers

Any other dollar or token stop, such as the daily cap, a `token_budget` or a
node's `budget_usd`, has no raise in the interface. The item says "The item
can't raise this cap: the policy or the chain sets it. Retry once it is
raised there, or after local midnight for the daily cap.", and offers
**Retry** in place of a raise (on a phone, **Retry** alone).

On the board, a row or phone card for any budget stop reads **Raise budget**,
even for one the item can't raise. What it opens depends on the stop:

- **The item-wide `budget_usd`**: the side panel's Overview, with the **Raise
  budget cap** dialog open.
- **The item's own cap**: the Config tab, with the budget editor open.
- **A budget the item can't raise** (the day's cap, say): the item on a banner
  (on a phone, its card) that says why not and offers **Retry**.

## Raising a budget from the command line

`raise-budget` and `raise_budget` raise whichever of the two stopped the item, as
**Raise cap** does. On the item-wide `budget_usd`, they set it in the item's
policy override and keep every other field the override sets.

```bash
kraft item raise-budget ID --usd 25
```

```text
raised the cap on <id> to $25 and retried it; the item is now running
```

Three stops are not raised this way:

- **`token_budget`.** Raise it with
  `kraft item set-policy ID --policy token_budget=N`.
- **A node's `budget_usd`.** Use `kraft item set-policy ID --policy budget_usd=N`.
  That sets the cap item-wide, and a cap the chain set on that node still binds.
- **`budget.daily_usd`.** It is refused everywhere: raise it in `policy.yaml`,
  or wait for local midnight. Then run `kraft item retry`.

`set-policy` replaces the item's whole override, so pass every field it already
sets too (read `policy_override` in `kraft view show ID --json`). A change to
`budget_usd` or `token_budget` in `policy.yaml` reaches only items filed after
it.

If every slot is busy, `raise-budget` changes nothing and says so. Pause
something, or wait, and run it again.

### A stop on unknown spend

A `budget_usd` stop on unknown spend is different: no higher cap passes it,
since Kraft still cannot show the scope is under the new one. Clear the
item-wide cap instead. This also retries the item:

```bash
kraft item raise-budget ID --usd none
```

`budget_usd=none` means no dollar cap for the work item, and none for each node,
step or task the chain set no `budget_usd` on. It replaces the chain's, the
repository's and the `policy.yaml` defaults. It is item-wide only, and refused
when `maxima.work_item.budget_usd` is set. A cap the chain set on a node, step
or task still binds: skip that node with `kraft item skip` instead.
`token_budget`, `budget.work_item_usd` and `budget.daily_usd` still bound the
item.

## Check it worked

1. The command ends by saying the item is running: `kraft item retry ID` prints
   `retried <id>; the item is now running`, and `raise-budget` prints the line
   above. If it says the item is "stopped for a person", the item stopped
   again: `kraft view show ID` says why.
2. On the board, the item has left **Needs you**. It sits under **Running**, and
   the header's **N NEED YOU** count is one lower.
