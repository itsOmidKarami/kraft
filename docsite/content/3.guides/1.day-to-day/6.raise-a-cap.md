---
title: Raise a cap on a stopped item
description: "Clear a time, attempts or dollar stop from the interface or the command line, with no config edit."
---

Raise the cap that stopped a [work item](/concepts/vocabulary#work-item) and retry it from where it stopped. Its own cap can exceed the chain's, up to `maxima.work_item`, so you need no config edit.

## Raise the cap and retry

You need a work item that a cap stopped. The board shows it under **Needs you**, and `kraft view show ID` names the limit it hit. `kraft view list` shows its ID.

In the interface:

1. Open the item. Its banner names the limit it hit.
2. Click **Raise cap**. On a phone, a dollar stop offers **Raise budget** instead.
3. Enter a higher value, or pick +$5, +$10 or no cap for a dollar cap, then click **Save & retry**. The editor shows the current value and the [policy](/concepts/vocabulary#policy)'s maximum, if there is one.

From the command line, for a dollar cap:

```bash
kraft item raise-budget ID --usd 25
```

```text
raised the cap on <id> to $25 and retried it; the item is now running
```

For a time or attempts cap:

```bash
kraft item set-policy ID --policy time_cap_minutes=240
kraft item retry ID
```

You know it worked when the item has left **Needs you** and sits under **Running**, and the header's **N NEED YOU** count is one lower. The command ends by saying the item is running: `kraft item retry ID` prints `retried <id>; the item is now running`. If it says the item is "stopped for a person", the item stopped again: `kraft view show ID` says why.

Not every stop offers a raise. [Cap stops and the raises they offer](/reference/web-ui/cap-stops-and-raises) says what each one offers, stop by stop. For what the caps are, and why a raise is bounded, see [Caps and budgets](/concepts/caps-and-budgets).

## A stop on unknown spend

A `budget_usd` stop on unknown spend is different: no higher cap passes it, since Kraft still cannot show the scope is under the new one. Clear the item-wide cap instead. This also retries the item:

```bash
kraft item raise-budget ID --usd none
```

`budget_usd=none` means no dollar cap for the work item, and none for each node, step or task the chain set no `budget_usd` on. It is item-wide only, and refused when `maxima.work_item.budget_usd` is set. A cap the chain set on a node, step or task still binds.

## If the stop has no raise

The daily cap, a `token_budget` and a node's `budget_usd` are not raised with **Raise cap** or `raise-budget`. The item says so and offers **Retry**.

- **`token_budget`:** `kraft item set-policy ID --policy token_budget=N`, then `kraft item retry ID`.
- **A node's `budget_usd`:** skip the node with `kraft item skip ID`, or raise the cap in the chain and file the item again.
- **`budget.daily_usd`:** raise it in `policy.yaml`, or wait for local midnight. Then run `kraft item retry ID`.

[Cap stops and the raises they offer](/reference/web-ui/cap-stops-and-raises) has the reasons and every refusal.
