---
title: The first run
description: The three setup steps the board shows when no repo is connected, from connecting a repo to filing a first work item.
---

The first time you open Kraft's web UI, a setup wizard takes the board's place. This page walks through its three steps and the warnings it can show.

With no repo connected, the board shows **Nothing on the board yet** and three
setup steps. The header's **+ New work item** is there too, so you can file
work without finishing them; filing one ends the setup.

1. **Connect a repo.** Type the path to a local git checkout and click
   **+ Add repo**, which probes it.
   - When the server was started inside a checkout that is not connected yet,
     a **Try** line under the field offers its path: click it to fill the
     field.
   - Before you add anything, the panel beside the step lists what Kraft will
     probe (`.gitmodules`, `.beads/`, the test command and the forge remote),
     each marked **after you add**.
   - Kraft then probes the repo and lists what it found: those, the setup
     command and more. Check them, then click **Add repo**, which replaces **+ Add repo** once the probe is done. It does what
     `kraft repo connect` does.
   - A repo with no commit yet cannot be added: the wizard says so beside
     **Add repo**. Commit its files, then click **Check again**.
   - **Skip to chain →** moves on to step 2 without a repo; the step is not
     marked done until one is added.
2. **Chain and policy.** Shows the chain every item uses unless it names
   another (`default`) and the policy's fix attempts and dollar cap. **Open
   Chains** takes you to the chain; **Continue** moves on.
3. **First work item.** **+ New work item** opens the composer described in
   [File a work item](/guides/day-to-day/file-a-work-item).
   This step also says what Claude workers need before you start an item:
   Kraft's MCP server, from the Kraft plugin or from `kraft admin init`, not
   both. **Copy commands** copies the plugin install commands. **Go to the
   board** leaves the wizard without filing anything.

The wizard first shows while no repo is connected. Once you add one, it stays
on the board until either of these happens:

- You leave its last step, with **+ New work item** or **Go to the board**.
- The first work item exists, wherever it was filed: an item filed from the CLI
  while the wizard is open ends it, and the board shows the item.

If you reload the page, or follow a link to another page and come back, it
opens at the step you were on. This browser remembers it.

A repo where Kraft found no test command is connected disabled. The wizard
says so (**No test command: connected disabled. In Settings › Repos, set its
test command and Enable it, then publish.**), and step 3 reminds you that
**New work item** cannot file to it yet: the composer and the new-item page
list only enabled repos. Before you file work on it, open **Settings ›
Repos**, select the repo, set its **test command**, click **Enable**, then
**Review & publish**.

A repo where Kraft found no setup command is connected without one, enabled or
not. The wizard says so too: **No setup command found: its first work item
stops before it starts until you set one, or tick No setup needed, in
Settings › Repos**.

An item on a repo with no setup command stops at once, before its first node runs, and its stop names the
missing `setup_command`.

In **Settings › Repos**, select the repo and set its **setup
command** (such as `npm ci` or `uv sync`), or tick **No setup needed** for a
repo with nothing to install. Then **Review & publish**.

When the tests are in subdirectories, the wizard names them: **No setup
command: web has tests and nothing found prepares it.** It lists each
directory that has tests and nothing to prepare them. Set a setup command that
covers them, in **Settings › Repos**.
