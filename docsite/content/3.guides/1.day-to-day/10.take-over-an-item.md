_Added in next_

When a [work item](/concepts/vocabulary#work-item) stops, you can work in its agent's session instead of steering from outside. `kraft item takeover` opens that session on your terminal, in the item's [worktree](/concepts/vocabulary#worktree), and carries on from the worker's conversation. Herdr, tmux, a plain terminal or VS Code's terminal are only where the command runs.

## Take over an item

You need an item that is `paused` or `needs_human`, with an agent task that has run, on a local worktree with no sandbox. `kraft view list` shows its ID.

```bash
kraft item takeover ID
```

```text
forking your session from s2
```

Claude Code opens in the item's worktree. You work in it as in any session, and permission prompts come to you. Kraft's permission policy doesn't apply: you are the policy. Exit the session as usual.

The item's status never changes while you work. A running item is refused: `kraft item pause ID` it first.

## Hand the item back

When you exit, Kraft frees the item and prints what to do next. It depends on how the item stopped.

| The item was | Next step |
|---|---|
| `paused` | `kraft item resume ID` runs the step again with your commits and continues your conversation. `kraft item skip ID` passes the step, if you finished it yourself. |
| `needs_human` | `kraft item skip ID` passes the step, if you finished it. `kraft item retry ID --steer "..."` runs it again with your commits. Your conversation won't carry over, because a retry always starts fresh, so put what matters in `--steer`. |

`resume` is the usual choice, because the step's tests and reviews still check what you did. An agent that resumes a session you worked in is told so: it treats your turns as steers and checks `git log` and `git status` before it does anything.

If you quit before sending a turn, nothing is kept, and a resume behaves as if you hadn't taken over. A `needs_human` item has no paused session to fork, so Kraft starts a fresh one and says so.

## Check your worktree

The exit printout warns when:

- the worktree has uncommitted changes;
- `HEAD` is no longer on the item's branch;
- the branch no longer descends from where it was when you started, because history was rewritten.

Each of these can fail the next run, so fix it before you resume.

## While you have the session

Every other verb that acts on the item answers `409`: `resume`, `retry`, `skip`, `complete`, `cancel`, `abandon`, `escalate`, `raise-budget`, `rerun-ci`, `unblock`, `set-chain`, `set-overrides`, `set-policy` and a gate's `approve` and `reject`. Auto-escalation and the start queue leave the item alone. Reading verbs and `pause` still work.

If your terminal was closed or killed, the next verb that finds the lock without its process frees it. To free it yourself:

```bash
kraft item takeover ID --release
```

## Limits

- **Cost:** the session's spend isn't recorded, so dollar caps don't see it.
- **Permissions:** Kraft's permission policy, `allowed_tools`, `deny_tools` and the approval channel, don't apply.
- **Configuration:** a repository's `env:` in `repos.yaml` isn't applied, and your session runs with your own environment and login. A `claude.yaml` you own that has no [`interactive:` block](/reference/harnesses/harness-files#interactive) refuses takeover until you add it.
- **Kraft's instructions:** the session has none of the worker's instructions. The next automated run passes them again.
- **Model:** your own default model is used. `/model` switches it.

## What is refused

| Item | Why |
|---|---|
| Sandboxed | A sandboxed session writes into a private store that Kraft syncs to the branch. Running it on your host would run the agent with your privileges over files the sandboxed agent wrote. |
| Run on a remote worker | Its worktree is on another machine. |
| On another harness than Claude Code | Only the shipped `claude` has an [`interactive:` block](/reference/harnesses/harness-files#interactive). |
| With nothing run on the step yet | There is no session to continue: resume the item instead. |
| With several agent tasks side by side in the step | Takeover needs to know which one. |
