To get a release, see [Upgrade Kraft](/guides/run/upgrade-kraft).

## Kraft 2.4: steps on other machines

<!-- not new: shipped in 2.4 -->

- **A step runs on a machine you register.** `runner:` on a step, or a
  group of machines, sends it to a machine from `workers.yaml` instead of
  the server. Its commits and files go there, its log and status come back
  while it runs, and a server restart reattaches it. Machines connect by
  dial-in token or ssh, cap how many steps they take, and can build an
  item's sandbox themselves. See
  [Run a step on another machine](/guides/run/run-a-step-on-another-machine).
- **Restarting Kraft no longer ends a running step.** A local worker runs
  every local step, so stopping, restarting or updating Kraft within a major
  version leaves worktree items running. See
  [Restart Kraft](/guides/run/restart-kraft#a-restart-leaves-local-steps-running).
- **Verification can run only the tests a change affects.** A test scope's
  `targeted_command` runs in place of its full `command` when a chain asks
  for it, and `carry` keeps a test-selection tool's state warm across
  worktrees. See
  [`targeted_command`](/reference/configuration/repos#targeted_command).

## Kraft 2.3: add-ons that build on add-ons, and updates when Kraft is free

<!-- not new: shipped in 2.3 -->

- **An add-on can build on another.** Name a parent and a version range in
  `requires.addons`, inherit its chains, components, steering, skills and
  profiles, and override, extend or remove what you inherit. Installing or
  updating one moves its parents with it, under one review. See
  [Add-ons](/reference/configuration/addons).
- **Update and restart when nothing is running.** Mark a release on the
  About page or with `kraft admin update --when-free`, turn on auto-update
  for minor and patch releases, and limit both to allowed hours. Both are off
  by default, and a failed unattended update goes back to the version you
  had. See
  [Update when Kraft is free](/guides/run/upgrade-kraft#update-when-kraft-is-free).

## Kraft 2.2: chains that extend a chain

<!-- not new: shipped in 2.2 -->

- **A chain can extend another** with `extends`, then `remove`, `add` and
  `overrides`, so a shared chain is customised without forking it. A repo's
  own `.kraft/` can extend an add-on's chain the same way, and the Templates
  screen edits an extending chain as changes to its parent. See
  [Extending a chain](/reference/configuration/library-and-chains#extending-a-chain).

## Kraft 2.1: add-ons, the console and in-place items

<!-- not new: shipped in 2.1 -->

- **Share chains as add-ons.** Chains, library components, skills and agent
  profiles travel as an add-on in a git collection. `kraft admin addon`
  installs, updates and removes them; each is pinned to a commit and reviewed
  before every update. A connected repo shares its own from `.kraft/` on its
  default branch. See
  [Share chains with add-ons](/guides/customize/share-chains-with-addons).
- **`kraft console`.** A terminal UI: the board, an item's document, history,
  log and diff, the server, repos and add-ons, and every `kraft` verb from its
  prompt. See [Console](/reference/console).
- **In-place items.** A repo, or one work item, can run in the repo's own
  checkout instead of a per-item worktree. Kraft never forces, sweeps or
  deletes anything there, and stops the item when the checkout needs you. See
  [Run items in your own checkout](/guides/run/run-items-in-place).
- **Waiting and queueing.** `kraft item create --after ID` makes an item wait
  for others, and a start made while every slot is busy queues instead of
  being refused.

## Kraft 2.0: a place to work, not just an engine

<!-- not new: shipped in 2.0 -->

Kraft 1.0 shipped the engine: [chains](/concepts/vocabulary#chain) that take
your coding agent from spec to merge request and stop only where a decision
is yours. 2.0 is built around those decisions.

- **A new interface, built around what needs you.** The board keeps 1.4's
  four groups and its one button per row, you can act on several items at once, and
  an item's page draws its chain as a graph. ⌘K (Ctrl+K) search and the phone
  layout match. The [demo](/demo/) runs it on sample data in your browser.
  See [Web UI](/reference/web-ui).
- **Review the way you would on a code host.** Each item has a **Review**
  page with the diff, the comment threads and the
  [gate](/concepts/vocabulary#gate) decision. Comment on a line or a range,
  suggest a change in place, and send a round at once with **Finish review**.
  See [Reviewing a change](/guides/day-to-day/review-a-change).
- **Shape the work from its page.** Read the spec and plan an item was filed
  with, set the model, effort and limits of the item and its nodes beside what its chain
  would use, change a running item's chain, and raise the
  [cap](/concepts/vocabulary#cap) that stopped it. Chains, the library,
  harnesses, repos and policy are edited as a draft you publish. See
  [Templates](/reference/web-ui/templates-and-settings#templates).
- **Repo connect reads more of the repo.** `kraft repo connect` proposes the
  setup and test commands from the repo's task runner, its toolchain's files
  and its CI, explains each choice, and rehearses them with `--verify`. See
  [How connect proposes commands](/reference/configuration/repos/connect-proposals).
- **Safer to share.** No other site can frame the board, an image from
  another site loads only when you click it, and off loopback Kraft answers a
  browser only at a name you listed. See
  [Remote access](/guides/run/remote-access).

2.0 is a major version because making the interface and the API consistent
changed some `--json` fields and exit codes, and the database moved to a
schema 1.4 can't open. Coming from 1.4, follow
[Upgrade from 1.4](/guides/run/upgrade-from-1-4): it lists what needs action
before the update and every change, and
[Changes from 1.4 to 2.0](/reference/changes-from-1-4) is the reference.
