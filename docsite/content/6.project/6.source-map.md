This page is for contributors. It lists what each part of `src/kraft/` holds, and
where to make each kind of change. For how those parts fit together, see
[Architecture](/project/architecture).

## Module map

Every path below is under `src/kraft/`.

### Serving

| Path | What it does |
|---|---|
| `cli/` | The `kraft` command: `item`, `view`, `repo` and `admin` verb groups, and starting the server. `cli/verify.py` is `kraft repo connect --verify`. |
| `client/` | The one HTTP client. `transport.py` is the wire, `actions.py` changes things, `reads.py` reads, `context.py` knows which item a worker stands in. |
| `mcp.py` | `kraft admin mcp`: the MCP tools, each a call into `client/`. |
| `api/__init__.py` | Builds the FastAPI app, installs middleware, serves the SPA. |
| `api/startup.py` | The lifespan: opens the database, reattaches sessions, starts the pollers. |
| `api/deps.py` | Helpers shared by routes, including `spawn`, which starts a [walk](/concepts/vocabulary#walk). |
| `api/perimeter.py` | Who may call the API at all. |
| `api/apidocs.py` | The `/docs` and `/redoc` pages, with their scripts pinned to one release and checked by hash. |
| `api/routes/` | One module per resource: `work_items`, `lifecycle`, `gates`, `review`, `board`, `artifacts`, `sessions`, `repos`, `settings`, `harnesses`, `search`, `auth`, `check`, `admin`, `drafts`. |
| `api/routes/lifecycle.py` | Pause, resume, retry, skip, abandon, complete, cancel, escalate. |
| `api/routes/sessions.py` | Logs, permission requests, the WebSocket. |
| `api/routes/admin.py` | Pending changes, restart, update. |
| `api/routes/drafts.py` | The Templates editor's unpublished edits. |
| `api/config_check.py` | Checks a config file the way saving it would. |
| `drafts/`, `apply.py` | Unpublished config and item-chain edits kept server-side, and what is saved but not yet running (reload and restart items). |
| `ws.py` | Fans committed events out to WebSocket clients. |
| `render.py` | Terminal formatting for the CLI. |

### Running a chain

| Path | What it does |
|---|---|
| `executor/entry.py` | Intake, attachments, and closing an item's issues in beads when it completes. |
| `executor/walk.py` | The walk: node by node, with recovery, the [fix loop](/concepts/vocabulary#fix-loop), escalation and every stop. |
| `executor/dispatch.py` | Runs a node's steps and tasks, measures the result, collects findings, and asks the fix-loop judge. |
| `executor/gates.py` | Opening gates, approval and rejection, agent gate review, and automatic escalation of [stuck](/concepts/vocabulary#stuck) stops. |
| `executor/stops.py` | Writes each kind of stop, and guards every claim so an `active` item always has a walk behind it. |
| `executor/resuming.py` | Resuming after a restart, and addressing a steer to paused tasks. |
| `executor/retry.py`, `store/forks.py`, `templates/forks.py` | A retry forks the run at a task, step or node path. |
| `executor/prompts.py` | The text Kraft adds to an agent's prompt: steers, failures, findings, review threads, progress. |
| `executor/context.py` | Walk results and the `Steer` object. |
| `executor/fallback.py` | Moving a rate-limited or unavailable agent task to its next `fallback:` entry. |
| `executor/read_only.py` | Checks that a `read_only` step changed nothing. |
| `builtins.py` | Work Kraft does itself: the [worktree](/concepts/vocabulary#worktree), setup, rebases, changed-test scopes. |
| `waits.py` | External waits and the scheduler that re-enters them. |
| `rate_limit_retry.py` | Re-enters a `rate_limited` item after its reset. |
| `mr_poller.py` | Notices a merge request closed on the [forge](/concepts/vocabulary#forge) without merging. |
| `caps.py`, `cap_levels.py` | Time caps per scope, and the poller that stops parked items. |
| `policy.py` | Loads `policy.yaml`: loops, caps, budget, concurrency, escalation settings. |
| `findings.py` | The finding schema reviewers report, and its identity across rounds. |
| `escalate.py` | [Escalation turns](/concepts/vocabulary#escalation-turn): the agent a stopped item hands to. |
| `auto_escalate_delay.py` | Fires a delayed automatic escalation. |
| `gate_review.py` | An agent reviewing a gate before a person sees it. |
| `review.py` | The one producer of "what changed" for the gate viewer and review agents. |
| `review_reply.py` | The agent that answers review threads. |
| `node_runs.py` | Pins the commit each node run started and ended on. |
| `progress.py` | Reads a plan's `## Task N` headings for "Task 3 of 6". |

Outside `src/kraft/`: the web UI is in `frontend/src/ng/` (a folder per area),
the shipped default configuration is in `config/`, the agent plugins are in
`plugins/`, the VS Code extension is in `vscode/`, and contributor scripts are
in `dev/`.

## Workspace members

A sandbox covers a [workspace](/concepts/vocabulary#workspace)'s members as it covers the root. A member is a
worktree of its connected repository (`_setup_submodules` in `builtins.py`), so
host git in it reads that repository's config, not a git directory under the
root's worktree. It also reads the member's own `config.worktree` when that
repository sets `extensions.worktreeConfig`.

| What a sandboxed container sees of a member | Enforced by |
|---|---|
| Its refs go through a [ref store](/concepts/vocabulary#ref-store) of its own. | `prepare_stores` in `worker/refstore.py` |
| Its `.git`, and the `commondir`, `gitdir` and `config.worktree` of its admin directory, are read-only. They are mounted from paths derived from the connected repository, never read from the member's `.git`. | `_gitdir_mounts` in `worker/backends/docker.py` |
| Each directory from the worktree down to the member is mounted onto itself, so no container can rename it and put another `.git` in the member's place. | `_pin_path` in `worker/backends/docker.py` |

Before host git runs in a member, Kraft checks it against the checkout Kraft
made:

- For a sandboxed item, `refuse_planted_repos` in `executor/stops.py` runs the
  check (`foreign_members` in `worker/sandbox.py`). A task's launch mounts
  exactly the checkout that check returned.
- Every other sandboxed launch takes its checkout from `sandbox_checkout`.
  These are a gate review, an [escalation turn](/concepts/vocabulary#escalation-turn), a review reply and the setup
  command. It runs the same check and leaves out any member that fails it, so
  the launch does not start.

## Where to change things

| To | Change |
|---|---|
| Add a CLI verb or MCP tool | A function in `client/actions.py` or `client/reads.py`, its verb in `cli/item.py` or `cli/view.py`, its tool in `mcp.py`, and the [CLI](/reference/cli) reference. |
| Add an API route | A handler on `api_router` in the matching `api/routes/*.py`. A new module is imported in `api/__init__.py`. |
| Add a harness | A YAML file in `harnesses/`. See [Add or override a harness](/guides/harnesses/adding-a-harness). |
| Add a builtin action | A member of `BuiltinAction` in `templates/models.py`, its branch in `executor/dispatch.py`, and the work in `builtins.py`. |
| Add a forge action or backend | `ForgeAction` in `templates/models.py` and `adapters/forge/run.py`; a backend beside `gh.py` and `glab.py`. |
| Change what a [Kraft plugin](/concepts/vocabulary#kraft-plugin) may carry | `LIMITS` and `problems` in `plugins/update.py`, the layout and limits in `plugins/manifest.py` and `plugins/fetch.py`, and [Plugins and collections](/reference/configuration/plugins). |
| Change a shipped chain or library component | `config/chains/*.yaml` and `config/library.yaml` at the repo root. Run `kraft admin templates lint`. |
| Change what an agent is told | The skill in `skills/<name>/SKILL.md`, or Kraft's own notes in `executor/prompts.py`. |
| Add a `policy.yaml` key | `PolicyInput` and `Policy` in `policy.py`, the default in `config/policy.yaml`, and [policy.yaml](/reference/configuration/policy). |
| Add a `repos.yaml` key | `RepoEntry` in `config.py`, and [repos.yaml](/reference/configuration/repos). |
| Change the database | A new numbered migration in `db.py`, and the queries in `store/`. |
| Change how a stop is handled | `executor/walk.py` and `executor/stops.py`. |
| Add a status transition | The write in `store/`, through `write_status` in `store/_common.py`, and the door in `api/routes/lifecycle.py`. |
| Add a `doctor` check | `doctor.py`. |
| Change a screen | Its area's folder under `frontend/src/ng/` (`board/`, `item/`, `review/`, `templates/`, `settings/` and so on). |
