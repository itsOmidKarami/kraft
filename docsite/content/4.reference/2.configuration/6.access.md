---
title: Access
description: "Every field in access.yaml: bind address, password, and remote access."
---

`access.yaml` sets the address Kraft binds to and the password that protects it.

```yaml
bind: 127.0.0.1
port: 8765
password_hash: null
session_expiry_days: 7
allowed_hosts: []
```

| Field | Default | Means |
|---|---|---|
| `bind` | `127.0.0.1` | The address `kraft admin start` binds. `--host` overrides `KRAFT_HOST`, which overrides this file. A non-loopback value is refused unless `password_hash` is set. |
| `port` | `8765` | The port `kraft admin start` binds. `--port` overrides `KRAFT_PORT`, which overrides this file. |
| `password_hash` | `null` | The login password's hash. Required for any non-loopback bind. On `127.0.0.1`, Settings → Access asks for it when you pick **Local network** and saves both together; `PUT /api/access` with `{"password": "..."}` also sets it. See [Set a password](/guides/remote-access#set-a-password). |
| `session_expiry_days` | `7` | How long a browser session cookie stays valid after logging in. |
| `allowed_hosts` | `[]` | `Host` header allowlist checked on a non-loopback bind — a password alone does not authorize an arbitrary hostname. A browser on the machine itself is always accepted at `127.0.0.1`, `localhost` or `[::1]`; list the names other devices use. Kraft keeps each entry as a bare name: it lowercases it and drops a scheme, a path, a port and a trailing dot, so `http://Kraft.Local:8765/` is kept as `kraft.local`. An IPv6 address is kept in brackets, as `[fd00::5]`, and a Unicode name in the punycode form a browser sends, as `xn--fa-hia.de` for `faß.de`. Wildcards such as `*.ts.net` are not supported: Settings → Access and `PUT /api/access` refuse a new one with a 422 that names it. One already in the file stays, and `kraft admin doctor` names it. See [Remote access](/guides/remote-access). |

A saved `bind` or `port` takes effect at the next start. Until then the header's apply chip reads **Restart needed**
(`GET /api/apply`), unless `KRAFT_HOST` or `KRAFT_PORT` is set, which wins over the file. A server a service manager
started can be restarted from there; one started from a terminal has to be restarted in that terminal.
