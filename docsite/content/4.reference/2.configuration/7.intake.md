---
title: Intake
description: "Every field in intake.yaml: autonomous pickup, and schedules."
---

`intake.yaml` controls what files work without anyone typing `kraft item create`: autonomous pickup from beads, and schedules.

Off by default. When enabled, Kraft polls [`bd ready`](https://github.com/gastownhall/beads),
the ready list of the optional [beads](/concepts/vocabulary#beads) issue tracker,
files each matching issue as a work item without anyone typing
`kraft item create`, and starts it. Unlike an item you file by hand, it does
not land paused. It goes through the same [intake](/concepts/vocabulary#intake)
checks, and no gate is skipped.

```yaml
enabled: false
interval_s: 300
repos: []              # empty means every enabled repo in repos.yaml
priority_ceiling: 2    # P0 and P1 are left for a person; P2 and higher numbers are picked up
schedules: []          # cron-fired work items; see below
```

| Field | Default | Means |
|---|---|---|
| `enabled` | `false` | Turns autonomous pickup on. |
| `interval_s` | `300` | Seconds between polls. |
| `repos` | `[]` | Repo paths to poll. Empty means every enabled repo in `repos.yaml`. |
| `priority_ceiling` | `2` | Issues with a priority number below this (P0, P1) are left for a person. P2 and higher numbers start unattended. |
| `schedules` | `[]` | Cron entries that file a paused work item each; the fields are in [Inbound triggers](/reference/triggers#schedules). |

How many items may run at once is not here: it is `max_concurrent` in
[`policy.yaml`](/reference/configuration/policy), whichever way they were
started. A pre-2.0 file naming `max_concurrent` here still loads; the key is
not honoured, and `kraft admin doctor` names the move.

An item that auto-intake files runs to its first gate and stops there for a
human, exactly as a typed-in one does. Kraft refuses to auto-start a chain that
has no gate at all. Auto-intake removes the typing, not the judgement. Editable here or from Settings › Auto-intake,
which applies a change without a restart.

A hand edit of `intake.yaml` is picked up by `kraft admin reload` (or **Reload** in the header's apply chip), which also replaces the poller.
