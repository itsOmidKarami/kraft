---
title: View verbs
description: "The kraft view verbs: read the board, follow a running item, and review its diff and documents."
---

`kraft view` reads work items without changing them. Wherever a command takes an ID, you can omit it inside that item's worktree. See the [CLI overview](/reference/cli) for output format and `--json`.

## Reading the board

```bash
kraft view list
kraft view list --all --status=paused
kraft view list --include-abandoned
kraft view show
kraft view search "retry policy"
kraft view search "retry policy" --limit 50
```

| Command | Effect |
|---|---|
| `view list` | The board, scoped to the repo you are in. `--all` spans every repo. `--repo PATH` picks one. `--status` filters to `active`, `needs_human`, `paused`, `waiting`, `rate_limited`, `completed` or `abandoned`. `--include-abandoned` adds abandoned items, cancelled ones included. |
| `view show` | The work item whose worktree you are in. |
| `view search` | Search the document index. `--limit` caps the result count (default 20). |

`kraft view show` reports what the item has spent: uncached input, cache
writes, cache reads and output tokens, then cost. A session recorded before
cache tokens were split out has a single input figure, counted under `in`, and
the line says `(cache not split on older sessions)`. A `token_budget` counts
all four kinds.

On a stopped item, `stop_reason` says why, and `suggested_action` names the one
command the chain proposes. A stop on a dollar cap the item can raise (its own,
or its policy's item-wide `budget_usd`) adds a `next` line naming
`kraft item raise-budget ID --usd N`, the command behind the board's **Raise cap**.

## Following a running item

```bash
kraft view logs -f
kraft view logs --session <id> -n 0
kraft view events
kraft view events -f
kraft view events --type permission_decision
kraft view watch
```

| Command | Effect |
|---|---|
| `view logs` | The current session's log. `-f` follows until the session stops. `-n N` sets the backlog lines shown first (default 50). `--session` picks a session. |
| `view events` | Node transitions, gate decisions and escalations. `--after N` shows only later events. `--type T` filters by type; see [Events](/reference/events) for every type. `-f`/`--follow` streams until the item completes or is abandoned; with `--json`, every event is one line of NDJSON. |
| `view watch` | A live board, redrawn on every event. Needs a terminal. `--repo PATH` picks the repo. |

`-n 0 -f` prints only lines written after it starts.

## Reviewing before you approve

```bash
kraft view diff --stat
kraft view diff --name-only
kraft view diff
kraft view diff --no-pager
kraft view docs
kraft view docs <id> --attachment spec
kraft view doc <id> --open
kraft view artifact <id>
```

| Command | Effect |
|---|---|
| `view diff` | The colored diff, through `$PAGER`. `--no-pager` prints straight to the terminal. |
| `view diff --stat` | Size of the change. |
| `view diff --name-only` | Changed and untracked paths. |
| `view diff -w` | `--ignore-whitespace`: leaves out files whose only change is whitespace. |
| `view docs` | Specs, plans and summaries linked to the item, the spec or plan it was filed with (`--spec`, `--plan`) included. One the index does not hold yet is listed as `attachment:<id>:spec` (or `:plan`), read from the item's worktree, or before the item starts from the copy Kraft stored at filing; `kraft view doc` takes that id. `--json` prints the same list. |
| `view docs --attachment spec\|plan` | The spec or plan the item was filed with, as Kraft stored it at filing, which is what its worktree gets: the one reader before the item starts. `--json` prints its `path`, `title` and `content`. `--no-pager` prints straight to the terminal. |
| `view doc ID` | One document. `--open [EDITOR]` opens it in an editor on the server's machine; an `attachment:` id opens only once the item has started and has a worktree (before that, a 409 names `view docs --attachment`). `--no-pager` prints straight to the terminal. |
| `view artifact` | The document the pending gate is about. `--no-pager` prints straight to the terminal. |

Once an item has commits, `view diff` and `view diff --stat` show two blocks.
**The change under review** is every commit on the item's branch since its
base, the spec and plan documents included. **Uncommitted** is what an agent
left in the worktree without committing; Kraft commits after every task, so it
is usually empty and reads "(nothing uncommitted)". An item with no commits
yet shows one block.

A truncated diff always says so on its last line. Files the agent wrote
without `git add` are listed separately, because a unified diff does not show
them.

## Reviewing threads and comparing attempts

```bash
kraft view threads
kraft view threads --open
kraft view compare --from base --to latest
kraft view compare --from attempt:1 --to attempt:2 --stat
kraft view compare --nodes implementation,verify --name-only
```

| Command | Effect |
|---|---|
| `view threads` | Review threads on the item, drafts marked. `--open` drops resolved ones. Each line range carries its side as the diff marks it: `calc.py:+8` is new line 8, `calc.py:-3 to -4` old lines 3 to 4, and `calc.py:-2 to +2` a removed line through its replacement. |
| `view compare` | Diffs two review targets: `base`, `attempt:N`, `last_review`, or `latest` (the working tree; `attempt:N` needs a pending gate). `--nodes` limits it to files those node ids touched. `--stat`/`--name-only`/`-w` mirror `view diff`. With `--json` each file also carries `viewed`. |

See [Reviewing a change](/guides/review-a-change) for how threads, comments and
outcomes fit together.
