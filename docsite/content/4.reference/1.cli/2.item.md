---
title: Item verbs
description: "The kraft item verbs: file, approve, reject, pause, resume, retry, skip, escalate, and set policy."
---

`kraft item` acts on a work item. Wherever a command takes an ID, you can omit it inside that item's worktree. See the [CLI overview](/reference/cli) for output format and `--json`.

## Approve, reject, pause, resume, retry

```bash
kraft item approve
kraft item reject --note "the plan skips migrations"
kraft item pause
kraft item resume --steer "try the other adapter"
kraft item retry
```

| Command | Effect |
|---|---|
| `item approve` | Approves the pending gate. `--gate` names a gate when more than one could apply. `--digest` pins the approval to a chain revision, as `kraft view artifact` printed it. |
| `item reject` | Rejects the pending gate. `--note` records why. `--node N` re-enters the chain at node N instead of the gate's default. |
| `item pause`, `item resume` | Pause stops the whole work item. `resume --steer` gives the paused agent a message. |
| `item retry` | Re-runs the node a stopped item stopped on. It is the only way back onto a stopped item. |

## Filing a work item

```bash
kraft item create "fix the flaky test" --description "..."
kraft item create "fix it now" --autostart
kraft item create "ship the thing" --spec .engineering/specs/x.md
kraft item create "backport the fix" --base-branch release/1.2
kraft item create "fix the parser" --repo ~/code/app --chain quick-task --auto-gate
kraft item create "small fix" --skip-nodes spec,plan --budget 5
kraft item create "tuned fix" --node-override implementation.attempts=2
```

| Flag | Effect |
|---|---|
| (none) | Files the item paused. A person starts it. |
| `--autostart` | Starts the item at once. A Kraft worker session is refused. |
| `--spec`, `--plan` | Attaches a document and skips the node that would write it. |
| `--base-branch` | Starts from, and merges into, that branch. |
| `--repo`, `--chain` | Targets another connected repo or chain. |
| `--implements ID` | Closes the named issue in your optional issue tracker when the item completes. |
| `--auto-gate` | Has an agent review each gate and auto-escalate before a human is asked. |
| `--skip-nodes` | Skips the named nodes. |
| `--budget USD` | Sets the item's dollar cap. `--budget none` lifts it. |
| `--node-override N.FIELD=VALUE` | Overrides one field on node N. |
| `--policy KEY=VALUE` | Gives the item its own [policy override](#a-work-items-own-policy). Repeatable. |

`--repo` must name a repo you have already connected with `kraft repo connect`.
Kraft refuses any other path and names that command.

## Addressing work by path

Retry, skip and resume address chain work by its path: `node`, `node.step` or
`node.step.task`. A `tasks:` node's one step is `main`, so the path to its
`implement` task is `implementation.main.implement`. `kraft view show --json`
lists every path.

```bash
kraft item retry --path verification.review
kraft item retry --path verification.review.code_review
kraft item retry --path spec
kraft item retry --restart
kraft item resume --steer "keep the old API" --steer-task verification.review.code_review="check the auth module first"
kraft item skip --path verification.review.code_review
```

| Command | Effect |
|---|---|
| `retry --path node.step` | Re-runs that step and everything after it. |
| `retry --path node.step.task` | Re-runs that task. Its finished siblings stand. |
| `retry --path node` | Re-runs a node that already completed, and everything after it. |
| `retry --restart` | Re-runs the whole chain from its first node. |
| `resume --steer` | Sends a message to every paused agent task. |
| `resume --steer-task PATH=TEXT` | Sends a message to one paused agent task. |
| `skip --path` | Skips only that task. Its siblings keep running. |

A retry keeps everything the earlier run did and runs on a new run fork. It
reopens every gate it has to rerun. A gate before the retried work keeps its
decision.

A paused agent task resumes its own session when its harness supports it, and
is told the steer. Otherwise it restarts with its brief and the steer. You see
a refusal when you:

- steer an item that is still running (pause it first);
- steer an item whose pause stopped no agent task, such as a test run or a CI
  wait;
- name a `--steer-task` that is not a paused agent task.

## Less common item verbs

```bash
kraft item skip --note "already fixed upstream"
kraft item escalate --message "the fix loop keeps missing the same edge case"
kraft item escalate --message "..." --new-thread
kraft item set-chain --template quick-task
kraft item set-attachments --spec specs/x.md
kraft item set-attachments --drop spec
kraft item set-overrides --model opus --effort high
kraft item set-overrides --clear
kraft item mr-label --id <id> release::patch
kraft item abandon --yes
kraft item complete --reason "shipped by hand"
kraft item cancel --reason "superseded by #412"
```

| Command | Effect |
|---|---|
| `skip` | Advances past the current node or gate without running it. |
| `progress N` | `kraft item progress N` is called by a worker session to report it started plan task N. You do not run it by hand. |
| `escalate` | The manual counterpart of the board's auto-escalation. Asks an agent to help resolve a `needs_human` stop. `--new-thread` starts a fresh agent session instead of continuing the latest thread. |
| `set-chain` | Switches a not-yet-started item's chain. |
| `set-attachments` | Revises a not-yet-started item's spec or plan. `--drop KIND` removes it and restores its gate. |
| `set-overrides` | Sets the item-wide model and effort. `--clear` returns to the template's own binding. |
| `mr-label` | Relabels the merge request. This re-creates its pipeline. |
| `abandon` | Drops the item and reclaims its worktree. It destroys uncommitted work, so `--yes` is required. |
| `complete` | Ends the item as completed. Requires `--reason`. Add `--close-beads` to close its linked issues. |
| `cancel` | Ends the item as cancelled. Requires `--reason`. The worktree stays. |

`complete` and `cancel` stop whatever is running and record the reason on the
item's timeline.

### One node's agent tasks

`kraft item set-node-override --node N` changes one node of one item until
that node starts. After that, Kraft refuses the change.

```bash
kraft item set-node-override --node verify --auto-escalate-stuck
kraft item set-node-override --node implementation --model opus --effort high
kraft item set-node-override --node implementation --extra-prompt "Keep the migration backwards compatible."
```

Besides the auto-escalate settings, `attempts` and `wall_clock_s`, it accepts:

- `--model`, `--effort`: what every agent task in the node launches with. From
  highest precedence to lowest: this node override, the item-wide
  `set-overrides`, the task's own `model:` and `effort:` in the library, the
  repo's `models:` (model only), then the harness profile's `defaults:`. A
  value the node's harness does not accept is refused when you set it, not at
  launch. A gate's `auto_review` uses the item-wide values only.
- `--extra-prompt TEXT`: appended to the instruction of every agent task the
  node runs, after the task's own prompt and brief. It never replaces them. It
  does not reach a gate's `auto_review` or the interactive escalation turn.
  At intake, `N.extra_prompt=...` is taken as written, not read as YAML.

The override is stored on the item. It does not edit the chain.

### A work item's own policy

`kraft item create --policy KEY=VALUE` (repeatable) and `kraft item
set-policy` give one work item its own policy override, without touching its
chain or any other item. `FIELD=VALUE` applies item-wide. `PATH.FIELD=VALUE`
applies to one node, step or task and everything under it. Values are read as
YAML, so `deny_tools=[WebFetch]` is a list.

```bash
kraft item create "quick fix" --policy time_cap_minutes=45 --policy merge_request_feedback.ci.await_ci.total_time_cap_minutes=60 --policy verification.max_attempts=4
kraft item set-policy --policy merge_request_feedback.ci.await_ci.total_time_cap_minutes=60
kraft item set-policy <id> --policy max_attempts=2
kraft item set-policy --clear
```

`set-policy` replaces the whole override. The fields are those described in
[Configuration](/reference/configuration/policy):

| Fields | Behaviour |
|---|---|
| `timeout_minutes`, `max_attempts`, `allowed_harnesses` | Move within the administrator `maxima` and win over what the chain set. `max_attempts` applies to execution nodes only. |
| `allowed_tools`, `deny_tools`, `sandbox` | Only tighten. A list intersects with what each task already allows. |
| `time_cap_minutes`, `total_time_cap_minutes`, `token_budget`, `budget_usd` | Item-wide caps. Raise one above the chain's, up to `maxima.work_item`, to unstick a capped item before a retry. |

On a path, you can pass that level's default up to its level's maximum. Kraft
refuses a value above what the chain or the item already gives that scope,
naming both. A wait task's total cap is its timeout.

`wait_timeout_minutes` is retired. Kraft refuses it and names
`total_time_cap_minutes`. Kraft also refuses a value past its maximum, a path
the chain does not have, and a key that is not a policy field, naming the
field.

`set-policy` works on any item that has not ended. On a running or waiting
item it takes effect from the next node the item enters and from the next
check of a wait it is parked on. The new timeout counts from when the wait
started.
