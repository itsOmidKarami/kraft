title: Drafts
description: The routes the Templates and Settings editors use to keep, change, publish and discard drafts, and the `result` they answer.
---

The board's routes for the drafts behind the Templates and Settings editors, and the `result` every one answers. The [ops](/reference/http-api/draft-ops) a draft takes are on their own page.

The Templates editor keeps unpublished edits on the server, as drafts. There
is one draft per area and key: area `chains` with a chain id as the key (the
file `chains/<id>.yaml`), or area `library` with the key `library` (the file
`library.yaml`). File names are relative to the config directory.

An op
can join more files to a draft: `move_to_library` adds `library.yaml` to a
chain's, and renaming a library component adds each chain file it rewrites to
the library's. Each joined file records its own base, and a publish writes
them all. These are board routes, so they can change in any release.

The settings files have drafts too. The key is the area's own name, and a PUT
to a file outside the area's set answers `422`:

| Area and key | Files | Applied by a publish |
|---|---|---|
| `harnesses` | `harnesses.yaml`, `policy.yaml` | Reloads the policy only when `policy.yaml` is in the draft. |
| `repos` | `repos.yaml` | Nothing; `repos.yaml` is read when needed. |
| `policy` | `policy.yaml` | Reloads the policy, as `PUT /api/policy` does. |
| `intake` | `intake.yaml`, `policy.yaml` | Rereads `intake.yaml` and restarts the poller; reloads the policy when `policy.yaml` is in the draft. |

A settings draft's `problems` are every problem its files have, the same checks
the matching `PUT` route runs, so a draft with none is one that route would
accept. Two drafts may hold `policy.yaml`: the first publish wins and the
second answers `409`, which `rebase` resolves. A publish whose apply step fails
has already written its files: it answers `500`, keeps the draft, and tries
again on the next publish.

| Route | Answers |
|---|---|
| `GET /api/drafts` | Every open draft: `area`, `key`, `files` (names), `changes` and `problems` (counts as of its last write), `updated_at`. |
| `GET /api/drafts/{area}/{key}` | `{area, key, draft, files, base, published, updated_at, result}`. See [`GET /api/drafts/{area}/{key}`](#get-apidraftsareakey). |
| `PUT /api/drafts/{area}/{key}/files/{file}` | Body `{text}`. Stores the text as typed, comments kept, and answers as [`GET /api/drafts/{area}/{key}`](#get-apidraftsareakey) does. The first write makes the draft. A write whose files parse to the published ones drops it. |
| `POST /api/drafts/{area}/{key}/ops` | Body `{ops: [{op, ...}]}`. Applies the [ops](/reference/http-api/draft-ops#draft-ops) in order and answers as [`GET /api/drafts/{area}/{key}`](#get-apidraftsareakey) does, plus `ops: [{op, result?}]`, each op's own answer. All or nothing, and one request for undo. `?preview=1` answers the same without saving. |
| `POST /api/drafts/{area}/{key}/undo` | Undoes the last request and answers as [`GET /api/drafts/{area}/{key}`](#get-apidraftsareakey) does. PUTs to one file less than 4 seconds apart count as one request. `409` when there is nothing to undo. |
| `POST /api/drafts/{area}/{key}/publish` | No body. Writes each file, applies them (the templates are reloaded; a settings area applies as above) and drops the draft. See [`POST /api/drafts/{area}/{key}/publish`](#post-apidraftsareakeypublish). |
| `POST /api/drafts/{area}/{key}/rebase` | No body. Takes the published files as the draft's new base and keeps its text, so the next publish no longer answers `409`: the way out of a conflict when the draft should win. See [`POST /api/drafts/{area}/{key}/rebase`](#post-apidraftsareakeyrebase). |
| `GET /api/drafts/{area}/{key}/fragment?path=` | `{path, text}`: the YAML of the component at `path` (a task, a node, a policy block), from the draft when there is one, else from the published file. See [`GET /api/drafts/{area}/{key}/fragment?path=`](#get-apidraftsareakeyfragmentpath). |
| `GET /api/drafts/policy/{key}/preview?chain=` | A published chain's caps under the `policy` draft: `{chain, scopes: [{path, kind, level, caps}]}`. See [`GET /api/drafts/policy/{key}/preview?chain=`](#get-apidraftspolicykeypreviewchain). |
| `DELETE /api/drafts/{area}/{key}` | Discards the draft for good: `204`, or `404` with no draft. |

An unknown area answers `404`, a key the area does not accept (a chain key
that is not a valid chain id) `400`, and a file that is not one of the key's
files `422`. A draft also takes a `PUT` of any file an op joined to it,
such as the new file of a chain the `rename` op moved, which keeps its old key.

`result` is the same on every route:

| Field | Holds |
|---|---|
| `model` | Per file, the mapping it parses to. For a file that does not parse, the newest earlier state that did, else the published file. |
| `resolved` | The chain with `extends` expanded, as `GET /api/templates/chains/{id}/resolved` shows it, or `null` when it does not resolve. |
| `problems` | `[{path, field, message, file, line, col}]`: everything a save would refuse, with every schema error listed. See [`result.problems`](#resultproblems). |
| `sources` | For a chain that resolves, `{path: {field: {value, source}}}` for each node, step, task and fix loop: its own fields, and each `policy.*` cap of its scope. See [`result.sources`](#resultsources). |
| `changes` | `[{path, kind, summary, fields?}]` against the published chain, `kind` being `add`, `change`, `remove` or `rename`. See [`result.changes`](#resultchanges). |
| `impact` | For a chain: `{running, repos}`, the items still running it and the repos whose default it is. For the library: `{chains, repos}`, the chains any change reaches and the repos whose `steering:` names a changed profile. |
| `warnings` | `[{file, message}]` for a file an edit rewrote whole, whose published text has comments a publish would drop. |
| `policy_values` | `{auto_escalate_delay_s, auto_review_attempts}`, the instance's values from `policy.yaml`. |
| `choices` | The closed sets the editors offer, by field: `ref` (a builtin task's actions), `target` (a forge task's targets), `inputs` (what an agent task can ask for) and `grants`. See [`result.choices`](#resultchoices). |
| `yaml_error` | Only when a file does not parse: `{file, line, col, message}`. |

A publish checks each file against the one on disk when the file joined the
draft. If any changed since, for example through a save on the Settings
screens, it answers `409` and writes nothing:

```json
{"detail": "published since this draft began: chains/default.yaml",
 "files": {"chains/default.yaml": {"published": "…", "draft": "…", "diff": "--- published/chains/default.yaml\n+++ draft/chains/default.yaml\n…"}}}
```

A draft with a `yaml_error` or any problem answers `422`
`{detail, problems}` and writes nothing either.

## `result.problems`

- `path` is the component's canonical path (`implementation.main.implement`), `field` the key below it.
- On the library, `problems` is everything `PUT /api/templates/library` would refuse, checked against every chain and repo, each problem adding `chain` or `repo` (the one it breaks, or both `null` for one in `library.yaml` itself, whose `path` is the component, `tasks.implementer`) and `component`, the library component it comes from, or `null`.
- A repo's problem is at `path` `steering` in `repos.yaml`.

## `result.sources`

`source` is:

- `chain` (the file sets it at that path);
- `library:<section>.<name>` (the nearest library component it inherits it from, such as `library:tasks.implementer` or `library:nodes.verification`);
- `policy` (a cap no layer sets, at the value the scope runs under); or
- `default`.

A subprocess, builtin or forge task leaves out `steering` and the agent-only caps unless it sets them; with an `on_failure` recovery it lists those caps with `recovery: true`, since the recovery runs under them.

## `result.changes`

- A reordered component is a `change` whose summary says `moved`.
- A chain-level key that differs (`description`, `policy`) is one `change` row at the chain's own path, `""`, its summary naming the keys.
- A chain the `rename` op moved to a new id is one `rename` row at `""`, with `from` and `to` the old and new ids.
- On the `policy` and `intake` areas each row is one dotted key of a file, `{path, kind, summary, file}`, `summary` reading "was → now" (`not set`, or `no bound` for a maximum); a list of mappings (`schedules:`) is keyed by index (`schedules.0.cron`).
- On the library, `path` is a component path (`tasks.implementer`, `nodes.verification.review.code_review`) and each change adds `reaches`, the ids of the chains that use the component, as published or as drafted.

## `result.choices`

Each of `ref`, `target`, `inputs` and `grants` is a list of `{value, summary}`, and a `target` also has `waits`, true for one that runs as an external wait.

## `GET /api/drafts/{area}/{key}`

- `published` holds the text of each file as it is on disk (`null` for one that does not exist yet): the left side of a diff.
- With no draft, `draft` is `false` and `files` are the published ones.
- A chain with neither a file nor a draft answers `404`.

## `POST /api/drafts/{area}/{key}/publish`

Answers `{published: [files], changes, result}`: `changes` is what was published, as the draft's `result.changes` listed it, and `result` the state after, with no draft left.

## `POST /api/drafts/{area}/{key}/rebase`

Pushes no undo entry. Answers as [`GET /api/drafts/{area}/{key}`](#get-apidraftsareakey) does, or `404` with no draft.

## `GET /api/drafts/{area}/{key}/fragment?path=`

- `400` with no `path`, `404` when nothing is there.
- The text is what `set_fragment` takes back.
- On a `repos` draft `path` is a repo's path and the answer is read-only (there is no `set_fragment` for it); the other settings areas have no fragments and answer `404`.

## `GET /api/drafts/policy/{key}/preview?chain=`

- `kind` is `chain`, `node`, `step` or `task` (a gate waits for a person and has none).
- Each cap (`time_cap_minutes`, `total_time_cap_minutes`, `token_budget`, `budget_usd`) is `{value, source, maximum, exceeds}`: `source` is `chain`, `library:<section>.<name>`, `policy` or `default`, `maximum` the `{value, level}` bounding it at its level (`null`: no bound) and `exceeds` whether `value` is past it.
- A read; the draft is unchanged.
- `404` for a chain not in the library, `422` for a draft that does not load.
