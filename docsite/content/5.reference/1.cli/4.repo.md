---
title: Repo verbs
description: "The kraft repo verbs: list, connect, and disconnect repositories, and reach their worktrees."
---

`kraft repo` manages the repositories Kraft works in and their worktrees.

```bash
kraft repo list
kraft repo connect
kraft repo connect --verify
kraft repo connect --test-command "make check" --setup-command "./configure"
kraft repo disconnect
cd "$(kraft repo path <id>)"
kraft repo path --shell
kraft repo open <id>
kraft repo open <id> --editor cursor
```

| Command | Effect |
|---|---|
| `repo list` | The connected repos. `*` marks the one you are in. `--all` also lists auto-connected repos nobody has touched yet. |
| `repo connect [PATH]` | Connects a repo (safe to repeat). See [Connect a repo](#connect-a-repo). |
| `repo disconnect [PATH]` | Forgets the repo. Refused (exit 1) while it has an item that has not ended. See [Disconnect a repo](#disconnect-a-repo). |
| `repo path [ID]` | Prints the item's worktree path. `repo cd` is an alias. `--shell` prints a shell function that does the `cd` for you. |
| `repo open [ID]` | Opens the worktree in an editor. `--editor` picks `code`, `cursor`, `zed`, `obsidian` or `system` (the OS opener). With none named, it is the **Default editor** in Settings, else `KRAFT_EDITOR`, else the OS opener. |

## Connect a repo

A relative `PATH`, `.` included, is read from where you stand. `repo connect` proposes a setup command and a test command from the repo's task runner, CI and lockfiles ([Detectors](/reference/configuration/repos/detectors)), prints each with the file it came from, lists what else it found, and says when it found none. In a terminal it asks which candidate to use.

A repo with no commit yet is refused: commit its files first.

| Flag | What it does |
|---|---|
| `-y` | Takes the proposal. |
| `--test-command CMD`, `--setup-command CMD` | Replace the proposal (`""` for none). |
| `--no-tests` | Declares a repo with no tests, and saves it enabled: its work items pass verification without running a test. It cannot be combined with `--test-command`. |
| `--verify` | Runs the setup and test commands once, after connecting, in a throwaway worktree of the commit a work item starts from. It exits 1 if any fails, runs past `--timeout` minutes, or leaves files a work item would commit. |
| `--timeout MIN` | The minutes `--verify` allows. Default 30. |
| `--on-host` | `--verify` refuses a sandboxed repo unless `--on-host`. |
| `--json` | With `--verify`, its lines are in the answer's `verify.output`. |

### Connecting a repo that is already connected

On a repo already connected, connect probes again for what its entry leaves undecided (a test command where it has none and no test scopes, a setup command where none is declared), says what it found, and saves only that, after a yes in a terminal. A repo saved disabled for want of a test command is enabled once it has one.

Anything already decided stays as it is: change it in `repos.yaml`. `--verify` rehearses what it then declares.

## Disconnect a repo

Refused (exit 1) while the repo has an item that has not ended, paused and never-started ones included: complete, cancel or abandon them first (`kraft item complete`, `cancel`, or `abandon --yes`). Ended items are untouched, and no file in the repo is.

## Repo settings

For each repo's settings (`setup_command`, `env`, `test_scopes` and the rest),
see [Configuration](/reference/configuration/repos). Past connecting, you
edit them in Settings › Repos or in `repos.yaml`, not with the CLI.
