---
title: Console
description: The terminal UI that kraft console opens, for checking in on Kraft from a terminal, a tmux pane or over SSH.
---

_Added in next_

It runs on the machine the server runs on, and shows the statuses, words and
colours of the [web UI](/reference/web-ui). The [CLI](/reference/cli) stays as
it is: the console is a third way in, not a replacement.

## Open it

Run `kraft console` in a terminal. It refuses, with one sentence, when:

- stdin or stdout is not a terminal, such as in a pipe: it needs one to draw in;
- it runs inside a Kraft worker, where `KRAFT_WORK_ITEM_ID` is set;
- the server on Kraft's port is another instance, with a different run directory.

With no server answering, it opens anyway and says so on every screen.

## The top line

Every screen keeps the top line.

| Part | What it shows |
|---|---|
| `● live` | The console is following the server's events. A muted `● reconnecting` means it is not: what is on screen stays until it reconnects. |
| **Board** | How many items need you (the **Needs you** group), in the repo the console was opened in, or in every repo after `s`. |
| **Server** | The server's health word: `ok` or `degraded`, or `down` with no answer. |
| **Add-ons** | How many add-on updates wait for you. |
| **Repos** | The connected repos. |
| The right end | The repo the console was opened in (`all repos` outside a connected one), the version, and `update available` when a newer release is out. |

## Keys

The footer lists the keys of the screen you are on.

| Key | What it does |
|---|---|
| `1` to `4` | Board, Server, Add-ons, Repos. |
| `?` | Every key of the current screen. Press it again to close. |
| `/` | The prompt, with the `/` typed. |
| Ctrl+O | The output panel. |
| Esc | Back: from an item to the screen you opened it from. |
| `q` | Back like Esc, or quit from Board, Server, Add-ons or Repos. |
| Ctrl+P | The command palette: a screen, an item by id or title (opens it), or a verb, typed at the prompt. **Dark** and **Light** switch the look. |
| Ctrl+Q | Quit. |

## The Board

The Board lists every item in the web UI's groups and order: **Needs you**,
**Running**, **Not started** and **Done**. Done is folded to its count.
Archived items are not shown.

Each item is one line: a bar in its state's colour, the first 8 characters of
its id, its title, what it is doing or waiting for in the web UI's words, its
chain when that is not `default`, and how long ago it last changed. With every
repo shown, the repo's name joins the chain. A title too long for its column
ends in `…`. In a window under 80 columns the chain, repo and age columns
drop.

A live update redraws the list without moving your place in it. If the item
under the cursor goes (archived, say), the cursor moves to its neighbour.

The Board starts on the repo the console was opened in, as `kraft view list`
does, or on every repo when it was opened outside a connected one.

| Key | What it does |
|---|---|
| `j`, `k`, ↓, ↑ | Move between items; they stop on each group's heading too. |
| Home, End, PageUp, PageDown | Jump to the first or last line, or a page up or down. |
| Enter | On Done's heading, opens or folds Done. On an item, opens it ([The Item](#the-item)). |
| `a` | Opens the item's Overview, where `a` approves its gate once you have read the document. |
| `r` | Rejects the gate the item waits on, with a note saying what is wrong. The note is required. |
| `p` | Pauses a running item, or resumes a paused one with an optional steer. On an agent's question, asks for your answer and resumes with it. |
| `t` | Retries a stopped item, with an optional steer. |
| `v` | Opens or closes the peek. |
| `s` | Every repo, or only the one the console was opened in. The top line says which. It appears only inside a connected repo. |
| `f` | Filters by title or id as you type. Enter keeps the filter; Esc clears it. |

With nothing filed, the Board says so. When nothing needs you, it says that
instead, under **Needs you**. A filter that matches nothing says "nothing here
for this filter".

`a`, `r`, `p` and `t` are in the footer only while the server allows them for the
selected item. Esc in their dialog sends nothing. Afterwards a toast says what
the server did, in the CLI's words: a resume that found no free slot says the
item is queued, not resumed. A refusal shows in the server's own words, and the
Board and the peek read again.

## The peek

The peek follows the selected item in the bottom third of the Board. It starts
closed in a window under 30 rows; `v` opens and closes it at any size. It
reads the item once the cursor stops, not for every row passed.

| Selected | The peek shows |
|---|---|
| An item at a gate | The chain around the gate, the gate, and the start of the document it decides. When approving waits on open must-fix threads, it says how many. |
| An agent's question | The question. `p` answers it. |
| A failed or stopped item | The reason, and `t` when a retry is open. |
| A paused item | Where it paused, and how long ago. |
| A blocked or queued item | The unfinished items it comes after. |
| A running item | Its newest session's log as the agent writes it, then `session ended`. |
| A done or cancelled item | The outcome, and the merge request when there is one. |
| A group heading, or nothing | The end of `server.log`, followed as the server writes it. |

## The Item

Enter on an item, `a`, or an item chosen with Ctrl+P opens it. Esc goes back.

The top two lines name the item, its repo and chain, and its status in the web
UI's words, with what it has spent and when it last changed. A stopped item has
a banner under them: the server's reason and, where the web UI gives one, the
way on. Then its chain, with the node it stands on in the accent colour.

`[` and `]` step through its four tabs, round the end. `j`, `k`, PageUp,
PageDown, Home and End scroll the one shown.

| Tab | What it shows |
|---|---|
| **Overview** | The document the pending gate decides, whole; a document the server cut says so at its end. Without a gate, where the item stands. Then every node of the chain. |
| **Activity** | The item's events, newest first, in the web UI's words, without the bookkeeping ones. New ones appear as they happen; End at the bottom reads earlier ones. |
| **Log** | The newest session's log, followed as the agent writes it, then `session ended`. Leaving the tab stops following. `s` steps to the next older session, round to the newest, when there is more than one. |
| **Diff** | What has landed on the branch, then uncommitted work, then untracked files and a cut diff's warning, as `kraft view diff` says them. It reads again when the item changes. A worktree that is gone shows the server's own words. |

| Key | What it does |
|---|---|
| `a` | Approves the gate, for the document the Overview shows; from another tab, shows the Overview first. Offered once the document is read. While open must-fix threads keep approve shut, the Overview says how many. |
| `r` | Rejects the gate with a required note. Where the gate has a fix target before it, the node the work goes back to starts there, and Shift+Tab reaches it to pick another node before the gate. |
| `p`, `t` | As on the Board. |
| `s` | On the Log, with more than one session: the next older one. |
| `m` | The menu of what else the server allows now: skip, unblock, raise budget, escalate, complete, cancel, archive. |

| Menu entry | What it asks |
|---|---|
| Skip | An optional note, then passes the current node or gate without running it. |
| Unblock | Nothing: drops what the item still comes after. |
| Raise budget | The new cap in dollars, or `none`. A cap at or below what the item spent is refused in the dialog, which asks again. When the cap is raised but the retry is refused, the toast says both. |
| Escalate | What the agent should look into. |
| Complete | A required reason. |
| Cancel | What cancelling stops and keeps, then a required reason. The worktree and branch stay. |
| Archive | The console's confirm, then `kraft item archive ID --yes` in the output panel. |

An item abandoned while it is open says it no longer exists. One archived while open shows Archived, with no keys to act.

## The prompt

Every `kraft` verb runs from the prompt at the bottom of every screen. Type it
with or without the leading `/`, and with or without `kraft`, so a command the
CLI printed can be pasted back as it is: `/item resume a91c` and
`kraft item resume a91c` do the same.

| Key | What it does |
|---|---|
| Enter | Runs the command in the output panel. |
| Tab | Completes a group, a verb, a flag, or an item id where the verb takes one. With several choices, it completes what they share and lists them. |
| ↑ | The commands you ran since the console opened. |
| Esc | Clears the prompt and hands the keys back to the screen. |

A group on its own opens its screen: `/admin` the Server screen, `/repo`
Repos, `/addon` Add-ons, `/view` and `/item` the Board. `/view watch` opens
the Board too.

Some commands are refused, with a sentence saying why:

| Typed | Why |
|---|---|
| `kraft`, `/admin start` | The server would run inside the console and stop when it quits. `/admin start --detach` starts it on its own. |
| `/admin mcp`, `/admin permission-hook` | They talk to an agent or a harness, not to you. |
| `/console` | You are in it. |
| `/view logs -f`, `/view events -f` | Following arrives with the Item screen. Leave out `-f` to print what is there now. |

`/admin update` never passes `-y`, even when you type it, so the refusals it
would otherwise skip still show.

## The output panel

Each command runs as its own `kraft` process, and the output panel opens above
the prompt to show it: the command, everything it prints as it prints it, and
its exit code, in red when it is not 0. The panel keeps every command you ran
since the console opened.

| Key | What it does |
|---|---|
| `x` or **Stop** | Stops the running command, as Ctrl+C would in a terminal, so it cleans up after itself. |
| Esc | Closes the panel. The command keeps running; Ctrl+O shows it again. |

One command runs at a time. A command has no terminal to ask you anything on,
so one that would ask goes on without asking or stops with its own refusal.
Quitting the console stops a running command, and kills it if it has not
stopped within three seconds.

## Confirms

Before a command that cannot be undone, the console asks first. **Cancel** has
the focus, so Enter alone never goes on, and Esc answers Cancel.

| Command | What the question adds |
|---|---|
| `/admin restart`, `/admin stop`, `/admin update --restart` | The running items whose agents the stop ends. |
| `/admin update`, `/repo disconnect`, `/item cancel`, `/admin addon uninstall` | What going on does. |
| `/item abandon --yes`, `/item archive --yes` | What is lost. Without `--yes` they only preview, so nothing is asked. |

## Small windows

The console is laid out for 80 columns by 24 rows. Narrower than 80 columns,
the footer keeps only `? keys`, so it still works as a side pane. Smaller than
60 by 16, it shows "make the window larger" until the window grows.

## When it cannot reach the server

| It says | What it means |
|---|---|
| `No server at 127.0.0.1:8765.` | Nothing answers on Kraft's address. **Start server**, focused, runs `kraft admin start --detach`; the console follows the server as soon as it answers. The button is not offered for a server on another host. |
| `The server could not show the board: 500: ...` | The server answers, but three reads of the board in a row failed. The rest is the server's own words. The console keeps trying. |
| `The server refused this machine's token (run/mcp-token).` | A server answers but does not accept the token the console read from `run/mcp-token` in its `KRAFT_HOME`. Check that both use the same home. |
| `● reconnecting` | The event stream dropped, as it does while the server restarts. The console tries again, then reads the board afresh. |
