_Added in next_

These are measurements of `opencode acp` 2.2.5 and the Claude ACP bridge, taken to decide how Kraft's `acp` log reader counts usage.

| What | Measured |
|---|---|
| A turn's usage block from OpenCode 2.2.5 | `{"inputTokens":7305,"outputTokens":103,"totalTokens":15809,"thoughtTokens":209,"cachedReadTokens":8192}`. The parts sum to `totalTokens`. |
| Thought tokens | In addition to output tokens: 7305 + 103 + 209 + 8192 = 15809. Kraft counts output tokens as `outputTokens` plus `thoughtTokens`. |
| Cache | Apart from input tokens: `inputTokens` is the uncached part, and `cachedReadTokens` is added on top of it. |
| A turn from a model that thinks nothing | `{"inputTokens":3608,"outputTokens":3,"totalTokens":5403,"cachedReadTokens":1792}` sums exactly, with no `thoughtTokens` key. |
| The Claude bridge's block | `{"inputTokens":4,"outputTokens":887,"cachedReadTokens":73907,"cachedWriteTokens":38635,"totalTokens":113433}` sums exactly, with no thought tokens. |
| Resuming an OpenCode session | `session/resume` works when the launch runs in the same working directory; from another directory OpenCode answers `session not found`. The second turn sent 42 input tokens and read 5376 from cache. |
| System prompt | OpenCode does not advertise `sessionCapabilities.systemPrompt`, so Kraft folds its context into the prompt text. |
| Whether a resumed process's `usage_update.cost` restarts at 0 | Unverified: the free model reports a cost of 0 on both turns, so a restart cannot be told from a continuation. The reader keeps cost per turn and does not net it. |

The test that holds the sum to the agent's own `totalTokens` runs against a real `opencode` (`tests/acp/test_client_e2e.py`); a future agent that counts differently fails it instead of printing a wrong total.
