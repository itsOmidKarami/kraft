There are two routes to Claude. The shipped `claude` harness (`kind: cli`) runs the installed Claude Code and stays the default. `claude-acp` runs Claude through the `claude-agent-acp` bridge over the Agent Client Protocol. It exists as a comparison: use it to see what an ACP agent keeps and loses against the route Kraft was built around.

## Before you start

Install `@agentclientprotocol/claude-agent-acp` yourself, so that `claude-agent-acp` is on the `PATH` Kraft's workers get. Kraft never installs it and never runs `npx` for it. The bridge starts its own bundled Claude Code, a separate copy of about 320 MB, and needs the same Claude login the `cli` route uses.

## The entries

No ACP harness is bundled. Copy one of these two files into `$KRAFT_HOME/config/harnesses/`. They are the same files as `fixtures/claude-acp.yaml` and `fixtures/opencode-acp.yaml` in the Kraft repository.

```yaml [config/harnesses/claude-acp.yaml]
# Claude Code over ACP, through the bridge `@agentclientprotocol/claude-agent-acp` (0.101.0).
# Copy to $KRAFT_HOME/config/harnesses/claude-acp.yaml, add a profile naming it by `provider:`.
# Kraft never installs the bridge: it must be on the PATH Kraft's workers get.
# The bridge spawns its own bundled Claude Code, so this is the *comparison* route: the shipped
# `claude` harness (kind: cli) stays the default (docs: reference/harnesses/claude-over-acp).
id: claude-acp
kind: acp
command: [claude-agent-acp]
reports: [tokens, cost]
# `mode` is a session config option of the bridge; "default" is its "Manual" (asks before changes).
asks_everything: { mode: default }
# Claude's own always-on deny (claude.yaml, Kraft-avpe): no Monitor in a one-shot launch.
always_deny: [Monitor]
# Tools the bridge runs without asking in Manual mode, measured with `kraft admin acp-probe` (four
# runs, bridge 0.101.0): Read, Bash and ToolSearch. It asked only before Write; Glob and Grep were
# never called (the model used Bash for those steps).
# A task whose policy denies one of these, or leaves it out of an allowlist, refuses at launch.
settles_itself: [Read, Bash, ToolSearch]
options:
  model:  { config: model }
  effort: { config: effort }
```

```yaml [config/harnesses/opencode-acp.yaml]
# OpenCode over ACP (`opencode acp`, 2.2.5). Copy to $KRAFT_HOME/config/harnesses/opencode-acp.yaml.
id: opencode-acp
kind: acp
command: [opencode, acp]
reports: [tokens, cost]
asks_everything:
  env: { OPENCODE_CONFIG_CONTENT: '{"permission":{"*":"ask"}}' }
tool_names: { read: Read, write: Write, edit: Edit, shell: Bash, glob: Glob, grep: Grep, webfetch: WebFetch }
options:
  model: { config: model }
```

Then add a profile to `harnesses.yaml` that names it, such as `claude-acp: { provider: claude-acp, enabled: true }`, and run [`kraft admin acp-probe claude-acp`](/reference/cli/admin#probe-an-acp-agent). The probe has two limits you should know. It answers **every** ask `allow_once`, so it enforces no tool limit. It also runs with your shell's whole environment, where a launch's environment is built from an allowlist.

## Compare the routes

| | `cli` route (`claude`) | `acp` route (`claude-acp`) |
|---|---|---|
| Process | The installed `claude`. | The bridge's own bundled Claude Code, separate from the installed one. |
| Model, effort | Both. | Both; the bridge offers effort `low` to `max`. |
| Tool lists | A gate, plus a `--tools` cut. | The gate, on the calls the bridge asks about. `restrict_tools` is lost. |
| Always-on `Monitor` deny | `--disallowed-tools`. | `always_deny: [Monitor]`, held on the asks. |
| Background tasks off | `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS`. | Unverified that the variable reaches the bundled child. |
| Autocompact | Yes. | No. |
| Context | A system prompt. | A system prompt object. |
| Resume | `--resume`. | `session/resume`, with no replay of history. |
| Cost | From the result envelope. | From `usage_update.cost`. |
| Tokens | Totals in the log. | Per turn, at the end of each turn. |
| Rate-limit fallback | Yes. | No: ACP has no signal for it. |
| Settles itself | Read-only work. | `Read`, `Bash` and `ToolSearch`, as the entry lists them. |
| Grants | Named grants. | Refused when a limit denies Bash. |
| Sandbox and remote machines | As any `cli` harness. | Runs there too, with only the bridge inside the sandbox. See [ACP in a sandbox or on a machine](/reference/harnesses/harness-files#acp-in-a-sandbox-or-on-a-machine). |
| Your plugins and agents | Loaded from your `HOME`. | Loaded, with user, project and local settings, when `HOME` is yours. |
| Your own Claude `permissions` | Read, but Kraft's gate decides every call. | A known difference: they change which calls the bridge asks about. |

The bridge runs `Bash` calls such as `echo` without asking, and Kraft can't stop a call it was never asked about, so the entry lists `Bash` in `settles_itself`, and a task whose policy denies Bash, or whose allowlist leaves out `Read`, `Bash` or `ToolSearch`, refuses to launch on this route. Kraft doesn't relax a limit to make a task run.

The bridge loads `settingSources` user, project and local. Your own Claude `permissions` rules therefore decide some asks before Kraft sees them, and the tools in `settles_itself` were measured under one machine's settings. Run the probe on your machine before you trust that list.

## What refuses on the ACP route

A launch that this entry can't hold stops before the agent starts, with `could not start ...`.

| The reason says | Why |
|---|---|
| `permission_mode` | An ACP agent's asking is its entry's `asks_everything`, so no task can set a mode. |
| `runs Read without asking`, `runs Bash without asking` or `runs ToolSearch without asking` | A limit denies the tool, or an allowlist omits it. |
| `named grant(s)` | A grant is held alongside a limit that denies Bash. |

The shipped default chain, with every shipped task routed to this entry and the shipped profiles, ran to `local_review` on Claude over ACP with no task refused: spec, plan, chain revision, implementation, code review and work brief, 6 agent steps on `sonnet`, with a cost recorded for each step. This is one run, on 2026-11-10, with bridge 0.101.0 and Claude Code 2.1.319.

## What the probe measured

`kraft admin acp-probe` ran four times against `claude-agent-acp` 0.101.0: three on `haiku`, one on the agent's default model.

- **Ran unasked.** `Read`, `Bash` and `ToolSearch`, in every run.
- **Asked.** `Write`, in every run.
- **Not called.** `Glob` and `Grep`: the model used `Bash` for those two steps.
- **Usage.** Tokens came back on each turn's result, with cache read and write counts. Cost came back in `usage_update.cost`; one run on the default model reported about 0.35 USD.

These came from the author's own Claude settings, with their login. The probe isn't a real launch: it answered every ask `allow_once` and ran with the full environment of the shell that started it.
