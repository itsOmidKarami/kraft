`workers.yaml` lists the machines Kraft may run steps on. A machine is another computer with the agent CLIs installed and `kraft` on its `PATH`. In this release a connected machine runs nothing yet: Kraft keeps the connection, reports whether it is up and why not, and nothing else.

```yaml [config/workers.yaml]
workers:
  gpu-box:
    ssh: gpu-box              # ssh mode: a host or an ~/.ssh/config alias
    capacity: 2               # sessions at once; default 1
    repos: [kraft, infra]     # optional; left out means every connected repo
    give_up_after: 2h         # default 2h; "never" turns the limit off
  home-server:
    token_sha256: "9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08"
```

`kraft admin worker add` writes this file for you. The file does not exist until the first machine is added.

| Field | Type | Default | Meaning |
|---|---|---|---|
| `ssh` | string | unset | Ssh mode. A host, `user@host` or an ssh config alias that Kraft's server dials. |
| `token_sha256` | string | unset | Dial-in mode. The SHA-256 of the machine's token, as 64 lowercase hex characters. `worker add` writes it; the token itself is never stored. |
| `capacity` | integer, 1 or more | `1` | How many sessions the machine may run at once. |
| `repos` | list of names | every connected repo | Limits the machine to these repos. See [Naming a repo](#naming-a-repo). |
| `give_up_after` | `30s`, `90m`, `2h`, `1d` or `never` | `2h` | How long Kraft waits for a vanished machine before treating its work as lost. It has no effect yet. |

Each machine sets exactly one of `ssh` and `token_sha256`.

## Names

A machine's name is 1 to 39 lowercase letters, digits, `-` or `_`, starting with a letter or digit. `local` and `any` are refused: they are placement words, not machines.

## Naming a repo

An entry in `repos` matches a connected repo by its `id`, its `name`, or the last part of its `path`. A name that matches no connected repo is refused when you save the file in Settings or add the machine with `worker add`. A hand edit that names one is shown as a problem on the pending reload.

## Two ways to connect

### Dial-in

The machine opens a connection to the server, so it works behind a NAT and needs no inbound port. This is the default mode: `kraft admin worker add NAME` with no `--ssh` registers one.

1. Run `kraft admin worker add home-server`. It prints a token once, and the command to run on the machine.
2. On the machine, run `kraft admin worker serve --server URL --token TOKEN`. It redials by itself after a drop, a refusal or an unreachable server, until you stop it.

The server must be reachable from the machine. That means binding it beyond loopback with a password, as in [Remote access](/guides/run/remote-access).

The connection route is `/api/workers/connect`. It is exempt from the login cookie: the machine proves itself with its token and nothing else. It still obeys the rest of the perimeter, so a server with no password refuses a peer that is not local, token or not.

Kraft speaks plain WebSocket, so TLS is your reverse proxy's job. Put the `https://` address in `--server`.

The token appears in the process list on the machine, because it is on the command line. Treat that machine as trusted with it. To rotate, remove the machine and add it again.

### Ssh

The server dials the machine with `ssh HOST kraft admin worker serve --stdio` and redials when the connection ends. Nothing runs on the machine until the server connects.

Kraft uses the server process's own `ssh` and its own `~/.ssh/config`. A server started by `launchd` or `systemd` may not reach your SSH agent, so give it a key file with no passphrase prompt, or an agent socket it can see. The connection runs with `BatchMode=yes`, so it never asks for a password. `kraft` must be on the remote machine's non-interactive `PATH`.

`kraft admin worker add NAME --ssh HOST` saves the machine, connects once and prints the result. A failed connect leaves the machine saved and exits 1, because a machine that is asleep or not yet reachable is still worth registering.

## When a machine is offline

`kraft admin worker list` shows `offline:` and the reason.

| Reason | What it means |
|---|---|
| `never connected` | Nothing has dialled in, or the server has not connected yet since it started. |
| `refused: invalid token` | The token does not belong to any machine. It was removed, rotated or mistyped. |
| `refused: incompatible protocol: ...` | The machine and the server speak different protocol versions. The reason names both, with each side's Kraft version. Update the older one. |
| `disconnected: ...` | The connection ended, or the other side was silent for 60 seconds. |
| `ssh: ...` | The server's `ssh` ended before the machine answered. The reason is the last of what `ssh` printed, such as `Permission denied (publickey)`. |
| `could not run ssh: ...` | The server could not start `ssh` at all. |

`kraft admin doctor` shows each offline machine as a warning with the same reason. For an ssh machine it is the server's own attempt, not your shell's, so a failure there that your terminal does not show points to the SSH agent.

A second connection from a machine replaces the first. A machine that is removed, or whose `ssh` or `token_sha256` changes, loses its connection at once.

## How Kraft reads the file

- Kraft reads the file at startup and again on `kraft admin reload`. A hand edit shows in Settings as waiting to be reloaded.
- A file that does not load is not used: at startup no machine is connected, and on a reload the running set is kept. `kraft admin doctor` names the problem.
- `kraft admin worker add` and `remove` write the file themselves and apply it at once.
- A Kraft session cannot add, list or remove a machine. Only a person, or an assistant a person is working with, can.
