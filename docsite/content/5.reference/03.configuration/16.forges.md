_Added in next_

`forges.yaml` names forge accounts. An account records which forge a host runs and its web address, so `kraft repo connect` stops asking about a self-hosted host whose name does not say which forge it is. The file does not exist until you write it, and without it nothing changes.

```yaml [config/forges.yaml]
accounts:
  corp-gitlab:
    forge: gitlab                 # github | gitlab
    web_url: https://code.corp.example/gitlab
    default_for_host: true        # repos on this host use it unless they name another
  acme-gh:
    forge: github
    web_url: https://github.com
```

An account that talks to the forge's API names where its token comes from:

```yaml [config/forges.yaml]
accounts:
  corp-gitlab:
    forge: gitlab
    client: api                   # api | cli
    web_url: https://code.corp.example/gitlab
    ca_file: /etc/ssl/corp-ca.pem # optional
    default_for_host: true
    token: { from: git-credential, kind: unknown }
  acme-gh:
    forge: github
    client: api
    web_url: https://github.com
    token: { from: file, file: ~/.kraft/secrets/acme-gh, kind: pat }
```

| Field | Type | Default | Meaning |
|---|---|---|---|
| `forge` | `github` or `gitlab` | required | The forge the account is on. It must agree with the `forge` of each repo that uses it. |
| `client` | `cli` or `api` | `cli` | How Kraft talks to the forge. `cli` keeps the sign-in of `gh` and `glab`, and refuses `token` and `ca_file`. `api` reads a token from the source `token` names. |
| `web_url` | `https://` address | required | The forge's web address. A trailing `/` is dropped. `http://` is refused. |
| `api_url` | `https://` address | derived | The API address. It must have `web_url`'s origin (host and port), except `api.github.com` for `github.com` and `api.SUBDOMAIN.ghe.com` for `SUBDOMAIN.ghe.com`. |
| `token` | mapping | `from: git-credential` | An `api` account only. Where the token comes from, and its kind. See the tables below. A bare string is refused: the file never holds a token. |
| `ca_file` | path | none | An `api` account only. A PEM file of certificate authorities to trust for the forge, for a private CA. |
| `default_for_host` | `true` or `false` | `false` | Repos on this web host use the account unless their entry names another. Only one account may be the default for a host. |

An unset `api_url` is `https://api.github.com` for github.com, `https://api.SUBDOMAIN.ghe.com` for a `ghe.com` host, `https://HOST/api/v3` for another GitHub host, and `WEB_URL/api/v4` for GitLab.

## Where the token comes from

`token.from` names one source, and the one key that source needs. Any other key is refused.

| `from` | Key | What it stores and where it runs |
|---|---|---|
| `git-credential` | none | Nothing. Kraft runs `git credential fill`, asked by host only, and never prompts. It reuses what your git helper holds. |
| `command` | `command` | Nothing. The command runs without a shell and its stdout is the token. Wrap a pipe in `sh -c`. |
| `env` | `env` | Nothing. The variable is taken out of the server's environment when it starts, so a change needs a restart. |
| `file` | `file` | The token, in one file only you can read. The path starts with `/`, `~/` or `$`. |

A `file` path may use `~` and `$VAR`; an unset variable is refused, naming it. The file is refused when it is a symlink, is not owned by the user the server runs as, or has any group or other permission bit. It is also refused inside a connected repo, a worktree, a `sandbox.expose` root, `/etc`, or a system directory every sandbox mounts.

A sandboxed worker never sees the file. A host (unsandboxed) worker runs as the same user as the server, so it can read the file.

An `env` name may not be one Kraft needs: `KRAFT_*`, `GIT_*`, `PATH` and the other variables every child gets, or `ANTHROPIC_API_KEY` and the other credentials Kraft passes to agents.

`token.kind` says what the token is. Every kind is sent as `Authorization: Bearer`.

| `kind` | Meaning |
|---|---|
| `pat` | A personal or project access token. |
| `oauth` | An OAuth access token. |
| `unknown` | The default. Kraft does not say what it is. |

## The origin rule

`api_url` must be on `web_url`'s origin: the same host and the same port, where no port means 443. An `api_url` on another port is refused. The two exceptions are `api.github.com` for `github.com` and `api.SUBDOMAIN.ghe.com` for `SUBDOMAIN.ghe.com`, where both addresses must be on 443.

## Which account a repo uses

A repo uses the account its `repos.yaml` entry names with `forge_account`. Otherwise it uses the account marked `default_for_host` for the host of its `origin` remote, when that account's `forge` is the repo's `forge`; a default for another forge is skipped, and doctor says so. Otherwise it uses the CLI as before.

Hosts compare in lowercase, without a port or a trailing dot. An SSH alias such as `github-work` is not the account's host, so a repo with one names its account itself.

## A file that does not load

A file that does not load is refused when the server rereads it: the running accounts are kept, `/health` reports `degraded` with `invalid_forges`, and `kraft admin doctor` names the file and the key, or for a file that is not valid YAML, the line and column. `kraft admin reload` rereads it.

A file that does not load when the server starts leaves no accounts to keep. Items already pinned keep their pins. Every repo not yet pinned, whether it names an account or not, stops at its next forge node with `forges.yaml does not load (<why>); fix it, then a person's kraft item retry`, until the file loads and a person retries it. A missing file is not this case: it means no accounts.

`invalid_forges` also names a repo whose `forge_account` names no account, or an account on another forge. A save that fixes it clears it.

## What this release does not do yet

- The API backends are not in this release. An item whose repo uses a `client: api` account stops at its first forge node, naming the account. It never falls back to `gh` or `glab`.
- `forges.yaml` is carried across a major update unchanged, like `workers.yaml`.
