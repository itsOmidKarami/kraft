A node's own view, opened from [An item's page](/reference/web-ui/item-page#the-chain-graph), draws the tasks inside the node. This page names the two specialist drawings there: a node with a fix loop and a changed-test-scope task.

![The verification node's own view on a running item: its test, checks and review steps with their tasks, the fix loop drawn as a dashed arc labelled round 2 back to the start, the round picker reading round 2 · latest, and the pane with the node's progress, fix loop round and steps](/assets/fixloop.png)

## A node with a fix loop

A node's own view draws the loop as a dashed arc under the steps. Once the loop has run, its **repair** tasks and the **judge** sit on it as tasks of their own: select one to open it. A loop step with more than one task is one box, captioned **n in parallel**, in the worst state among its tasks; select it to open a frame holding the tasks.

### Picking a round

Beside the zoom, **round n of m** says which round the canvas shows, starting on the newest. Open it to pick an earlier round, newest first, with what became of each; the canvas then shows every task as that round ran it, the repair that went on from it and the [judge](/concepts/vocabulary#judge) after it. **latest ↩** goes back. The round is in the page address (`?round=`), so a copied link opens on it.

### Picking a pass

_Added in 2.1_

The chain can run a node again. Each time is a [pass](/concepts/vocabulary#pass), with its own rounds, tasks, logs and scopes. On a node the chain ran more than once, **pass n of m** sits beside the round and picks an earlier pass (`?pass=`). A node that ran once shows no pass. Each pass says what started it:

| It says | What sent the chain back |
|---|---|
| **after changes were requested at approve local review** | A Request changes at that gate |
| **after a fix at approve local review** | That gate's reviewer, which repaired the work itself |
| **after a retry** | A retry of the node or of one before it |
| **after a base change** | The base branch moved |

**Retry** in a panel runs on the node as it stands now, whichever pass you are reading, and its confirmation says so. A gate's reviewer is in no pass. An [escalation turn](/concepts/vocabulary#escalation-turn) is in the pass whose stop it answered.

### A task in a round

A repair or judge that hasn't run in a round is drawn dashed and faded. Its panel says why: **not yet**, **last round** or **stopped by judge** on the newest round, **not run in this round** on an earlier one, and **skipped · first repair** for round 1's judge.

A task's subtitle names the round (**agent task · round 2 of 3 · running 41s**), so **attempt n of m ▾** appears only when the round itself ran the task more than once.

## A node's on_failure handler
_Added in 2.3_

Once an `on_failure` handler has run, the node's view draws its tasks as a row of their own, hung by a dashed line from what owns it and captioned **on failure** (or with the owner's name, **on failure · lint**). Each box shows how that task went, so a stop inside a handler is red, and a task it never reached is dashed. A stop card's **Open** link opens the node on that task.

## A changed-test-scope task

A changed-test-scope task (`kraft.verify_changed_test_scopes`) opens in place while it, or one of its scopes, is selected: its box becomes a frame with one row per repository, in the order the task visits them (a [workspace](/concepts/vocabulary#workspace)'s root first, then its members), and each repository's scopes as chips.

The task is all of its scopes: it reads **failed** when one of the round's scopes failed, even if a later one passed, and **running** while one still runs. Its log then opens on that scope's.

### The frame

Scopes that run one after another are joined by arrows, and a task set to `execution: parallel` stacks them in a fork. An item in one repository has one row, drawn as its chips alone. While a row has no chips it says **waiting** or **not reached**.

### What a chip says

A chip says how that scope went and how long it took, and reads as the scope's command (an area's setup reads **setup · area**). Hover it for the whole command and the paths it covers.

| You see | It means |
|---|---|
| A dashed **waiting** chip | A scope the round picked and hasn't started |
| **not reached**, with no chips | A repository after the first one that failed |
| **new** | Against the round before it, a scope picked for the first time |
| A dashed **not picked** chip | A scope that ran last round and isn't picked now |

### Targeted and full commands
_Added in 2.4_

A scope that declares a [`targeted_command`](/reference/configuration/repos#targeted_command) runs it in place of its `command`, unless the task says `suite: full`. A chip reads as the command that ran, and says **targeted** beside its state when it was the targeted one. 

A pass says so: the gate reads `✓ 3 scopes (targeted)`, or `(1 targeted)` when only some ran that way, and the work-kept line reads **targeted tests passing** or **partly targeted tests passing**.

When Kraft ran the full command although a targeted one exists, the reason is the `full_reason` of the round's `test_scopes_selected` event: `kraft view events ID --type test_scopes_selected`.

### A chip's panel

A chip opens the scope's panel: its command and paths, its repository when the item has more than one, how it went in every other round, and its log. A link to a scope the round has no chip for opens a panel that says why:

| It says | It means |
|---|---|
| **not picked** | Another round or pass ran the scope, and this round ran its repository without it |
| **not reached** | The round stopped before the scope's repository, or the task didn't run in it |
| **still choosing** | The round is running and hasn't picked its scopes yet |
| **not found** | The task ran no scope with that command |

### Stepping back and closing

**Esc** steps back from a scope to its task, then from the task to its box.
