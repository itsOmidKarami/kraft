**Templates** holds the two files an item is copied from, the [chains](/concepts/vocabulary#chain) and the [library](/concepts/vocabulary#library), as screens. Each edits a draft: your changes take effect when you select **Review & publish**, which shows what changed and checks it first. **YAML** shows the file itself. Open items, every one not done or cancelled, keep the chain they were filed with, and the screens count them as **open**.

## Chains

**Chains** draws a chain as a graph, picked from the menu beside **Chains**. See [Write your own chain](/guides/customize/write-your-own-chain).

![The Chains screen on the default chain: its nodes as a graph under the chain overview, with the spec_approval gate selected and the inspector on the right, with Overview, Config and YAML tabs, showing the gate's message, document and reject-to node, and the header marking an unpublished draft](/assets/chains.png)

| Control | What it does |
|---|---|
| A [node](/concepts/vocabulary#node) | Select it for its settings in [the inspector](/reference/web-ui/item-page#the-inspector); double-click for its own view of steps and tasks. A long chain has [an overview](/reference/web-ui/item-page#the-chain-overview) above it |
| The inspector's name | Rename in place. Renaming the chain shows `old → new` beside **Chains** until you publish, and publishing moves its file to the new name, which new items then name |
| **Review & publish** | Becomes **Back to editing** while you review. The reason **Publish** is blocked is written above it |
| **Duplicate** | Copies the chain under a new name |
| **N defaults · show** | Settings nothing sets fold into this line. A task's **Config** leaves out agent settings a command or merge-request task never uses |
| **reviewer may**, on a gate with a reviewer | **check first (reject, or hand it to you)** or **decide (can approve)**; it sets `auto_review_mode`, and unset reads as **decide**. See [A reviewer that checks first](/guides/customize/add-review-agents#a-reviewer-that-checks-first) |
| `route` and `fallback`, in a task's **Overview** | `route` says how the agent's model is chosen, by a named `profile` or by a `model` and `effort`. `fallback` says what runs when a launch is rate-limited or its harness is unavailable |

An agent task's `fallback` is edited as a list of entries; an entry's `model` and `effort` are set only in YAML.

A value that isn't on a key's allowed list (`ref`, `target`, `inputs`, `steering`, `grants`, `allowed_harnesses`) is marked and isn't saved: [Chain file keys](/reference/chain-nodes) has the lists.

A node's own view has a bottom pane with **On failure**, **Fix loop** and **Escalation**, and **On conflict** once **on base change** is set. An **On failure** recovery has a **read only** switch: on, none of its steps may change code.

A node that merges its merge request has **On merge rejected**, **On failure** and **Escalation**, with no **Fix loop**. The repair runs when a merge train or queue drops the merge request, and the item then restarts from an earlier node and goes through the final review again. Adding the repair, or picking **on merge rejected** in **Config**, sets that node: before the final review when the merge comes after it.

Selecting the merge node draws that restart as an arc labelled **on merge rejected**. Its **On failure** starts with **read only** on, and it stays on: a step may retry, wait or ask, but not change code, which would merge without a review.

### Chains on a phone

_Added in 2.1_

**More › Chains** edits a chain's time caps and a node's or task's **Config** rows into the same draft. Adding, removing and reordering nodes and steps, renaming a chain and editing on-failure handlers stay on the desktop.

### An extending chain

_Added in 2.2_

A chain that [extends](/reference/configuration/library-and-chains#extending-a-chain) another is edited like any chain, and every change is written as one of its edits: `remove`, `add` or `overrides`. Nothing it inherits is copied into its file. The header shows `extends <parent>`.

![The Chains screen on team-default, which extends default: the header reads extends default, the canvas marks verification overridden here and security_scan added here, and the selected verification node's pane says Inherited from default, changes here are saved as this chain's overrides, with Reset all overrides and Remove node](/assets/chain-extends.png)

| Mark | Meaning |
|---|---|
| `added here` | A node the chain adds. It is edited in full, and goes after one of the parent's nodes |
| `overridden here` | A node whose fields the chain overrides. ↺ or **Reset all overrides** deletes the override |
| `removed`, faded | A parent node the chain removes. **Restore** puts it back |
| No mark | A node inherited unchanged. Its fields are editable, and a change writes an override |

What is inside an inherited node is its parent's. Rename, **Change base…**, **Move to library…**, its YAML tab, and adding or removing its steps, tasks and handlers are disabled, each saying `Inherited from <parent>: change it in YAML, or detach the chain.` These marks are about `extends`; a [child add-on's](#a-child-add-ons-chains-and-components) read `inherited from <parent>`.

| Control | What it does |
|---|---|
| **Duplicate** › **Extend** | Starts a chain that keeps following this one, under an ID starting `<chain>_ext` |
| **Duplicate** › **Copy** | Makes a standalone copy you own. The default for a chain of your own; copying an extending chain copies its file, which still extends the same parent |
| **Change base…** | Picks another chain to follow, then lists which edits the new parent can take and which it drops, before changing anything |
| **Detach…** | Writes the nodes into the chain's file; later changes to the parent no longer reach it |

When the edits no longer apply to the parent, the canvas says `<chain>'s edits don't apply to <parent>. Fix them in YAML.`

### Content from an add-on

_Added in 2.1_

A chain or component that an installed [Kraft add-on](/concepts/vocabulary#add-on) ships is listed beside your own under its qualified name, such as `release:ship`, with a badge naming the add-on and its version: `release@acme 1.0.0`. It is read-only: the screens show its settings and YAML and offer no control that changes them.

| Control | What it does |
|---|---|
| **Add to my library**, on a chain | Where **Duplicate** stands. **Extend**, the default, starts a chain of your own that [extends](#an-extending-chain) the add-on's, so an update still reaches it; **Copy** makes a standalone copy |
| **Copy to my library**, on a component | Asks for a name and opens a draft of your library |

A later update to the add-on doesn't change the copy. A copy of a child add-on's chain or component runs what the child serves, overrides included; what it takes from a parent's entries is written into it, and a skill or profile keeps the name of the add-on that ships it, such as `company:slow`. The phone shows add-on content but has neither button.

A [repo library](/reference/configuration/repo-libraries)'s content is listed the same way with the badge `repo library <id>`, read-only, and with neither button: edit it in that repository's `.kraft/`.

#### A child add-on's chains and components

_Added in 2.3_

A chain or component of an add-on that [builds on another add-on](/guides/customize/share-chains-with-addons) carries a mark beside its badge:

| Mark | Meaning |
|---|---|
| `inherited from <parent>` | An ancestor wrote it and this add-on passes it on unchanged |
| `overridden here` | This add-on wrote one of a name its parent has |
| `added here` | This add-on wrote one its parent lacks |

Add-ons are installed and updated with [`kraft admin addon`](/reference/cli/addon#install-and-update-add-ons), not on a screen.

## Library

**Library** lists the components chains are built from, under **Nodes**, **Steps**, **Tasks** and **Steering**, each with how many chains use it. With nothing selected it shows a tile per section; a tile narrows the list to that section, and **Show all** brings the rest back. A component's **Config** tab appears only when it writes a setting its **Overview** doesn't already edit.

The filter button narrows the list by **Kind** and, once an add-on or a repo library ships components, by **Source**: **Local** for your own library, then each add-on or repo library by name. While any filter is on, the list says `Hiding N of M` with a **Reset filters** link.
