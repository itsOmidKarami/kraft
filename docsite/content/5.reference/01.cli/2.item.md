`kraft item` acts on a [work item](/concepts/vocabulary#work-item). Wherever a command takes an ID, you can omit it inside that item's [worktree](/concepts/vocabulary#worktree). Every verb here accepts `--json`; the exceptions are in [Output format](/reference/cli#output-format).

## Verbs at a glance

| Verb | What it does |
|---|---|
| [`item create`](/reference/cli/item#item-create) | Files a work item. |
| [`item approve`](/reference/cli/item#item-approve) | Approves the pending gate. |
| [`item reject`](/reference/cli/item#item-reject) | Rejects the pending gate, with a note on why. |
| [`item pause`](/reference/cli/item#item-pause) | Stops a running, waiting or queued item. |
| [`item resume`](/reference/cli/item#item-resume) | Starts a paused item, optionally with a message. |
| [`item retry`](/reference/cli/item#item-retry) | Re-runs the node a stopped item stopped on. |
| [`item raise-budget`](#item-raise-budget) | Raises the dollar cap that stopped an item and retries it. |
| [`item unblock`](/reference/cli/item#item-unblock) | Drops what a blocked item still comes after. _Added in 2.1_ |
| [`item skip`](/reference/cli/item#item-skip) | Advances past the current node or gate without running it. |
| [`item escalate`](/reference/cli/item#item-escalate) | Asks an agent to help with a `needs_human` stop. |
| [`item complete`](/reference/cli/item#item-complete) | Ends the item as completed. |
| [`item cancel`](/reference/cli/item#item-cancel) | Ends the item as cancelled; its worktree stays. |
| [`item abandon`](/reference/cli/item#item-abandon) | Drops the item, its worktree and its branch. |
| [`item archive`](/reference/cli/item#item-archive) | Archives finished items and removes their worktrees. _Added in 2.1_ |
| [`item restore`](/reference/cli/item#item-restore) | Puts an archived item back under Done. _Added in 2.1_ |

| [`item resolve`](/reference/cli/item#item-resolve) | Marks a review thread resolved. |

| [`item mr-label`](/reference/cli/item#item-mr-label) | Labels the item's merge request. |

| [`item reply`](/reference/cli/item#item-reply) | A worker answers a review thread. |

## Gates and running work

### `item approve`

```text
kraft item approve [flags] [ID]
```

Approves the pending [gate](/concepts/vocabulary#gate).

| Flag | Type | Default | Meaning |
|---|---|---|---|
| `--gate` | gate ID | whichever gate is pending | Names the gate you mean to decide. Refused if it isn't the pending one. |
| `--digest` | text | none | Pins the approval to a [chain revision](/concepts/vocabulary#chain-revision), as `kraft view artifact` printed it. |
| `--head` | text | none | Names the head you reviewed, as `kraft view show` printed it. The final review's approval is refused without it, or once the branch has moved. _Added in 2.3_ |

### `item reject`

```text
kraft item reject [flags] [ID]
```

Rejects the pending gate, with a note on why.

| Flag | Type | Default | Meaning |
|---|---|---|---|
| `--note` | text | none given: required | Records why. A rejection needs a reason. |
| `--gate` | gate ID | whichever gate is pending | Names the gate you mean to decide. Refused if it isn't the pending one. |
| `--node` | node ID | the chain's own `reject_to` | Re-enters the chain at that [node](/concepts/vocabulary#node) instead of the gate's default. |

### `item pause`

```text
kraft item pause [ID]
```

Stops the whole work item: a running one, one waiting on CI, or one waiting out a rate limit. It also takes a queued or blocked item out of the hold, back to the status it came from.

It signals the current node's running agent sessions to stop and keeps their logs, drops a CI wait's or rate limit's next wake-up so nothing restarts the item, and leaves its worktree and branch as they are. It takes no flags besides the ID.

| Refusal | Cause |
|---|---|
| `409: work item is STATUS, not running` | The item is in a status pause doesn't take, such as `needs_human` or `completed`. |
| `409: work item is being started from the queue: pause it again in a moment` | The start queue has taken the item and not yet started it. |
| `403` | A [worker](/concepts/vocabulary#worker) session names its own item. |

### `item resume`

```text
kraft item resume [flags] [ID]
```

Starts a paused item, including one just filed, or one stopped on an agent's question. With every slot busy it is queued.

| Flag | Type | Default | Meaning |
|---|---|---|---|
| `--steer` | text | none | Gives every paused agent task a message, or the answer to its question. |
| `--steer-task` | `PATH=TEXT`, repeatable | none | Sends a message to one paused agent task, named by its `node.step.task` [path](#addressing-work-by-path). |

One message for every paused task, and a different one for the code review:

```bash each
kraft item resume --steer "keep the old API" --steer-task verification.review.code_review="check the auth module first"
```

A paused agent task resumes its own session where its harness can, as [What retry and resume keep](#what-retry-and-resume-keep) says.

| Refusal | Cause |
|---|---|
| `409` naming `item retry` | The item is stopped, not paused. |
| `--steer` refused | The item is still running: pause it first. |
| `--steer` refused | The item's pause stopped no agent task, such as a test run or a CI wait. |
| `--steer-task` refused | The path isn't a paused agent task. |

### `item retry`

```text
kraft item retry [flags] [ID]
```

Re-runs the node a stopped item stopped on, or after a cap [its step](#what-retry-and-resume-keep), and is the way back onto a stopped item. With every slot busy the item is queued.

| Flag | Type | Default | Meaning |
|---|---|---|---|
| `--steer` | text | none | Carries a message into the retry's prompt. |
| `--path` | `node`, `node.step` or `node.step.task` | the node it stopped on | A step re-runs that step and everything after it. A task re-runs only that task, and its finished siblings stand. A node that already completed re-runs with everything after it. Exclusive with `--restart`. |
| `--restart` | switch | off | Re-runs the whole chain from its first node. |
| `--sandbox-from-config` | switch | off | Prints the item's sandbox and the one `repos.yaml` sets now, and changes nothing. A worker or an assistant is refused. _Added in 2.3_ |
| `--yes` | switch | off | With `--sandbox-from-config`, replaces the sandbox and retries. |

#### What retry and resume keep

A retry keeps everything the earlier run did and starts a new run from the retried work. It reopens every gate it has to re-run. A gate before the retried work keeps its decision.

A retry with no `--path` after a time cap, a budget cap or rate-limit retries running out starts at the step the item stopped in, not at its node's first: the steps before it passed, and running out says nothing about them. **Raise cap** and `raise-budget` retry the same way. A fix-loop cap, or any of these once the node's fix loop has run, re-runs the whole node, since a fix can break a step that had passed.

Only a retry you run yourself resets the counters of a cap the item breached, and Kraft records the reset as a `cap_counters_reset` event. A retry sent from a session Kraft started, or through the MCP client, leaves every counter where it stands, so an item that stopped on a cap stops again.

A gate rejection gives the nodes it re-runs their fix-loop attempts back, whoever rejected. The gate's own reject loop still counts each rejection, and only your retry resets that.

A paused agent task resumes its own session when its harness supports it, and is told the [steer](/concepts/vocabulary#steer). Otherwise it restarts with its brief and the steer.

### `item raise-budget`

<!-- renamed from: Raise a cap that stopped an item -->

```text
kraft item raise-budget [flags] [ID]
```

`kraft item raise-budget` raises the dollar [cap](/concepts/vocabulary#cap) that stopped the item, then retries the node it stopped on.

| Flag | Type | Default | Meaning |
|---|---|---|---|
| `--usd` | dollars or `none` | none given: required | `--usd N` raises the cap to N dollars and retries the item. `--usd none` lifts the cap. |

It raises one of two caps:

- The item's own cap, the one `item create --budget` sets.
- The item-wide `budget_usd` of the item's [policy](/concepts/vocabulary#policy). Kraft writes it into the item's policy override and keeps the override's other fields, as the interface's **Raise cap** does.

It refuses, and changes nothing, in these cases:

| Refusal | Cause |
|---|---|
| A worker session: `kraft: a worker session cannot act on its own work item (ID). Gates are where a human decides; report what you found instead.` An escalation turn: the same sentence after `kraft: 403:`. | The caller is a [worker](/concepts/vocabulary#worker) session on its own item, or an [escalation turn](/concepts/vocabulary#escalation-turn): a spending cap is a person's call. |
| `409: work item is not stopped` | The item's status isn't `needs_human`. |
| `409: work item is queued for a free slot and starts on its own: pause it to take it out of the queue (kraft item pause ID)`, or the blocked wording. | The item is `queued` or `blocked`. |
| `409: work item was not stopped by a spend cap` | The item stopped for a reason that isn't a spend cap, such as a failed test. |
| `409: a budget_usd on a node, step or task stopped this item: raise it with ...` or `409: a token_budget stopped this item, not a dollar cap: raise it with ...`. Both name `kraft item set-policy`. | The stop was on a node, step or task's `budget_usd`, or on a `token_budget`. `item set-policy` raises those, but it replaces the item's whole override, so pass the fields it already has too. |
| `409: the daily cap stopped this item, not its own cap: raise budget.daily_usd in policy.yaml, or wait for local midnight, then retry` | The stop was on `budget.daily_usd`. Raise it in `policy.yaml`, or wait for local midnight. |
| `409: a budget_usd stopped this item on spend a harness never reported, which no higher cap passes: ...` | The stop was on spend a [harness](/concepts/vocabulary#harness) never reported, and you passed a number, or the cap is a node, step or task's. Only `--usd none` on the item-wide cap passes. |
| `422: the item has already spent $X; a cap of $N would stop it again at once: raise it above that, or to none` | N is at most what the item has already spent. Raise it above that, or use `none`. |
| `blocked ID: it comes after OTHER (status). It starts when they complete; kraft item unblock ID drops them` | The item comes after an unfinished item, so the retry waits for it. The cap is raised. |
| `queued ID: N of M slots are busy. It starts when one frees; kraft item pause ID takes it out of the queue` | Every slot is busy, so the retry waits for one. The cap is raised. |
| `queued ID: held by the worktree storage limit: 12G counted against the 10G limit. It starts when space frees; kraft item archive --reclaimable archives finished items to make room, kraft item pause ID takes it out of the queue` | Worktrees are over `storage.worktrees.limit`, so the retry waits for space. The cap is raised. |
| `queued ID: waiting for the checkout: “TITLE” is using it. It starts when the checkout frees; kraft item pause ID takes it out of the queue` | The item runs [in place](/guides/run/run-items-in-place) and another one is using the checkout. The cap is raised. |
| `409: a walk is already running for this work item; the cap was not changed` | A [walk](/concepts/vocabulary#walk) is still running, so the retry couldn't start. |
| `422: 'budget_usd' 25 cannot exceed the administrator maximum 20`; for `none`, the value reads `none`. | The item-wide cap you set, or `none`, is past `maxima.work_item.budget_usd` in `policy.yaml`. |
| `409: this work item has no chain snapshot to hold a policy override` | The item has no chain snapshot to hold a policy override. |

If the cap moves and the retry is then refused, the answer says so. Run `kraft item retry` once that is resolved.

See [Raise a cap on a stopped item](/guides/day-to-day/raise-a-cap).

## Filing a work item

### `item create`

```text
kraft item create [flags] TITLE
```

Files a work item. Without `--autostart` it is filed paused, and you start it.

| Flag | Type | Default | Meaning |
|---|---|---|---|
| `--description` | text | none | The brief: what the work is, which the spec is written from. Ids in it aren't parsed; `--implements` names an issue. |
| `--after` | item ID, repeatable | none | Names a work item this one comes after. See [Items that come after others](#items-that-come-after-others). |
| `--autostart` | switch | off | Starts the item at once. Refused from a session Kraft started. With every slot busy, the item is filed `queued` and starts when one frees, and the command says so: [What create prints](#what-create-prints) shows the line. `--json` carries the `slots`. |
| `--spec`, `--plan` | path | none | Attaches a document and skips the node that would write it. See [Attach a spec or plan](#attach-a-spec-or-plan). |
| `--base-branch` | branch name | the repo's default branch | Starts from, and merges into, that branch. It must exist on `origin`. |
| `--in-place`, `--worktree` | switch | the repo's `worktrees` setting | Runs the item in the repo's own checkout, or in a worktree of its own. Either overrides the repo's [`worktrees`](/reference/configuration/repos#worktrees) setting. Frozen when filed. See [Run items in your own checkout](/guides/run/run-items-in-place). _Added in 2.1_ |
| `--chain-file` | path | none | Files the item with a one-off chain read from the file, exclusive with `--chain`. A person reviews its custom content in the web UI before the item can start; until then `--autostart` files it paused. _Added in 2.5_ |
| `--repo` | path | the repo you are standing in | Targets another connected repo. A relative path is read from where you stand. |
| `--chain` | chain ID | the repo's `default_chain`, else `default` | Targets another chain. |
| `--implements` | bead ID, repeatable | none | Closes the named issue in your optional [beads](/concepts/vocabulary#beads) issue tracker when the item completes. |
| `--auto-gate`, `--no-auto-gate` | switch | on | An agent reviews each gate that declares `auto_review` before you are asked, in either `auto_review_mode`. `--no-auto-gate` turns that off for this item. Items filed by a schedule, `POST /api/triggers` or [auto-intake](/concepts/vocabulary#auto-intake) have it off. |
| `--runner` | machine, group, `any` or `local` | the library's | Where the item's steps run: a machine or [group](/reference/configuration/workers#groups) from [`workers.yaml`](/reference/configuration/workers), `any` or `local`, over the library's. See [Run a step on another machine](/guides/run/run-a-step-on-another-machine). _Added in 2.4_ |
| `--skip-nodes` | node ID, repeatable | none | Node IDs to leave out of the item's chain at intake, comma-separated or repeated (`--skip-nodes spec,plan` or `--skip-nodes spec --skip-nodes plan`). |
| `--budget` | dollars or `none` | the policy's | Sets the item's dollar cap. `--budget none` lifts it. |
| `--node-override` | `NODE.FIELD=VALUE`, repeatable | none | Overrides one field on node `NODE`, any field `item set-node-override` takes. |
| `--policy` | `KEY=VALUE`, repeatable | none | Gives the item its own [policy override](#a-work-items-own-policy). |

It refuses, and files nothing, in these cases:

| Refusal | Cause |
|---|---|
| An error naming `kraft repo connect` | `--repo` names a repo you haven't connected. |
| A refusal of `--runner` | The name is unknown, or the item runs in place or has workspace members. |
| `422` | An `--after` ID is unknown or abandoned. |
| `attachment path escapes the repo` | A `--spec` or `--plan` file is outside the repo. |
| `422: unknown node id(s) to skip: [...]` | A `--skip-nodes` ID the chain doesn't have. |
| `422: skip_nodes: 'ID' does not allow skipping` | A `--skip-nodes` node that doesn't allow skipping. |
| `422: dropping [...] would leave chain 'ID' with no nodes` | The skipped nodes, with any an attachment trims, are the whole chain. |

`--autostart` is refused (403, nothing filed) from a session Kraft started and
from a request tagged as the MCP client, which has no autostart option. The
server can't tell a coding agent that runs the command in its own shell from a
person, so that call starts the item.

#### What create prints

`item create` prints the new item's `id`, `status` and `title` as `key  value` lines. A line follows for each warning that applies: `repo_warning`, `bead_warning` or `duplicate_warning`.

```text
id      3f9c1e7a5b2d4c80a6e1d97f0b34c2aa
status  paused
title   fix the flaky test
```

`status` is what the server answers: `paused`, or `active` when `--autostart` found a free slot. With `--autostart` and every slot busy, the item is filed `queued` and a last line replaces the `slots` key, after any warning lines:

```text
queued 3f9c1e7a5b2d4c80a6e1d97f0b34c2aa: 3 of 3 slots are busy. It starts when one frees; kraft item pause 3f9c1e7a5b2d4c80a6e1d97f0b34c2aa takes it out of the queue
```

When the storage limit or an in-place item's checkout holds the start instead of a busy slot, that line says so in place of the slot count, as the table above shows for `raise-budget`.

#### Items that come after others

_Added in 2.1_

`--after ID` takes a work item ID of any repo on this Kraft instance, or a start of one 4 characters or more that no other item's ID shares. The item stores the whole ID. An unknown or abandoned ID is refused with `422`, and a completed one counts as met. Dependencies are set when the item is filed: `item unblock` drops them, and nothing adds them.

A dependency is met when the item it names is `completed`, post-merge nodes included. `item resume`, `retry` and `raise-budget` on an item with an unfinished dependency block it, after their own refusals and before the slot check. The scheduler moves it to the queue once all are met. A start after an abandoned item is refused with a `409` naming it, and the two ways on: `item unblock` or `item cancel`.

`item pause` takes a blocked item out and keeps its dependencies, so starting it again blocks it again. `item unblock` drops the unmet ones, or only `--dependency ID` (the start of one of its IDs is enough), and the next scheduler pass releases the item. On any status but `blocked` or `paused` it answers `409`. A blocked item whose dependency is abandoned goes back to where it came from, and its timeline says why.

#### What a blocked start prints

_Added in 2.1_

`item resume`, `retry`, `raise-budget` and `create --autostart` on an item that comes after an unfinished one print one line, and `--json` carries `waiting_on`:

```text
blocked 3f9c1e7a5b2d4c80a6e1d97f0b34c2aa: it comes after b81d0c42e6a94f3d8c5a7e19f2046b13 (active). It starts when they complete; kraft item unblock 3f9c1e7a5b2d4c80a6e1d97f0b34c2aa drops them
```

#### Attach a spec or plan

- `PATH` must be a file inside the repo (or a worktree of it), usually under `.engineering/`, since it is committed on the item's branch.
- A file outside is refused with `attachment path escapes the repo`: copy it in first.
- A relative `PATH` is read from where you stand.

#### Filing on a repo that can't run the item yet
<!-- renamed from: Filing on a repo that cannot run the item yet -->

Filing on a repo that can't run the item yet still works, with a warning. A
repo with no setup command declared stops the item before its first task. One
with no test command (and no test scopes) stops it at verification, after its
agent tasks have run. Set the missing command in Settings › Repos, or run
`kraft repo connect` in the repo again, before you start the item. `--json`
carries the warning as `repo_warning`.

### `item unblock`

_Added in 2.1_

```text
kraft item unblock [flags] [ID]
```

Drops what a blocked or paused item still comes after.

| Flag | Type | Default | Meaning |
|---|---|---|---|
| `--dependency` | item ID, or the start of one of 4 characters or more | every unmet dependency | Drops only that one. |

On any status but `blocked` or `paused` it answers `409`. [Items that come after others](#items-that-come-after-others) says what happens next.

## Addressing work by path

Retry, skip and resume address chain work by its path: `node`, `node.step` or
`node.step.task`. A `tasks:` node's one step is `main`, so the path to its
`implement` task is `implementation.main.implement`. `kraft view show --json`
lists every path. [`item retry --path`](/reference/cli/item#item-retry) and
[`item resume --steer-task`](/reference/cli/item#item-resume) take one, and so
does [`item skip --path`](/reference/cli/item#item-skip).

## Reviewing a change

### `item comment`

```text
kraft item comment [flags] [ID]
```

Drafts a review comment: a new thread, or with `--reply` an answer to one. `--file`, `--lines` and `--side` anchor it to a line range; without them it is about the whole change.

| Flag | Type | Default | Meaning |
|---|---|---|---|
| `--body` | text | none given: required | The comment. |
| `--reply` | thread ID | none | Answers an existing thread instead of starting a new one. |
| `--file` | path, as the diff names it | none | The file in the repository the comment is about. |
| `--lines` | `A[-B]` | none | The line range in `--file` the comment is anchored to. |
| `--side` | `old` or `new` | `new` | The side of the diff the range is on. |
| `--start-side` | `old` or `new` | the `--side` value | Puts line `A` on the other side, for a range across sides: `--lines 12-13 --start-side old --side new` is old line 12 through new line 13, a removed line through its replacement. |
| `--label` | one of `must-fix`, `question`, `nit` | none | Labels the thread. |
| `--suggest` | text | none | Gives a suggested replacement for the range. |

A comment across a removed line and its replacement:

```bash each
kraft item comment --body "keep the old name" --file src/db.py --lines 12-13 --start-side old --side new
```

Kraft quotes the range's lines from the diff onto the thread, so the agent that reads it gets them, as for a comment made on the review page. The command prints the thread's place (`src/db.py:+40`, `src/db.py:-12 to +13`) and the lines it quotes.

| Refusal | Cause |
|---|---|
| A refused `--file` | The path starts with `/` or holds `..`. |
| A refused `--suggest` | The range isn't `--lines` on the new side alone: a suggestion replaces new lines, so an old-side range is refused. |

### `item resolve`

```text
kraft item resolve [flags] THREAD
```

Marks a review thread resolved. It takes no flags. It prints one line, such as `resolved thread a893… on calc.py:+9 to +11`; `--json` prints the thread.

### `item reopen`

```text
kraft item reopen [flags] THREAD
```

Reopens a resolved review thread. It takes no flags. It prints one line, as `item resolve` does; `--json` prints the thread.

### `item review`

```text
kraft item review [flags] [ID] OUTCOME
```

Sends your drafted comments with an outcome. `OUTCOME` is one of:

| Outcome | Meaning |
|---|---|
| `comment` | Queues the drafts for the next agent; never interrupts. |
| `approve` | Needs a pending gate. |
| `request-changes` | Redoes the work now, at a pending gate or not. |

| Flag | Type | Default | Meaning |
|---|---|---|---|
| `--summary` | text | none | Adds a note above the threads. |
| `--node` | node ID | derived from the threads | Overrides where `request-changes` re-runs. |
| `--head` | text | none | Names the head you reviewed at the final review, as `item approve` takes it. _Added in 2.3_ |

Drafts are invisible to every agent until a review sends them. `must-fix`
blocks every gate approval until resolved. See [Reviewing a
change](/guides/day-to-day/review-a-change) for the full picture, and `kraft view
threads`/`kraft view compare` in the [view verbs](/reference/cli/view) to read
before you comment.

## Skip, escalate, end or drop an item

### `item skip`

```text
kraft item skip [flags] [ID]
```

Advances past the current node or gate without running it.

| Flag | Type | Default | Meaning |
|---|---|---|---|
| `--note` | text | none | Records why, on the skip's event. |
| `--path` | `node`, `node.step` or `node.step.task` | the whole current node or gate | Skips only that node, step or task of the current node. Its siblings keep running. |
| `--head` | text | none | Names the head you reviewed, as `kraft view show` printed it. Skipping the final review needs it. _Added in 2.3_ |

| Refusal | Cause |
|---|---|
| `422: path: ...` | `--path` names nothing in the item's chain. |
| `409: path: 'PATH' does not allow skipping` | The node, step or task doesn't allow skipping. |
| `409: path: 'PATH' is not the node the item stands on ...` | `--path` names a node other than the current one or its pending gate. |
| `409: a walk is already running for this work item` | A [walk](/concepts/vocabulary#walk) is still running for a stopped item. |

### `item escalate`

```text
kraft item escalate [flags] [ID]
```

Asks an agent to help with a `needs_human` stop, or with a paused item that has started. The manual form of the board's auto-escalation.

| Flag | Type | Default | Meaning |
|---|---|---|---|
| `--message` | text | none given: required | What to tell the agent. |
| `--new-thread` | switch | off | Starts a fresh agent session instead of continuing the latest thread. |

| Refusal | Cause |
|---|---|
| `409` | A spend cap stopped the item, and the agent would spend against the same cap. Raise that cap first: the item's own with `raise-budget`, the daily one with `budget.daily_usd` on Settings › Policy. |

### `item complete`

```text
kraft item complete [flags] [ID]
```

Ends the item as completed. It stops whatever is running and records the reason on the item's timeline.

| Flag | Type | Default | Meaning |
|---|---|---|---|
| `--reason` | text | none given: required | Why, recorded on the audit event. |
| `--close-beads` | switch | off | Also closes its linked [beads](/concepts/vocabulary#beads) issues. |

### `item cancel`

```text
kraft item cancel [flags] [ID]
```

Ends the item as cancelled. It stops whatever is running and records the reason on the item's timeline. The worktree stays.

| Flag | Type | Default | Meaning |
|---|---|---|---|
| `--reason` | text | none given: required | Why, recorded on the audit event. |

Cancel settles beads as abandon does: the item's own bead is closed with the reason, and a bead it implements stays open with a note.

### `item abandon`

```text
kraft item abandon [flags] [ID]
```

Drops the item, its worktree and its branch.

| Flag | Type | Default | Meaning |
|---|---|---|---|
| `--reason` | text | asked for in a terminal | Why it is dropped. With none recorded, it warns. |
| `--yes` | switch | off | Required, because uncommitted work and unpushed commits are lost. |

`abandon` records its reason on the item's `work_item_abandoned` event, and `kraft view show` and the item page show it. It also writes the reason to the item's [bead](/concepts/vocabulary#beads): the bead intake filed is closed with it, and a bead the item implements stays open with a note. A beads failure is logged and never fails the abandon.

`abandon` deletes the item's worktree, its branch and its [attachment](/concepts/vocabulary#attachment) copies, including those of a cancelled item. `abandon` has no MCP tool.

| Refusal | Cause |
|---|---|
| `409` | The item is active: pause it first. |

## Archive and restore finished items

_Added in 2.1_

### `item archive`

```text
kraft item archive [flags] [ID ...]
```

Archives completed or cancelled items and removes their worktrees. With no ID, the item whose worktree you are in.

| Flag | Type | Default | Meaning |
|---|---|---|---|
| `--yes` | switch | off | Archives. Without it the verb only prints the preview. Uncommitted changes in each worktree are lost. |
| `--reclaimable` | switch | off | Takes every completed or cancelled item that isn't archived and that [`view storage`](/reference/cli/view#worktree-disk-use) marks reclaimable, the 200 largest at most (the preview and bulk routes take no more); run it again for the rest. Refused beside IDs. |
| `--json` | switch | off | Prints the preview when `--yes` is missing, and the bulk results when it is given. |

```bash each
kraft item archive ID1 ID2 --yes
kraft item archive --reclaimable --yes
```

Before it archives, `item archive` prints one line per item: the worktree's size, how many uncommitted files the archive loses, and whether the branch stays (it does when it holds commits nothing else has). Then it prints the total freed and where usage lands against the quota and limit. `item archive` has no MCP tool.

| Refusal | Cause |
|---|---|
| Exit `1`, nothing archived | `--yes` is missing: it stops after the preview. |
| A line in the results, exit `1` | An item can't be archived. The rest are still archived. |

### `item restore`

```text
kraft item restore [ID]
```

Puts an archived item back under Done. The worktree archive removed doesn't come back. It takes no flags. `item restore` has no MCP tool.

## Change an item's setup

### `item set-chain`

```text
kraft item set-chain [flags] [ID]
```

Switches a not-yet-started item's chain. One of `--chain` and `--chain-file` is required.

| Flag | Type | Default | Meaning |
|---|---|---|---|
| `--chain` | chain ID | none | The chain to switch to. Also accepted as `--template`. |
| `--chain-file` | path | none | Gives the item a one-off chain instead, which a person reviews first if it has custom content. Exclusive with `--chain`. _Added in 2.5_ |

### `item set-attachments`

```text
kraft item set-attachments [flags] [ID]
```

Revises a not-yet-started item's spec or plan, copying the file again.

| Flag | Type | Default | Meaning |
|---|---|---|---|
| `--spec`, `--plan` | path | none | The revised document, a file inside the repo. [Attach a spec or plan](#attach-a-spec-or-plan) says which paths it takes. |
| `--drop` | `spec` or `plan`, repeatable | none | Removes that attachment and restores the gate it trimmed. |

| Refusal | Cause |
|---|---|
| `409` | The item has started: its worktree already holds its documents, committed on its branch. |

### `item set-overrides`

```text
kraft item set-overrides [flags] [ID]
```

Sets the item-wide model and effort, without changing the chain.

| Flag | Type | Default | Meaning |
|---|---|---|---|
| `--model` | model ID | the chain's own binding | The item-wide model. |
| `--effort` | one of `low`, `medium`, `high`, `xhigh`, `max` | the chain's own binding | The item-wide effort. |
| `--escalate-model` | model ID | the chain's own binding | The model for a [fix loop](/concepts/vocabulary#fix-loop)'s escalation. |
| `--runner` | machine, group, `any` or `local` | the stored one | Where the item's steps run. Takes effect at the next step launch. _Added in 2.4_ |
| `--clear` | switch | off | Returns every one to the chain's own binding, the runner too. |

Each call replaces the whole override, so a flag you leave out goes back to the chain's own binding. The one exception is `--runner`: a call that doesn't name it keeps the stored one.

| Refusal | Cause |
|---|---|
| A refused model | It doesn't look like a model ID: letters, digits and `. _ : / @ + [ ] -`, optionally after a leading `~`, at most 128 characters. |

### `item set-node-override`

```text
kraft item set-node-override [flags] [ID]
```

Changes one node of one item until that node starts. The override is stored on the item and doesn't edit the chain.

| Flag | Type | Default | Meaning |
|---|---|---|---|
| `--node` | node ID | none given: required | The node to change. |
| `--auto-escalate`, `--no-auto-escalate` | switch | unchanged | Arms or disarms agent review of this node's auto-escalate gates. |
| `--auto-escalate-stuck`, `--no-auto-escalate-stuck` | switch | unchanged | Arms or disarms auto-escalation when this node stops [stuck](/concepts/vocabulary#stuck). |
| `--auto-escalate-delay-s` | integer, seconds | unchanged | The delay before this node's auto-escalation fires. |
| `--model`, `--effort` | model ID, effort level | unchanged | What every agent task in the node launches with. See [Which model and effort a task uses](#which-model-and-effort-a-task-uses). |
| `--runner` | machine, group, `any` or `local` | unchanged | Where the node's steps run. Wins over the item-wide `--runner` and the library. _Added in 2.4_ |
| `--extra-prompt` | text | unchanged | Appended to the instruction of every agent task the node runs. See [Extra prompt](#extra-prompt). |
| `--reviewer` | `bot:LOGIN`, `check:NAME` or `none`, repeatable | unchanged | The automated reviewers the node's review wait reads, over the repo's and the task's. `none` alone expects none. _Added in 2.4_ |
| `--clear` | switch | off | Resets the node to the chain's own binding. |

Each call changes only the flags you give and keeps the node's other overrides, so `--model opus` and then `--effort max` leave both set. This differs from `set-overrides`, where each call replaces the whole item-wide override.

`attempts` and `wall_clock_s` have no flag here. Set them at filing with `kraft item create --node-override N.attempts=2`. Before the item starts, the node's Config tab on the item page also sets `attempts`.

| Refusal | Cause |
|---|---|
| A refused change | The node has started. `--runner` alone is allowed on a started node, because it takes effect at the next step launch. |
| `403` | `--extra-prompt` from a [worker](/concepts/vocabulary#worker) session or an escalation turn. |

One more case is allowed after the node starts: an item stopped at that node because its stored model override isn't a valid model ID. Fix it with `--clear`, or a new `--model` or `--effort`, then retry. An item filed by an older Kraft can meet this.

#### Which model and effort a task uses

From highest precedence to lowest:

1. This node override.
2. The item-wide `set-overrides`.
3. The task's own `model:` and `effort:` in the [library](/concepts/vocabulary#library).
4. The repo's `models:` (model only).
5. The [harness profile](/concepts/vocabulary#harness-profile)'s `defaults:`.

A value the node's harness doesn't accept is refused when you set it, not at launch. A gate's `auto_review` uses the item-wide values only.

#### Extra prompt

`--extra-prompt` is added after the task's own prompt and brief. It never replaces them. It doesn't reach a gate's `auto_review` or the interactive escalation turn. At [intake](/concepts/vocabulary#intake), `N.extra_prompt=...` is taken as written, not read as YAML.

An extra prompt is a person's to set, so an agent's text doesn't reach a task unreviewed. From a worker session or an escalation turn, `--extra-prompt` and `--node-override N.extra_prompt=...` are refused (`403`), and so is an `extra_prompt` sent through the MCP server.

### `item set-policy`

```text
kraft item set-policy [flags] [ID]
```

Gives the item its own policy override, replacing any it had.

| Flag | Type | Default | Meaning |
|---|---|---|---|
| `--policy` | `KEY=VALUE`, repeatable | none | One field of the override. |
| `--clear` | switch | off | Drops the item's own override. |

A key is dotted down the policy's levels, and `--policy` repeats for more than one field:

```bash each
kraft item set-policy --policy merge_request_feedback.ci.await_ci.total_time_cap_minutes=60
kraft item set-policy ID --policy max_attempts=2 --policy time_cap_minutes=45
```

#### A work item's own policy

`kraft item create --policy KEY=VALUE` (repeatable) and `kraft item
set-policy` give one work item its own policy override, without touching its
chain or any other item. `FIELD=VALUE` applies item-wide. `PATH.FIELD=VALUE`
applies to one node, step or task and everything under it, as in
`--policy merge_request_feedback.ci.await_ci.total_time_cap_minutes=60`. Values
are read as YAML, so `deny_tools=[WebFetch]` is a list.

`set-policy` replaces the whole override. The fields are those described in
[policy.yaml](/reference/configuration/policy):

| Fields | Behaviour |
|---|---|
| `timeout_minutes`, `max_attempts`, `allowed_harnesses` | Move within the `maxima` in `policy.yaml` and win over what the chain set. `max_attempts` applies to execution nodes only. |
| `allowed_tools`, `deny_tools`, `sandbox` | Only tighten. A list intersects with what each task already allows. |
| `time_cap_minutes`, `total_time_cap_minutes`, `token_budget`, `budget_usd` | Item-wide caps. Raise one above the chain's, up to `maxima.work_item`, to unstick a capped item before a retry. `budget_usd=none` clears the dollar cap, the one way past a stop on unknown spend; see [Raise a cap on a stopped item](/guides/day-to-day/raise-a-cap). |

On a path, a cap only tightens. Kraft refuses a value above what the chain or the item already gives that scope, and names both. A wait task's total cap is its timeout.

Kraft refuses a value past its maximum, a path the chain doesn't have, and a
key that isn't a policy field, naming the field.

`set-policy` works on any item that hasn't ended. On a running or waiting
item it takes effect from the next node the item enters and from the next
check of a wait it is parked on. The new timeout counts from when the wait
started.
