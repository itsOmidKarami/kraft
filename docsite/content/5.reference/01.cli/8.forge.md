`kraft admin forge` manages the accounts in `forges.yaml`. The [server](/reference/cli/server), [add-on](/reference/cli/addon) and [machine](/reference/cli/worker) verbs are on their own pages.

## Verbs at a glance

| Verb | What it does |
|---|---|
| [`admin forge`](#forge-accounts) | Names, edits, lists, removes and tests forge accounts. _Added in 2.5_ |

## Commands

```bash each
kraft admin forge add NAME --forge github|gitlab --web-url URL [--api-url URL] [--default-for-host] [--client cli|api] [--ca-file PATH] [--token-from SOURCE | --token-stdin] [--kind pat|oauth|unknown]
kraft admin forge edit NAME [--api-url URL] [--ca-file PATH] [--client cli|api] [--token-from SOURCE | --token-stdin] [--kind pat|oauth|unknown]
kraft admin forge list
kraft admin forge remove NAME
kraft admin forge test NAME
```

| Command | Effect |
|---|---|
| `admin forge add NAME` | Names a forge account: the host's forge and web address, and for `--client api` where its token comes from. See [Forge accounts](#forge-accounts). _Added in 2.5_ |
| `admin forge edit NAME` | Changes the flags given on an account: its API address, `ca_file`, client or token source. See [Forge accounts](#forge-accounts). _Added in 2.5_ |
| `admin forge list` | Each account: forge, web address and whether it is the host's default. _Added in 2.5_ |
| `admin forge remove NAME` | Forgets an account. Refused while a repo names it. _Added in 2.5_ |
| `admin forge test NAME` | Checks a `client: cli` account's `gh` or `glab` sign-in, or a `client: api` account's token: who it signs in as, its scopes, expiry and the repos it sees. Exits 1 on a failure. _Added in 2.5_ |

## Forge accounts

_Added in 2.5_

An account in `forges.yaml` records which forge a host runs and its web address, so `kraft repo connect` doesn't ask about a self-hosted host whose name doesn't say. A `client: cli` account holds no token: `gh` and `glab` keep their own sign-in. A `client: api` account reads one from a source; see [forges.yaml](/reference/configuration/forges). A repo names an account with `forge_account`.

### Add, edit, list, remove and test an account

`add` takes a name (lowercase letters, digits, `.`, `-` and `_`, starting with a letter or digit, so a web host such as `code.corp.example` works), `--forge github|gitlab` and an `https://` `--web-url`. `--api-url` must share the web address's origin (host and port). `--default-for-host` makes the account the one repos on that host use unless they name another; two such accounts for one host are refused.

`remove` is refused while a repo names the account. A default account no repo names is removed anyway, and items pinned to it stop at their next forge node. `test` exits 1 when it fails.

`--token-from` takes `git-credential`, `env:NAME`, `file:PATH` or `command:CMD`. `--token-stdin` reads the token from standard input, never from an argument, and the server writes it to a private file. Either one implies `--client api`, and `--client cli` with one is refused. `--kind` says what the token is (default `unknown`); `edit --kind` with no token flag is refused.

`--ca-file PATH` names the CA that signs a self-hosted forge's certificate, for the API client only. Without it Kraft trusts what git trusts for that address (git's `http.sslCAInfo`), then the system's CAs. TLS verification is never turned off.

`edit` changes only the flags given. `--client cli` drops the account's token and `ca_file`. A pasted token's file is deleted once the account stops reading it. If the paste fails, `edit` puts the changed fields back.

The API also refuses, with `403`, a write naming an `env` variable or `file` another account reads, or another account's pasted file; edit `forges.yaml` by hand to share one.

A `command` source runs code as the server's user, so the server's API refuses it. The CLI writes it into `forges.yaml` on the server's machine and reloads; elsewhere, or inside a worker, it refuses. A reload that refuses the file, or after which the server doesn't list the account, puts the old text back and exits 1.

The same goes for changing an account that already reads a `command` source: `edit` with `--token-from env:…`, `file:…`, `--token-stdin` or `--client cli` writes `forges.yaml` on the server's machine too, because the API (and so Settings) refuses to replace a command. A `--token-stdin` token is written to a private file under `$KRAFT_HOME/secrets/`, as the API does. Nothing is changed when the token is refused (too short, or holding whitespace).

On a `client: cli` account, `test` runs `gh auth status` or `glab auth status` in the server for the account's host, without its port. On a `client: api` account it probes the token and never runs the CLI. Every verb asks the server, which owns the file, except a command source, which the CLI writes on disk as above.
