Wrote `.engineering/specs/1900d827bb0b49e68bcc619cb661c9fc.md` covering
Kraft-g2pi, Kraft-7co4 and Kraft-ao6. No production code changed.

What I read before designing: `src/kraft/analytics.py` (`compute`, the sessions
loop), `frontend/src/views/Analytics.tsx` + `types.ts` + `Analytics.test.tsx`,
`src/kraft/reattach.py`, `src/kraft/adapters/subprocess.py::run_task`,

Decisions made rather than asked:

- New `totals["work_items_run"]` (distinct items with a session) as the Cost
  tile's divisor, label "per work item run"; `work_items` keeps meaning every
  item. A still-running item counts — the existing `cost_complete` floor caveat
  already replaces the subtitle while a run is in flight, so no extra rule.
- `reattach._exit_from_file` takes a `log_path` and passes
  `usage.read(log_path, result_path)`; `_adopt`'s SELECT grows a column.
- `kl.since()` compares `(stamp, walk position)` pairs instead of bare stamps.

One correction worth flagging for implementation: the smaller fix for
Kraft-ao6 — relax `<` to `<=` and exclude the record's own stamp — is wrong. I
prototyped it and the bead's own reproduction returned `[a: 0, b: 0]`: the first
of the tied pair loses its time. The spec carries the pair-comparison version,
prototyped against a scratch copy of `kl.py`: 148/148 plugin tests pass and the
reproduction gives `[a: 300, b: 0]`. The prototype was reverted; the tree
carries only the spec.

The brief's shared fixture does not exist and the spec says so: `kl.py` is
stdlib-only and its tests cannot import `kraft`, and the analytics and reattach
tests sit on opposite sides of the write. Each test extends the fixture already
in its own file.
