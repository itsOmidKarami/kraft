## Kraft-g2pi — cost per work item divides by items that ran

`src/kraft/analytics.py`: `totals` now carries `work_items_run` (seeded 0,
set to `len(item_node_rounds)` — exactly the items with a `worker_sessions`

new field, relabelled "per work item run". Tests: two new cases in
`tests/test_analytics.py`, fixture + assertion updated in
`Analytics.test.tsx`.

## Kraft-7co4 — adopted session records no usage

`src/kraft/reattach.py`: `_exit_from_file` grows a `log_path` parameter and
calls `usage.read(log_path, result_path)`, passing the result positionally
into `store.session_exited`. `_adopt`'s SELECT grows `log_path`; the
`reattach` loop's call passes `r["log_path"]` (already in hand via `SELECT
*`). Two new tests in `tests/test_reattach.py` cover both call sites
(resolved-from-file and the live-adoption path, which needed the SELECT
fix to catch).

## Kraft-ao6 — kraft-lite since() ties

`plugins/kraft-lite/kl.py`: `since()`'s `events` list now pairs each stamp
with its record's position in the walk (`order = {r["id"]: i for i, r in
enumerate([epic, *walk])}`), and comparisons use that `(stamp, position)`
tuple as the sort/compare key so two nodes sharing a `BD_TIME` second order
deterministically instead of the later one finding nothing earlier and
falling back to the epic. Docstring's ponytail note updated to state the
same-second case as a known, deliberate limitation rather than an
oversight. One new test in `plugins/kraft-lite/tests/test_records.py`.
