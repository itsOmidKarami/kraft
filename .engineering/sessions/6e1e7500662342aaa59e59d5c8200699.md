# Kraft-qlsf: Submodule merge requests (design 06 §2-§3a)

Followed the attached spec (`docs/superpowers/specs/2026-09-10-submodule-merge-requests-design.md`)
and plan (`docs/superpowers/plans/2026-09-10-submodule-merge-requests.md`) task-by-task.

## Blocker found and resolved

The work item's brief said it depends on Kraft-cppp (commit identity pinning in
`ensure_worktree`) landing first, and the plan explicitly assumes
`_pin_identity(repo, worktree, work_item_id)` already exists in `builtins.py`. It
did not — `grep` found no trace of it, and the Kraft-cppp bead was still open with
no spec/plan files in this worktree. Rather than stop, I implemented Kraft-cppp's
scope first (small, unambiguous from its own bead description) as a prerequisite
commit, then built Kraft-qlsf on top of it — still one branch, one MR, for this
work item only.

## What shipped, one commit per plan task

1. `_pin_identity` in `builtins.py`, called from `ensure_worktree` right after
   `git worktree add` succeeds — resolves `user.name`/`user.email` from the source
   repo and pins them into the new worktree's own config; missing either raises
   `RuntimeError` naming the repo and the missing key.
2. **Task 1** — `work_item_repos` table (schema v19), `store.add_repo` /
   `repos_for` / `update_repo_state` / `merge_rank_order`. `repos_for` now reads
   the new table instead of deriving a placeholder from the `submodules` JSON
   column + whether `merge` completed. Accepted trade-off: the repos panel is
   empty between intake and `ensure_worktree`, not populated immediately —
   updated the one existing test that assumed the old preview behavior.
3. **Task 2** — frontend `repoGlyphStatus` so a `"failed"` repo renders failed,
   not pending.
4. **Task 3** — `_assert_clean` now passes `--ignore-submodules=none`, so a
   submodule under `ignore = all` with uncommitted/unpushed commits is caught
   instead of reading as clean (the actual mechanism of the real failure).
5. **Task 4** — `ensure_worktree` resolves declared submodules only (never
   blanket), `git submodule update --init` on just those paths, checks the
   item's branch out inside each, pins identity, writes `work_item_repos` rows.
6. **Task 5** — new `on.repos.scan` builtin (`scan_submodules`), wired into the
   `implementation` node right after `on.implementation.start` in
   `default.yaml`: `git submodule status`'s `+` prefix catches a submodule the
   agent touched but nobody declared, adds a row, recomputes root's rank.
7. **Task 6** — `forge.run_task` extracted its handler `match` block into
   `_run_one`, now loops over `work_item_repos` rows deepest-first (or once,
   unchanged, when there are none). Added `_assert_submodules_covered` as the
   open_mr-time backstop. `FakeForge` needed to become repo-aware (`_opened_repo`)
   since two repos sharing a branch name — the design's own contract — used to
   let one repo's `find_mr` "discover" the other's fake MR.
8. **Task 7** — root is dropped from the per-repo loop when it has no commits of
   its own or policy is `skip`; its pointer-bump commit (policy `bump`, every
   submodule merged) is pushed directly to root's default branch after the merge
   node's loop, never through a merge request, per the plan's recorded design
   correction (no submodule has merged yet at `open_mr` time).
9. **Task 8** — standing regression test reproducing the real item's shape
   end-to-end via `executor.run`.
