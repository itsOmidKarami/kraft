task-by-task, all 7 tasks, each committed separately:

## Deviation from the plan

`frontend/src/palettes.order.test.ts` as written in the plan searched for the
bare substring `[data-mode="light"]`, which also appears inside palettes.css's
own top-of-file comment (describing the cascade-order rule the test exists to
enforce) — so the substring search matched the comment first and the test
failed against the plan's own correctly-ordered CSS. Fixed by searching for
the actual selector `:root[data-mode="light"] {` instead. Same intent, no
change to palettes.css itself.
