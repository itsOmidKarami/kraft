# Kraft-dwt — fence the editor-launch routes, gate the HTTP perimeter

## The problem

`_launch_editor` (`src/kraft/api.py:1351`) runs `subprocess.Popen([exe, path], start_new_session=True)`
on the machine hosting the API. Two routes reach it:

- `POST /documents/{doc_id}/open` (`api.py:1373`) — path built as `Path(doc["repo"]) / doc["path"]` from the index.
- `POST /work-items/{wid}/open-worktree` (`api.py:1180`) — path is `run_dirs.worktrees/<wid>`.

Callers: the SPA (`frontend/src/components/DocumentModal.tsx:112`,
`frontend/src/views/WorkItemDetail.tsx:358`) and the CLI (`kraft doc --open`,
`kraft open` → `client.py:365,378`). Not exposed over MCP.

What is *already* fine, and should not be re-fixed:

- The editor argv is an allowlist, not caller-supplied: `_EDITORS` (`api.py:1335`) maps
  four ids to fixed argv, anything else is a 400. There is no shell, no argument splicing.
- Cross-site drive-by against these two routes is already blocked by their JSON body.
  Verified against FastAPI directly: a cross-origin "simple" request (`text/plain`,
  form-encoded, or bodiless) that needs no preflight is rejected 422 before the handler
  runs, and a real `application/json` POST is preflighted, which fails because the app
  sets no CORS headers.

What is not fine:

1. **Any authenticated client anywhere can start a process on the server host.** Kraft
   supports a non-loopback bind (`cli.py:60`, `access.yaml`) behind *one* shared password,
   with no notion of users or roles. Whoever has that password gets a remote
   process-launch primitive plus a window opened on someone else's desktop. The route
   docstrings already say it is "local-only by nature"; nothing enforces that.
2. **The perimeter trusts a claim about the bind, not the socket.**
   `app.state.bound_host = os.environ.get("KRAFT_HOST") or access["bind"]` (`api.py:172`)
   and `_requires_auth` (`api.py:299`) keys off that string. `uvicorn kraft.api:app --host 0.0.0.0`
   — or any launch that widens the bind without going through `cli._bind` — serves the whole
   API, unauthenticated, to the LAN, because `access.yaml` still says `127.0.0.1`.
3. **No Origin or Host check on HTTP.** `_origin_ok` (`api.py:1427`) exists and is applied to
   `/ws/events` only. So:
   - the mutating routes that take *no* JSON body — `POST /work-items/{wid}/gates/{gate}/approve`
     (`api.py:931`), `/abandon` (`api.py:1079`), `/pause` (`api.py:1098`), `POST /index/rescan`
     (`api.py:1406`) — are reachable as no-preflight cross-site form POSTs from any page the
     operator visits. On the default loopback instance auth is off, so no cookie is needed;
     with auth on, `samesite="lax"` (`api.py:2128`) withholds the cookie. Work-item ids are
     unguessable, which limits this to `/index/rescan` in practice — but "the ids are secret"
     is not a control.
   - DNS rebinding is unmitigated and *is* the serious one: a page on `evil.com` whose DNS
     flips to `127.0.0.1` becomes same-origin with the local Kraft, can read every response
     (ids included) and then drive any route, including editor launch.

## Approach

Three changes, all in `src/kraft/api.py`, no new dependencies and no new config.

### 1. One helper: is the peer actually local?

```python
def _client_is_local(request: Request | WebSocket) -> bool:
    """True when the peer address is a loopback IP. Unknown/unparseable → False."""
    client = request.client
    try:
        return client is not None and ipaddress.ip_address(client.host).is_loopback
    except ValueError:
        return False
```

Fails closed. Note that uvicorn's proxy-header handling is on by default with
`forwarded_allow_ips="127.0.0.1"`, so a reverse proxy on the same box surfaces the real
client IP here (correct), and a forged `X-Forwarded-For` from a remote peer is ignored
because that peer is not in the trusted list. Both directions of that only ever make this
stricter.

### 2. Editor launch: refuse a non-loopback caller

`_launch_editor` takes the request and returns **403** (`"this server only opens editors
for a client on its own machine"`) when `not _client_is_local(request)` — before `shutil.which`,
before `Popen`. Chosen over refusing on `bound_host not in LOOPBACK`: a `0.0.0.0` bind is
exactly the case where the operator at the keyboard should still get their editor, and the
per-request check is the same number of lines.

The SPA needs no change: `openIn` (`DocumentModal.tsx:110`) falls back to
`vscode://file/<path>` and shows its note on *any* rejection, and `WorkItemDetail` already
hides "Open worktree" unless `onServerMachine()` (`WorkItemDetail.tsx:23`).

Same function also gets a path containment check for `/documents/{id}/open`, where the path
is assembled from index rows rather than derived from a run dir: resolve it and require the
repo root among its parents, else 400. Three lines, and it closes the whole class of
"an absolute or `../` index path escapes the repo" without anyone having to argue about
whether the ingester can ever produce one.

### 3. One perimeter middleware, ordered before `_authenticate`

```python
@app.middleware("http")
async def _perimeter(request, call_next): ...
```

Three rules, in this order:

| Rule | Condition | Response |
|---|---|---|
| Bind mismatch | peer is not loopback **and** no `password_hash` is set | 403 `"this server is configured for a loopback bind; refusing a request from <ip>"` |
| Rebinding | `sec-fetch-site` header present (i.e. a real browser) **and** the `Host` hostname is neither in `_LOCAL_HOSTS` nor equal to `bound_host` | 403 |
| Cross-site write | method is not GET/HEAD **and** an `Origin` header is present **and** its hostname is not in `_LOCAL_HOSTS` **and** its `netloc` ≠ the `Host` header | 403 |

Notes on each, because each has one non-obvious edge:

- **Bind mismatch** is the fail-closed half of point 2. Where a password *is* set, the
  existing `_authenticate` already demands it; `_requires_auth` additionally gains
  `and _client_is_local(request)` to its loopback short-circuit, so a remote peer reaching a
  server that believes it is on loopback must still log in.
- **Rebinding**: keyed on the presence of `sec-fetch-site` rather than applied
  unconditionally, because only a browser can be rebound, and every non-browser client —
  CLI, MCP, `httpx`, `TestClient`, `curl` — would otherwise need a Host allowlist entry for
  no security gain. Browsers older than the Fetch Metadata rollout (pre-2020) bypass this;
  acceptable, and stated here rather than discovered later. `changeOrigin: true` in
  `frontend/vite.config.ts:26` rewrites Host to `127.0.0.1:8765`, and the Playwright suite
  runs against `http://127.0.0.1:8765`, so both pass.
- **Cross-site write** is `_origin_ok` widened by one clause so that a LAN instance serving
  its own SPA (`Origin: http://192.168.1.5:8765`, `Host: 192.168.1.5:8765`) is not locked
  out of its own board. Dev keeps working: the vite proxy forwards the browser's
  `Origin: http://localhost:5173`, whose hostname is in `_LOCAL_HOSTS`.
  `/ws/events` keeps calling `_origin_ok` directly; websockets do not run HTTP middleware.

### Consequence for the test suite

`TestClient` reports a peer of `testclient`, which is not an IP, so under fail-closed rules
every existing API test becomes a non-loopback caller. The 21 `TestClient(...)` constructions
across `tests/` pass `client=("127.0.0.1", 54321)`. Mechanical, and it is what lets the new
tests express "a LAN client" as `client=("10.0.0.5", 54321)` rather than by monkeypatching.

## Alternatives rejected

- **Drop both routes, rely on the SPA's `vscode://` fallback.** It only knows VS Code, while
  the server allowlist covers Cursor, Zed, Obsidian and the OS handler; and it deletes
  `kraft open` / `kraft doc --open`, which `CLAUDE.md` documents and which are the whole point
  when you are sitting at the machine. Local launch is a feature; the bug is that it is not
  local.
- **Tighten the editor allowlist further.** The allowlist is already there and is not what is
  broken — the residual risk is the fact of launching a process for a remote caller, which no
  allowlist addresses.
- **Refuse when `bound_host` is non-loopback.** Punishes the operator at the keyboard for the
  bind, and keeps trusting the same config string that is unreliable in the first place.
- **A CORS middleware / a CSRF token.** More machinery than an Origin comparison, and a token
  needs somewhere to live for the CLI and MCP clients that hold a bearer token instead.
- **Per-user accounts so "who may launch" is answerable.** The real fix for a shared-password
  product, and far beyond this item; loopback-only is the honest interim answer.

## Out of scope

- Any change to the single-shared-password model, sessions, or the MCP bearer token.
- Removing or rewriting the SPA's editor UI beyond what falls out of a 403 (none needed).
- Rate limiting, audit logging of launches, sandboxing the spawned editor.
- `_os_open()` opening a document with the OS default handler: with a loopback-only caller
  this is exactly what the user typing `open <file>` gets, and no more.
- The `/health` bind disclosure (`api.py:2172`) — deliberate, the login screen needs it.

  which is the non-browser client contract.
- `test_the_websocket_origin_check_is_unchanged` — `/ws/events` still closes 1008 on a foreign
  origin (guards against the middleware being mistaken for websocket coverage).
