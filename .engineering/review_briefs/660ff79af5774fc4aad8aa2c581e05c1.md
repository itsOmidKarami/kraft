## What changed

18 files, +2435/-2 (docs + `dev/gen_palette.py` account for most of the
line count; the rest is app code):

- `dev/gen_palette.py` — OKLCH hue-rotation generator producing the 5 palette
  token sets, plus `tests/test_palette_contrast.py` asserting WCAG AA contrast
  for every palette × mode combination.
- `frontend/src/palettes.css` — 5 palettes (Nocturne, Rose, Forest, Amber,
  Slate) × light/dark token overrides. `nocturne.css`'s divider color was
  refactored to `var(--color-text)` so it participates in the same override
  cascade. `palettes.order.test.ts` pins the CSS cascade order (light block
  before dark block) so a future edit can't silently invert precedence.
- `src/kraft/api.py` — `GET`/`PUT /theme`, backed by `theme.yaml`, mirroring
  the existing `/policy` pattern.
- `frontend/src/theme.ts` — `PALETTES` catalog, `applyTheme()`, and a
  `matchMedia` listener for `"system"` mode that's torn down when the mode
  changes away from `"system"`.
- `main.tsx` — applies the saved theme in `boot()`, before first render.
- `frontend/src/views/Settings.tsx` — new Appearance section: 5 swatch chips
  + a Light/Dark/System segmented control, live preview on click, Save/Discard
  via the existing `SaveRow` pattern.

## Deviation from the plan

`palettes.order.test.ts`, as the plan wrote it, substring-searched for
`[data-mode="light"]`, which also occurs inside `palettes.css`'s own top-of-file
comment describing the ordering rule — so the test's own search matched the
comment before the real selector and failed against correctly-ordered CSS.
Fixed by matching the actual selector `:root[data-mode="light"] {`. Same
intent as planned, no change to `palettes.css` itself. One other deviation:
a plan-suggested local named `l` in the generator was renamed to `lms_l` to
satisfy this repo's `ruff` E741 rule — lint fix, not a behavior change.
