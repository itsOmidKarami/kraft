## What changed

Single commit (`acab6c0`) adds a nullable `work_items.description` column and
threads it through every door, matching the plan task-by-task:

- **Schema/store**: `db.py` v12→13 migration, `SCHEMA_SQL`; `store.create_work_item(..., description=None)`; `description or None` collapses `""` to `NULL`.
- **The payoff**: `executor._brief()` — title alone when no description, else `"{title}\n\n{description}"` — replaces the bare title at the one line (`executor.py:~304`) that builds every agent's task instruction.
- **beads, both directions**: `adapters.beads.intake` writes `description` to `-d` (falls back to the orchestrator string); `beads.ready()` now projects `description` instead of discarding it, so auto-intake carries a bead's own brief through `intake.py`.
- **API**: `NewWorkItem.description`, list + detail payloads carry it, new `PATCH /work-items/{wid}` — narrow, single-field, emits `work_item_description_edited`, 404s on unknown id.
- **CLI/client/MCP**: `--description` flag, `client.create_work_item(..., description=)` (key omitted rather than sent as `null`), MCP tool docstring telling agents what the field is for.
- **render.kv**: multi-line values now indent continuation lines to the value column instead of running to column zero — the description is the first field that can legitimately contain a newline.
- **UI**: `IntakeModal` gets an optional description textarea; `WorkItemDetail` gets a `Description` component (view / "Add a description" / inline edit-and-save via the new PATCH, rehydrating the item on save).
- Skills (`spec`, `review-brief`, `init.py`'s `handoff`) and docs (CLAUDE.md, AGENTS.md, README.md, `02_orchestrator_core.md`) updated to talk about "the brief" instead of "the title".

## One finding: `btn-quiet` is not a real CSS class

`WorkItemDetail.tsx`'s new `Description` component uses `className="btn btn-quiet"` for both the "Add a description" and "Edit" buttons. `btn-quiet` does not exist anywhere in `nocturne.css` or `styles.css` — the only defined `.btn-*` variants are `btn-primary`, `btn-secondary`, `btn-ghost`, `btn-icon`, `btn-block`. The plan's own Task 11 step 4 anticipated exactly this ("If `btn-quiet` is not an existing class in `styles.css`, use whichever secondary-button class the file already uses — do not invent a new one"), and the implementer used it anyway without checking.

Effect is cosmetic, not functional: the buttons still render with the base `.btn` border/padding, just without whatever secondary/ghost treatment was intended, and no test caught it since tests assert on role/name, not class. I'd have filed a bead for this and fixed it inline (swap to `btn-ghost`, which is the closest existing secondary style), but held off touching code that isn't mine to fix at this gate — flagging it here instead.
