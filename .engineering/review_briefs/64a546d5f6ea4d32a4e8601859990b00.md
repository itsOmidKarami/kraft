## What changed

Closes the loop on five beads (Kraft-82gz, -85wk, -8iw6, -vwv, -xwen) that
together made intake attachments unusable from an agent.

- **`src/kraft/api.py`** — `NewWorkItem` gains `cwd: str | None`.
  `_validated_attachments` now resolves a path against up to two roots: the
  registered repo (always) and, only when `cwd`'s `--git-common-dir` matches
  the repo's, `cwd`'s worktree toplevel. A path found under the second root
  gets an extra `source` field (absolute path) on the stored attachment dict.
  With no `cwd`, behaviour is byte-for-byte what it was (browser callers
  unaffected).
- **`src/kraft/client.py` / `cli.py` / `mcp.py`** — `create_work_item` now
  threads `attachments` and `cwd` through. CLI gets `--spec PATH` / `--plan
  PATH`; MCP's `create_work_item` gets `attachments: list[dict] | None`.
- **`src/kraft/builtins.py`** — new `_commit_paths(worktree, paths, message)`:
  stages and commits exactly the named paths, `--no-verify`, no-ops on
  nothing-to-stage or on git failure (logs a warning, doesn't raise).
  `_copy_attachments` now reads from `attachment["source"]` when the
  validator set one, and commits whatever it actually copied in one commit
  after the loop — so a copied-in attachment is no longer untracked when
  `open_mr`'s dirty-worktree guard runs.
- **Kraft-vwv** — recorded as a decision, not code: an attachment belongs to
  the item's root worktree only; a `cwd` inside a submodule contributes no
  root because its common-dir differs from the superproject's. Enforced by
  the same `_git_common_dir` check 85wk added, not by new logic.
- **Kraft-xwen** — only the primitive (`_commit_paths`) landed here, by
  explicit scope decision in the spec. Rewriting doc-node prompts/templates
  to call it instead of shelling out to `git commit` is deliberately left for
  a follow-up (needs Kraft-4aec4d47, per-node `allowed_tools`, first).
- **866258e** is a self-inflicted-regression fix, not incidental scope: the
  attachments work re-added `chain_definition` to `client.get_work_item`'s
  keep tuple, undoing an existing trim (Kraft-9rs) and breaking
  `test_get_work_item_names_the_next_node`. This commit drops it back out and
  repoints the attachment test at the untrimmed item instead.
