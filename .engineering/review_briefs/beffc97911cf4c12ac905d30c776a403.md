## What changed

Single commit, `src/kraft/api.py` (`_authenticate` middleware, ~line 392):

- Bypass condition gained a fourth clause: `(request.method == "GET" and not
  _is_api_path(request.url.path))`. Previously the only way an unauthenticated
  GET reached the SPA shell was a client-sent `Sec-Fetch-Dest: document`
  header — clients that omit/strip it (privacy browsers, in-app webviews,
  proxies) got a raw 401 on `GET /` instead of the login page.
- Deleted the now-dead inline `Sec-Fetch-Dest` check + manual
  `FileResponse(dist / "index.html")` block that the widened bypass makes
  unreachable — `call_next` now falls through to the existing catch-all
  `spa()` route, which already serves `index.html` publicly for any non-`/api`
  GET (same trust level already granted to static assets).
- Comment above the bearer-check explaining route ordering updated to match.

Test changes:
- `tests/test_api_perimeter.py`: new test, unauthenticated `GET /` with no
  `Sec-Fetch-Dest` header → 200 + shell body (previously would have been 401).
- `tests/test_settings_api.py`: existing traversal test (`GET /../pyproject.toml`)
  asserted `status_code != 200`; now asserts `200` with shell body specifically
  (`<!doctype html>`), since that path legitimately falls into the same
  non-/api-GET bypass now — the assertion had to change to keep checking what
  it actually cares about (no file leak), not just "not a leak status code".

No changes to `/api/*` routes, non-GET verbs, or `_spa_navigation` middleware
— all still fully gated, matching the plan's stated out-of-scope list.

## What I'm unsure about

- The traversal test change means `GET /../pyproject.toml` now returns 200
  with the SPA shell instead of a non-200. That's intentional and matches the
  new trust model (any non-/api GET = shell, same as a static asset), but a
  reviewer should sanity-check that no other file-serving path relies on that
  traversal request getting rejected outright rather than shell-shadowed.
  Nothing in this diff suggests one does.
