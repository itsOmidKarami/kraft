## What changed

Two beads, one branch, both already implemented when this session picked them up; this session verified, then committed the work (it was sitting uncommitted in the worktree) at `007e330`.

**Kraft-bo98 — diff view collapse** (`frontend/src/components/DiffModal.tsx`, `.test.tsx`, `styles.css`):
GitLab-style per-file collapsible sections replace the single continuous scroll. Each file gets a header row (path + `+n -n`) that toggles its hunks; large/generated files collapse by default. The old separate "New files (content not shown)" list is folded into the same per-file model instead of being a second mental model for the reviewer.

**Kraft-29a0 — log modal "Failed to fetch"** (`frontend/src/components/LogModal.tsx`, `.test.tsx`, `frontend/src/api.ts`, `.test.ts`, `src/kraft/api.py`, `tests/test_api_retry_open_log.py`):
- `LogModal` now clears a stale error (`setError(null)`) when `sessionId` changes, so an error from a previous session no longer lingers next to a later successful load.
- It stops asserting "following" once the SSE stream has actually ended.
- `api.ts`'s `req()` now names the failing server in its error on transport failure, instead of the browser's generic "Failed to fetch".
- `src/kraft/api.py` now follows pending (not-yet-running) sessions correctly, matching the frontend change.

## What was deliberately left out

- The root-cause theory in Kraft-29a0's description — that HTTP/1.1's 6-connection-per-origin cap plus persistent SSE streams starves an ordinary `fetch()` — was **not** fixed here; only the two visible symptoms (stale error, false "following" claim, and unnamed transport failure) were addressed. If that's the actual cause, the fetch can still fail under enough concurrent open logs.
- Two perf/scope follow-ups surfaced while specifying this work are already filed as separate open beads, not folded into this branch: **Kraft-21jy** (SSE tail re-reads the whole log file every 0.4s, O(n²) over a session) and **Kraft-9r4q** (dev vite proxy missing `/steering`, `/intake`, `/notify`).
- **Kraft-nceo** (split the diff view into landed/committed vs. in-flight/uncommitted, P2) rides on this same DiffModal work but is explicitly scoped as a separate item, not done here.
