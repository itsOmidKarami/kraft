## What changed

`src/kraft/index/service.py`:

- `_attachment_docs` no longer silently skips an attachment that has no
  `documents` table row (i.e. hasn't been indexed via `git ls-files` on the
  registered main checkout — true for anything committed only on the item's
  own unmerged branch). It now calls a new `_synthesize_attachment_doc`,
  which reads the file straight from the item's own worktree (same
  `_summary_path` resolution `ingest_session_summary` already uses) and
  shapes a dict with the same keys a real indexed row has, plus
  `document_id: f"attachment:{work_item_id}:{attachment['kind']}"`.
- `get_document` recognizes that `attachment:` id prefix and routes to a new
  `_get_synthetic_attachment_document`, which re-reads the worktree file
  for content rather than querying the `documents` table.

`tests/test_index_service.py`: new tests cover both — an attach-based item
shows its docs via `GET /work-items/{id}/documents` before merge, an
already-indexed attachment isn't duplicated by the fallback, and content
fetch through the synthetic id works.

Net effect: a work item created with `--spec`/`--plan` now shows those
documents in the UI's docs tab immediately, instead of only after the
item's branch merges to main and gets rescanned.

## What I found, not fixed

`POST /documents/{doc_id}/open` (the "open in editor" button) builds its
path as `Path(doc["repo"]) / doc["path"]`, not through `_summary_path`. For
a synthetic `attachment:` doc that path lives in the item's own worktree,
not the main repo checkout — pre-merge, that file usually doesn't exist at
that path in main repo, so clicking "open" on an unmerged attachment will
hand the editor a missing or wrong path. The content-view path (`GET
/documents/{id}`) was fixed to re-resolve via the worktree; the open-editor
path was not, and the plan's step 2 only scoped the content endpoint.
Filed as Kraft-2jy6 (P2) rather than fixed here — it's a real gap but
outside this work item's plan, and fixing it changes a different route's
authorization/path-validation logic than what this diff touches.
