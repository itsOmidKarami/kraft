## What changed

All three bugs fixed in one commit, `src/kraft/adapters/forge.py` (+190/-73, `tests/test_forge.py` +113):

- **`_wait_for_ci`** (new): factors the log-formatting + mergeable/state check that `ci_poll` used inline out into a shared helper.
- **`case "merge"`** in `_run_one`: before calling `forge.merge()`, now calls `_wait_for_ci` with the same timeout/interval `ci_poll` uses. Fixes Kraft-266b (human_review's own commit — the review brief itself, or any fix a person makes — re-arms a required-pipeline rule on a head `mr_checks` never watched) and Kraft-x10m (the old 300s `MERGE_VERIFY_TIMEOUT` wait was only for the *merge landing*, not for a freshly re-triggered pipeline to finish; a pipeline recreated by `mr_sync`'s push could still be running well past that window).
- **`GlabCli._merge_state`**: now checks `state == "merged"` ahead of `detailed_merge_status`/`merge_status`, and falls back to `find_mr` if `glab mr view` itself raises. Fixes Kraft-v6ci — an MR merged out-of-band (someone merges via the GitLab UI while this node polls) previously errored instead of being read as done, because a merged MR may carry neither merge-status field, and `glab mr view` can fail once the MR record's polling context is invalidated.
