## What changed

Nine fixes on one branch, per `.engineering/plans/af0fb78ef85c474f9ea11c1ec1f1010c.md`, all landed in commit `87d12dc`:

- **Kraft-97e** — `config.probe_repo` now resolves a linked worktree to its main checkout via `git rev-parse --path-format=absolute --git-common-dir`, falling back to `--show-toplevel` when the common dir isn't named `.git` (keeps submodules on their existing behavior). Fixes `ensure_repo()` / `kraft connect` registering a worktree as its own repo.
- **Kraft-sws6** — new `kraft disconnect [PATH]` verb + `client.disconnect_repo()`, calling the existing `DELETE /repos` endpoint. Along the way, fixed `client._delete`'s `path` parameter, which collided with the `path=` kwarg `disconnect_repo` passes it (a real `TypeError`, caught by the plan's own tests).
- **Kraft-5lpl** — new `kraft retry [ID] [--steer]` verb + `client.retry()` + a `retry_work_item` MCP tool, the only supported door back onto a `needs_human` stop.
- **Kraft-owea** — `render.table` / `event_line` take `headers=False` so `kraft events -f` prints one header instead of one per streamed row.
- **Kraft-tom2** — `events -f --json` now emits NDJSON (one flushed object per line) instead of a pretty-printed array per frame, matching the `logs -f` contract documented in CLAUDE.md.
- **Kraft-t5s9** — `client._target` renamed to public `client.resolve_work_item`, since `cli._cmd_events` needs the resolved id outside `client.py`.
- **Kraft-9rs** — `client.get_work_item` now returns `next_node_id` (NULL current node → node zero, same rule as `resume`); `/kraft:status` skill added to `init.SKILLS` (fourth entry, alongside handoff/board/gates) — a phase-line jq one-liner plus a bounded `events -f` follow that ends itself on completion/abandonment.
- **Kraft-ldeq** — `BudgetCard` always offers retry now that Kraft-bzwi removed the 409 a loopless node used to hit; copy still warns of re-breach. Three tests that pinned the old gate were deleted, one renamed to assert the new behavior.

Two follow-up commits (`d43bdae`, `0cb4df4`) landed on the same branch afterward, fixing `Kraft-c09h` (MRs titled by branch UUID instead of the work item title, and a stale MR description) — this is the human_review gate's own self-repair on this work item's MR, not part of the requested batch, but it's on the branch and tested.
