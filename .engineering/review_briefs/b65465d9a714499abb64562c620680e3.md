## What changed

- `src/kraft/builtins.py`: new `refresh_worktree_base()` — rebases a paused/retried
  work item's worktree onto current `HEAD` of the connected branch. On rebase
  conflict, aborts the rebase, leaves the worktree clean, and marks the item
  `needs_human` with a `conflict` reason instead of leaving it stuck mid-rebase.
  Skips the rebase entirely once the branch has already been pushed (an MR is
  open), to avoid rewriting pushed history.
- `src/kraft/api.py`: wires this into the resume and retry code paths (`api:
  rebase worktree onto current HEAD on resume` / `on retry`, commits b26b4c9,
  52255e8).
- `src/kraft/store.py`: small supporting change (8 lines) for the above.
- `tests/test_builtins.py`, `tests/test_pause_resume.py`,
  `tests/test_api_retry_open_log.py`: new/updated coverage for the rebase,
  conflict, and already-pushed-skip cases.

## Merge into origin/main

The branch conflicted with `origin/main` in `src/kraft/builtins.py`: main's
Kraft-qlsf submodule work landed a new function at the same insertion point as
`refresh_worktree_base`. Confirmed via `git merge-tree` the conflict was purely
additive on both sides (no logic overlap), then merged `origin/main` into this
branch with a plain merge commit (62109ae) — no rewrite of already-pushed
history. Kept both functions. Pushed.
