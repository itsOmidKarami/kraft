# What CI said

Green, on the 8th attempt at `mr_checks`. The only red job across all eight
retries was the pre-existing flaky search-overlay test (Kraft-ica3, now
documented and bumped to P1) — timing-sensitive, running on a self-hosted
runner sharing the machine with this session's own dev work. Two real
regressions surfaced along the way and were fixed on this branch, not worked
around:

- `CurrentNodePanel` left every task group collapsed when `current_node_id`
  named a node with no session yet (a normal mid-run state) — fixed with a
  fallback to the most-recently-active group (`2551a87`).
- `lifecycle.spec.ts` used `.first()`, which grabbed the earliest (closed)
  group instead of the now-open one after that fix — changed the locator to
  `:visible` (`fa1b7d6`).

Both fixes have their own commits and were the actual product/test bugs, not
patches over the flaky test.

# What changed

Seven tasks, one commit per bead, per the plan (`.engineering/plans/3b47c...`):

- **nceo** — `review.read_change` gained a `head=` param. `GET /work-items/{wid}/diff`
  now returns in-flight (`HEAD..worktree`) at the top level and a separate
  `landed` object (`base_ref..HEAD`) for what earlier nodes already committed.
  `render.py`, `cli.py --name-only`, and `DiffModal` all split on this.
  `write_package` (what review *agents* see) is untouched — same combined
  range as before; only the human-facing diff is split.
- **yytk** — `Gate.tsx` now offers both "Review brief" (artifact) and "Review
  changes" (diff) at `human_review_approval` instead of the diff button
  silently replacing the brief.
- **39un** — verified already fixed by an earlier commit (`2bd5d59`, not this
  branch); no code change, existing GFM-table tests re-run as the check.
- **n9gw** — `CurrentNodePanel` groups every session by node in chain order
  instead of filtering to the current node only.
- **zxu4** — `EventTimeline` rows are titled `"<hook_point> <verb>"`, joined
  client-side from sessions already in the detail payload; exit rows show
  status/elapsed/finding count.
- **d2sq** — `forge.py`'s `open_mr` (create and reuse paths) emits an
  `mr_opened` event; the detail page links `!<number>` to the MR when that
  event exists for the item.

Verification from the implementation session: `just test` on the four touched
modules — 137 passed; `just test-ui` — 29 files / 279 tests including `tsc -b`;
`just lint` clean.

# Deliberate deviations from spec/plan (both flagged in-line, not silent)

- `kraft view diff --name-only` was extended to list landed paths too, beyond
  what the spec named (`render.diff_stat`/`diff_body` only) — leaving it alone
  would have dropped committed work from the CLI, the same bug nceo exists to
  fix.
- The timeline's exit row reuses the existing `elapsed()` helper (`4m`), not a
  finer-grained formatter matching the spec's illustration (`4m32s`) — one row
  didn't justify a second formatter.
- d2sq's MR link is keyed on the `mr_opened` event's existence rather than on
  current node membership in a set of MR-related nodes — correct exactly when
  an MR exists, and survives a rejection walking back to `implementation`.
