## Dedup

Kraft-3cz and Kraft-ibwj were the same defect (`_bd_cwd()` lets `bd` inherit
the server's cwd). 3cz closed as duplicate of ibwj (P1, live repro, full
call-site list). Kraft-7gy ("bd is a hard external dependency") designed and
implemented together with ibwj in the same spec/plan. All three closed.

## What changed

- **`executor.intake`** (`src/kraft/executor.py:124`): resolves the bd
  workspace as `bd_cwd or repo` — the work item's own repo, not the daemon's
  ambient cwd. `KRAFT_BD_CWD` still overrides, so an operator's existing
  workaround keeps working.
- **Degrade on bd failure**: `intake` now catches `OSError` (bd missing) and
  any other exception from `beads.intake`, logs it, writes a `bead_not_filed`
  event in the same transaction as the work-item row, and proceeds with
  `bead_id=None`. Intake no longer hard-fails when bd is absent or broken.
- **`beads.complete`** callers in `executor.run`/`resume` (3 call sites) are
  now guarded on `row["bead_id"]` — a bead-less item skips the close instead
  of calling `bd close None`.
- **`beads.intake`** (`adapters/beads.py`): drops `check=True`, raises
  `RuntimeError` carrying `proc.stderr` on non-zero exit, so the real bd
  error ("no beads database found") surfaces instead of "exit status 1".
- **`api.py`**: `create_work_item`'s 502 handler message changed from "bd
  intake failed" to "intake failed" (bd failures no longer reach it — they
  degrade instead); response now carries `bead_warning` when intake
  degraded, read back via a new `_bead_warning()` helper that queries the
  `bead_not_filed` event. `/beads/search`'s repo-less case now fans out over
  every connected repo with a `.beads` dir (dedup by bead id) instead of
  relying solely on `KRAFT_BD_CWD`.
- **`client.py`**: `create_work_item` passes `bead_warning` through to the
  CLI caller when present.
- **`db.py`**: comment only, documenting that new rows always set
  `bead_cwd`.
- **`doctor.py`**: new `bd` check, always `ok=True` (bd is optional, its
  absence doesn't fail `kraft doctor`'s exit code); repo check reports
  "no .beads" as ok, not a fault.
- **README**: `bd` moved from hard requirement to optional, one line
  explaining the degrade.
