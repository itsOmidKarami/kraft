# Kraft-dwt — review brief

## What changed

`src/kraft/api.py` (+`tests/test_api_perimeter.py`, new):

- **`_client_is_local(request)`** — new helper, reads the socket peer, fails
  closed on anything that isn't a parseable loopback IP (absent peer, or
  starlette's `TestClient` default of `"testclient"`).
- **`_requires_auth`** now requires the peer to be loopback *in addition to*
  the recorded bind. Closes the gap where `bound_host` says `127.0.0.1` (from
  `access.yaml`) but the process was actually started with
  `--host 0.0.0.0`, which never updates that value.
- **`_launch_editor`** (reached by `POST /documents/{id}/open` and
  `POST /work-items/{id}/open-worktree`) now 403s any non-loopback caller
  before it touches `subprocess.Popen`. This is the actual fix the work item
  asked for: chose the "refuse off-loopback" option, not allowlisting or
  dropping the routes. The existing `vscode://` fallback in
  `DocumentModal.tsx` catches the 403 the same way it already catches a 501.
- **`open_document`** gained a path-containment check: resolves the
  indexer-supplied `repo/path` and 400s if it escapes `repo`, but launches
  the *unresolved* path (macOS temp-dir symlinks would otherwise change what
  the editor opens vs. what the UI shows).
- **New `_perimeter` HTTP middleware**, declared after `_authenticate` so it
  actually runs first (starlette's middleware order is reverse-declaration —
  see the plan's own "read this before writing the code" section, and
  `test_the_perimeter_runs_before_the_spa_shell_middleware` pins it): bind
  mismatch (403 any remote peer when no password is set), DNS rebinding (403
  a browser request whose `Host` isn't a loopback name when bound to
  loopback), cross-site write (403 a state-changing request whose Origin
  doesn't match Host and fails the existing `_origin_ok`).
- **`ws_events`** restates the bind-mismatch rule directly, since HTTP
  middleware doesn't run for websockets — otherwise the live event stream
  would be the one route still open to a remote peer on a passwordless
  instance.
- Mechanical: 21 `TestClient(api.app)` constructions across 14 test files now
  pass an explicit loopback peer, since starlette's default peer isn't a real
  IP and the new checks fail closed on it.

`templates/registry.yaml` + `tests/test_templates.py` (committed separately,
by me, in this session — see below):

- `on.test.run` changed from `[pytest, -q]` to `[uv, run, pytest, -q]`. Bare
  `pytest` isn't on `PATH` in this project's subprocess environment; this was
  blocking `verify` for unrelated reasons across several prior sessions.

## What was deliberately left out

Stated in the plan itself (`.engineering/plans/…md`, "Spec coverage" table),
not discovered here: shared password / MCP token model, SPA editor UI,
rate limiting, `_os_open`, and `/health`'s bind disclosure are all untouched.
The rebinding rule (`_perimeter` rule 2) only protects a loopback bind — a
`0.0.0.0` instance gets no rebinding protection from this change, because a
Host-vs-`bound_host` check there would 403 every legitimate LAN browser.
That residual is the subject of the separate, still-open `Kraft-cdy` ("DNS
rebinding is unmitigated on a non-loopback bind").

The plan also documents two departures from the spec it was given: the
rebinding rule's condition was loosened from `Host not in _LOCAL_HOSTS and
Host != bound_host` to just `Host not in _LOCAL_HOSTS` (the spec's version
403s every real LAN browser, and its own test didn't catch this because it
sent no `sec-fetch-site` header); and the path-containment check landed in
`open_document` rather than in `_launch_editor` itself, because
`open_worktree` has no repo root to hand it.
