## What changed

Two independent mechanical fixes, one branch:

**Kraft-nhps (branch slugs):** `work_items` gets a nullable `branch` column
(`src/kraft/db.py` v13→v14 migration). `store.branch_name` builds a slug from
the title plus an 8-char id suffix, filled in at row INSERT. `store.branch_for`
reads that column and falls back to `kraft/<id>` for rows written before the
migration (so items already in flight aren't stranded). `ensure_worktree`,
the forge dispatch, and `abandon`'s worktree cleanup (`builtins.py`,
`executor.py`, `api.py`) now all call `branch_for` instead of hand-building
`kraft/<id>`. Net effect: merge commits on main will read
`kraft/readable-merge-records-branch-slugs-gfm-tables-b63d95be` instead of
`kraft/b63d95be-4188-...`. This work item's own branch predates the migration,
so it still merges under its UUID name — the fix takes effect from the next
item created after this merges.

**Kraft-39un (GFM tables):** `remark-gfm` added as a dependency, wired into
the `react-markdown` instance in both `DocumentModal` and `ArtifactModal`,
plus `table`/`th`/`td` CSS in `.doc-modal-body`. Pipe tables in artifacts and
documents render as actual `<table>` elements now instead of a paragraph of
literal pipe characters.
