## What changed

Diff vs `origin/main` (`git diff origin/main...HEAD`): 11 files, spec+plan
docs plus:

- `templates/registry.yaml` — `on.mr.open`, `on.ci.poll`, `on.mr.sync`,
  `on.merge` change from hardcoded `backend: glab` to `backend: auto`.
- `src/kraft/adapters/forge.py` — new `backend_for(backend, repo_forge)`:
  if `backend != "auto"` returns it unchanged; otherwise looks up
  `repo_forge` ("gitlab"/"github") in a `{gitlab: glab, github: gh}` map and
  raises `ForgeError` if the repo has no forge recorded. `run_task` calls it
  before `resolve`, inside the try block that already guards session
  bookkeeping.
- `src/kraft/templates.py` — `auto` added to `_FORGE_BACKENDS` so registry
  validation accepts it (kept as a literal duplicate of `resolve`'s accepted
  names, per the existing comment convention).
- `src/kraft/executor.py` — `_dispatch` now passes
  `(launch.repo_entry or {}).get("forge")` into `run_task` as `repo_forge`.
- `src/kraft/doctor.py` — new `_binds_auto_forge()` / `_forge_check()`: if the
  live registry has any hook bound to `backend: auto`, `doctor` checks each
  connected repo can actually resolve a backend and that the resulting CLI
  (`gh`/`glab`) is on PATH, reusing `backend_for` itself so doctor cannot
  disagree with the runtime.

This picks option 1 of the three candidates named in the work item (resolve
from the repo's recorded origin at intake/dispatch, not ship `noop` or ship
`gh`). Kraft-rje, the kraft-lite mirror, was already closed the same way
(detect forge from origin remote rather than hardcode a CLI), so this keeps
the two consistent as the work item asked.

## What to double check

- `doctor.py:207` uses `except OSError, ValueError, KeyError, TypeError,
  yaml.YAMLError:` — no parentheses. This looks like Python 2 syntax at a
  glance; it's actually valid under PEP 758 (Python 3.14+), and
  `pyproject.toml` pins `requires-python = ">=3.14"`, so it's fine, but it's
  worth a second look since it reads as a typo.
- `_FORGE_CLI` only maps `gitlab`/`github`. A repo whose `forge` is a
  self-hosted variant or unset gets a `ForgeError` at dispatch (and doctor
  catches it ahead of time) rather than a fallback — this is the documented
  tradeoff ("named, never probed"), not an oversight, but it means a user who
  never set `forge` in Settings → Repos is still blocked until they do.
