**Vocabulary used throughout.**

- *envelope* — the last line of a worker's log, `{"type": "result", ...}`. Read
  by `usage.read_envelope` (`src/kraft/usage.py:76`) and
  `agent._envelope_is_error` (`src/kraft/adapters/agent.py:203`). Unchanged by

- *stream-json* — the CLI's NDJSON mode: one JSON object per line, written as
  the agent works. `{"type":"system","subtype":"init", ...}` first,
  `{"type":"assistant", "request_id": ..., "message": {...}}` per API turn, the
  envelope last.
- *binding* — one entry under `hooks:` in `templates/registry.yaml`, keyed by
  hook point (`on.plan.requested`). Loaded by `templates.load_registry`
  (`src/kraft/templates.py:76`), resolved into an `Invocation` by
  `agent.resolve_invocation` (`src/kraft/adapters/agent.py:135`).

**Deviations from the spec, all deliberate, all argued at the task that makes
them.** Task 4 classifies a `result` line as `sys` (the spec says so; an

## Task 1 — one line-numbering rule, and a log watcher that reads only what is new

### Why

`adapters/subprocess._watch_log` (`src/kraft/adapters/subprocess.py:76`) counts
the lines in the log five times a second by reading the whole file:
`log_path.read_text(errors="replace").splitlines()`. Against today's 0-byte log
that is free. Task 2 makes the log grow to megabytes while the worker runs, so
this becomes tens of MB/s per running worker.

Reading incrementally means counting bytes, which means counting `\n`.
`str.splitlines()` also splits on `\r`, `\v`, `\x1c` and U+2028, so writer and
reader would disagree about which line is line 4 — and the sidecar this thread
writes is keyed by line number. Both sides move onto one rule: split on `"\n"`.

```python
def split_lines(text: str) -> list[str]:
    """The one line-numbering rule, shared by everything that numbers log lines.

    `str.splitlines()` splits on `\\r`, `\\v`, `\\x1c` and U+2028 as well as
    `\\n`; a reader watching a byte stream for `b"\\n"` cannot. Rather than let
    the writer (`adapters.subprocess._watch_log`) and the reader (`jsonl`)
    disagree about which line is line 4 -- the sidecar between them is keyed by
    that number -- both split on `"\\n"` alone. The trailing empty element a
    newline-terminated file leaves behind is dropped; a file that ends mid-line
    still counts that line.
    """
    lines = text.split("\n")
    if lines and lines[-1] == "":
        lines.pop()
    return lines
```

```python
def _watch_log(
    log_path: Path, times_path: Path, stop: threading.Event, poll_s: float = 0.2
) -> None:
    """Record when each new line appeared in `log_path`, into a JSONL sidecar.

    Reads forward from one open handle rather than re-reading the file: under
    `--output-format stream-json` the log grows to megabytes while the worker
    works, and re-reading it five times a second would cost more than the
    worker. Only `b"\\n"` is counted, so a line is stamped when it completes and
    a partial trailing line is carried to the next poll -- the numbering
    `logs.split_lines` defines, which `logs.jsonl` reads back by. Best-effort
    throughout: an I/O error here must never take the session down with it.
    """
    seen = 0
    pending = b""
    try:
        with open(times_path, "w") as times, open(log_path, "rb") as log:
            while True:
                done = stop.is_set()
                chunk = log.read()  # b"" at EOF; the next read picks up new bytes
                if chunk:
                    pending += chunk
                    complete = pending.count(b"\n")
                    if complete:
                        now = datetime.now(UTC).isoformat()
                        for n in range(seen, seen + complete):
                            times.write(json.dumps({"n": n, "t": now}) + "\n")
                        times.flush()
                        seen += complete
                        pending = pending[pending.rfind(b"\n") + 1 :]
                if done:
                    return
                stop.wait(poll_s)
    except OSError:
        pass
```

Two behaviours worth stating, because both are load-bearing:

- The handle stays open across the loop. A plain file object at EOF returns
  `b""` and picks up whatever was appended on the next `read()`, which is what
  makes this a tail rather than a rescan.
- `done` is read *before* the read, and the loop returns *after* it. That is the
  existing contract — the child's last lines are written between `stop.set()`
  and `watcher.join()` in `run_task` (`src/kraft/adapters/subprocess.py:198`),
  and they must still be stamped.

## Task 2 — the worker streams its output

### Why

`Profile.output_json` for the `claude` profile is
`("--output-format", "json")` (`src/kraft/adapters/agent.py:101`), and
`run_agent_task` puts it on every agent command line (line 322). In that mode
the CLI prints one JSON object at exit and nothing before it: a real finished
session's log was one line of 28 442 bytes. That single fact is Kraft-77z (no

(no model, ever) at once.

`--verbose` is not optional: without it the CLI exits 1 with

does not set `stdin`. No hook should be reading the server's stdin, so
`DEVNULL` goes on `run_task` as a whole, not on the agent path alone.

would exercise the shapes tasks 3 and 4 parse.

## Task 3 — live tokens, and a model that is not NULL

### Why

Usage is harvested exactly once, at exit: `run_task` calls `_usage.read(...)`
and `store.session_exited(...)` (`src/kraft/adapters/subprocess.py:214-219`).
While a node is live its `worker_sessions` row holds NULL tokens, so
`store.usage_rollup` (`src/kraft/store.py:486`) reports 0 for the
`current_node_id` and `frontend/src/views/WorkItemDetail.tsx:45` renders
`0 tokens this node`. By the time the row has numbers, `current_node_id` has
moved on: the counter is never right, in either state (Kraft-54dk).

`usage.from_envelope` (`src/kraft/usage.py:63`) reads `envelope.get("model")`.
The envelope has no such key — it has `modelUsage`, keyed by model name — so
`worker_sessions.model` is NULL on every row ever written (Kraft-2r8s).

Both are answered off the stream task 2 turned on: `system/init` carries the
model before a token is spent, and each `assistant` line carries
`message.usage` for its request.

**The counting rule.** Sum `message.usage` across *distinct* `request_id`s. The
stream emits several `assistant` lines per API request with identical usage, so
a naive sum double-counts. The envelope's own `usage` is itself the sum over
requests (measured: `cache_read_input_tokens: 1780049` at the top level against
a single 78 657 iteration entry), so the running total converges on the number
`session_exited` writes at the end.

**No cost, live.** No per-request cost is reported, and cost is only ever the
agent's own number (`src/kraft/usage.py` module docstring). A live row keeps
`cost_usd` NULL until the envelope lands.

**No event.** One progress write every five seconds per running worker, times
every worker, through `events.append` would fan out to the WebSocket, the
indexer and the notifier for a number nobody subscribes to.

```python
#: Reserved key in the caller's `seen` map for the model the `system/init` line
#: reported. A `request_id` can never look like this, and an entry with no
#: tokens adds nothing to the sums, so one map carries both facts across calls
#: -- which it has to, because the init line arrives in a different call from
#: the `assistant` lines that follow it.
_INIT_KEY = "\x00init"


def from_stream(lines: Iterable[str], seen: dict[str, Usage]) -> Usage | None:
    """Fold new stream-json lines into `seen` and return the running total.

    `seen` maps `request_id` -> that request's usage and is owned by the
    caller, which is what makes repeated calls over a growing log correct: the
    CLI emits several `assistant` lines per API request, with identical usage
    on each (measured: two lines, one request), so summing lines rather than
    requests double-counts. The envelope's own totals are themselves the sum
    over requests, so this converges on the number `session_exited` writes.

    Returns None only when nothing has been seen at all, so a caller can tell
    "no usage yet" from "zero tokens so far, model known".

    No cost: no per-request cost is reported, and cost is only ever the agent's
    own number (module docstring). A live row keeps `cost_usd` NULL until the
    envelope lands.
    """
    for raw in lines:
        line = raw.strip()
        if not line.startswith("{"):
            continue
        try:
            obj = json.loads(line)
        except json.JSONDecodeError:
            continue
        if not isinstance(obj, dict):
            continue
        model = obj.get("model")
        if obj.get("type") == "system" and isinstance(model, str) and model:
            seen.setdefault(_INIT_KEY, Usage(model=model))
            continue
        message = obj.get("message")
        if not isinstance(message, dict):
            continue
        u = _from_usage_block(message.get("usage"), message.get("model"))
        if u is None:
            continue
        request_id = obj.get("request_id")
        # A line with no request_id cannot be deduplicated against anything;
        # key it on its own position so it is counted exactly once.
        key = (
            request_id if isinstance(request_id, str) and request_id else f"{_INIT_KEY}{len(seen)}"
        )
        seen[key] = u
    if not seen:
        return None
    return Usage(
        sum(u.tokens_in for u in seen.values()),
        sum(u.tokens_out for u in seen.values()),
        None,
        next((u.model for u in seen.values() if u.model), None),
    )
```

```python
def _read_new(path: Path, offset: int) -> tuple[str, int]:
    """Complete lines written since `offset`, and the offset to resume from.

    A partial trailing line is left where it is rather than decoded half-formed
    -- the log is a stream and the writer is mid-flush. Best-effort: an
    unreadable log is "nothing new", not a failed session.
    """
    try:
        with open(path, "rb") as fh:
            fh.seek(offset)
            data = fh.read()
    except OSError:
        return "", offset
    cut = data.rfind(b"\n")
    if cut < 0:
        return "", offset
    return data[: cut + 1].decode("utf-8", "replace"), offset + cut + 1
```

```python
#: Rendered lines are capped here. The modal renders every line and a
#: `tool_result` for a large file read is tens of KB; the plain-text endpoint
#: (`FileResponse`, api.py) serves the file itself and stays whole.
MAX_TEXT = 2000


def _shorten(text: str, limit: int = MAX_TEXT) -> str:
    return text if len(text) <= limit else text[:limit] + "…"


def _decode(line: str) -> dict | None:
    """The line as a JSON object, or None if it is not one."""
    stripped = line.strip()
    if not (stripped.startswith("{") and stripped.endswith("}")):
        return None
    try:
        obj = json.loads(stripped)
    except json.JSONDecodeError:
        return None
    return obj if isinstance(obj, dict) else None


def _blocks(obj: dict) -> list[dict]:
    """`message.content[]`, where stream-json nests tool use and text.

    Every block, not just the first: an assistant message routinely leads with
    a `thinking` or `text` block and carries its `tool_use` after it.
    """
    message = obj.get("message")
    content = message.get("content") if isinstance(message, dict) else None
    return [b for b in content if isinstance(b, dict)] if isinstance(content, list) else []


def _classify_obj(obj: dict | None) -> tuple[str, str | None]:
    if obj is None:
        return "stdout", None
    kind = obj.get("type")
    if kind in ("system", "result"):
        # the stream's own bookkeeping: the init line, the rate-limit lines and
        # the final envelope are the session speaking, not the agent
        src = "sys"
    elif kind in ("tool_use", "tool_result") or any(
        b.get("type") in ("tool_use", "tool_result") for b in _blocks(obj)
    ):
        src = "tool"
    else:
        src = "agent"
    t = obj.get("timestamp") or obj.get("t")
    return src, t if isinstance(t, str) else None


def classify(line: str) -> tuple[str, str | None]:
    """(source, timestamp) for one raw log line."""
    return _classify_obj(_decode(line))


def _tool_target(inp: object) -> str:
    """The one argument worth naming beside a tool: its path, pattern or command."""
    if not isinstance(inp, dict):
        return ""
    for key in ("file_path", "path", "pattern", "command", "url", "query"):
        value = inp.get(key)
        if isinstance(value, str) and value:
            return _shorten(value, 120)
    return ""


def summary(obj: dict | None, line: str) -> str:
    """One readable line for the modal and for `kraft view logs`.

    A wall of raw stream-json is not the log Kraft-77z asks for. `text` still
    carries the raw line and the plain-text endpoint still serves the file, so
    nothing is lost -- this is the column a reader scans.
    """
    if obj is None:
        return _shorten(line)
    kind = obj.get("type")
    if kind == "system":
        model = obj.get("model")
        if isinstance(model, str) and model:
            return f"init {model}"
        return f"system {obj.get('subtype') or ''}".strip()
    if kind == "result":

def jsonl(path: Path, *, start_line: int = 0) -> Iterator[dict]:
    """Structured lines from `start_line` onward. Missing file yields nothing."""
    try:
        text = path.read_text(errors="replace")
    except OSError:
        return
    times = read_times(times_path(path))
    for n, line in enumerate(split_lines(text)):
        if n < start_line:
            continue
        obj = _decode(line)
        src, t = _classify_obj(obj)
        yield {
            "n": n,
            "t": t or times.get(n),
            "src": src,
            "text": _shorten(line),
            "summary": summary(obj, line),
        }
```

## Task 5 — SIGTERM with a browser on the board (Kraft-9oab)

### Why

`kraft admin stop` sends SIGTERM and polls for the pidfile to go
(`src/kraft/cli.py:162`). With a browser holding `/ws/events` open the server
never exits, so the poll expires and `stop` reports a failure that is real.

Reproduced minimally: a FastAPI app whose WebSocket handler only ever *sends* —
a `while True` with a 1 s timeout, exactly the shape of `ws_events`
(`src/kraft/api.py:1570`) — with one connected client and one SIGTERM:
`STILL RUNNING after 30s`. The same app with a handler that also awaits
`websocket.receive()`: `EXITED after 0.2s rc=-15`.

Uvicorn's graceful shutdown closes the listening socket (which is why the port
frees within a second) and then waits for open connections to finish. It asks
the WebSocket to close; Starlette surfaces that as a `websocket.disconnect`
message delivered to `receive()`. `ws_events` never calls `receive()`, so it
sits in `asyncio.wait_for(client.queue.get(), timeout=1.0)` forever and
lifespan shutdown never runs. Nothing to do with the executor, the reattach
scanner or a non-daemon thread. `test_sigterm_shuts_down_cleanly_mid_task`
passes because it opens no WebSocket.

## Task 6 — the permission grant becomes a per-node registry key (Kraft-3tw)

### Why

## Task 7 — Kraft answers the permission prompts (Kraft-oor)

### Why

`--permission-prompt-tool mcp__<server>__<tool>` names an MCP tool the CLI
calls instead of prompting a human, whenever `--permission-mode auto` decides
it wants to ask. Kraft already ships that MCP server (`kraft admin mcp`,
registered at user scope by `kraft admin init`), the worker already inherits
it, and `client.resolve_context()` (`src/kraft/client.py:21`) already keys off
`KRAFT_WORK_ITEM_ID`, which `run_agent_task` already puts in the child's
environment (`src/kraft/adapters/agent.py:345`).

This is observability with teeth, not an unblocking: `--permission-mode auto`
(Kraft-8pe) is the functional fix and already shipped. What this adds is the
only channel by which the orchestrator ever learns what a worker decided it was
allowed to do — and it makes task 6's `allowed_tools` load-bearing rather than
decorative.

Four decisions, each argued because each is a place a reviewer will push:

- **A binding with no `allowed_tools` allows everything.** Today `auto`
  resolves those asks silently by itself; a default that denied would turn a
  pure-observability change into a behaviour change on every node at once.
- **Fail closed on an unreachable API.** That is exactly today's behaviour for
  an unanswered ask, so it regresses nothing, and failing open would make
  Kraft's outage a permission grant.
- **No `--mcp-config`.** On an install where `kraft admin init` was never run,
  the flag names a tool that does not exist. Measured: `claude -p ...
  --permission-prompt-tool mcp__nosuch__tool` exits 0 and completes normally —
  the degradation is back to today's behaviour, not a crash. Kraft does not own
  the operator's agent configuration; a doctor check for the registration is
  the better answer. Already filed as **Kraft-lqzx** ("doctor: check the
  kraft MCP server is registered with the agent CLI").
- **No escalation to a human gate.** Gates are chain-level and answered in
  hours; a worker blocked mid-tool-call for hours is worse than a denial it can
  route around.

```python
class PermissionAsk(BaseModel):
    """What `--permission-prompt-tool` hands over: the tool the agent wants to
    use, the arguments it wants to use it with, and the CLI's own id for the
    call."""

    tool_name: str
    input: dict = {}
    tool_use_id: str | None = None


@app.post("/worker-sessions/{sid}/permission")
async def permission_request(sid: str, body: PermissionAsk, request: Request):
    """Answer a worker's permission prompt from its node's grant (Kraft-oor).

    The policy is the hook binding's `allowed_tools` (Kraft-3tw), resolved
    session -> hook_point -> binding. A binding that declares none allows
    everything: `--permission-mode auto` already resolves these asks silently
    today, and a default that denied would turn an observability change into a
    behaviour change on every node at once. A binding that *does* declare an
    allowlist is taken at its word.

    Every decision appends an event. That is the whole point -- it is the only
    way the orchestrator ever learns what a worker decided it was allowed to do.
    """
    st = request.app.state
    row = st.db.read(
        lambda c: c.execute(
            "SELECT work_item_id, node_id, hook_point FROM worker_sessions WHERE id = ?", (sid,)
        ).fetchone()
    )
    if row is None:
        raise HTTPException(404, "unknown session")
    allowed = st.registry.hooks.get(row["hook_point"], {}).get("allowed_tools") or []
    if not allowed:
        decision, reason = "allow", f"{row['node_id']} declares no allowed_tools"
    elif body.tool_name in allowed:
        decision, reason = "allow", f"{body.tool_name} is in {row['node_id']}'s allowed_tools"
    else:
        decision, reason = (
            "deny",
            f"{body.tool_name} is not in {row['node_id']}'s allowed_tools ({', '.join(allowed)})",
        )
    await st.db.write(
        lambda c: events.append(
            c,
            row["work_item_id"],
            "permission_decision",
            {
                "session_id": sid,
                "node_id": row["node_id"],
                "tool": body.tool_name,
                "decision": decision,
                "reason": reason,
            },
        )
    )
    if decision == "allow":
        return {"behavior": "allow", "updatedInput": body.input}
    return {"behavior": "deny", "message": reason}
```

```python
async def permission_request(tool_name: str, input: dict, tool_use_id: str | None = None) -> dict:
    """Ask Kraft whether this worker session may use `tool_name` (Kraft-oor).

    Fails closed, and returns rather than raises: the caller is an MCP tool the
    agent CLI is waiting on, and every failure has to come back in the CLI's own
    contract shape. An unreachable server is a denial -- exactly what an
    unanswered ask is today, where failing open would make a Kraft outage a
    permission grant.
    """
    sid = os.environ.get("KRAFT_SESSION_ID")
    if not sid:
        return {"behavior": "deny", "message": "not a Kraft worker session"}
    try:
        status, body = await _post(
            f"/worker-sessions/{sid}/permission",
            {"tool_name": tool_name, "input": input, "tool_use_id": tool_use_id},
        )
    except ValueError as exc:  # `_send` raises this for a server that is not there
        return {"behavior": "deny", "message": str(exc)}
    if status >= 400 or not isinstance(body, dict) or "behavior" not in body:
        detail = body.get("detail") if isinstance(body, dict) else body
        return {"behavior": "deny", "message": f"kraft {status}: {detail}"}
    return body
```
