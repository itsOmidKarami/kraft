# Land the code the chain writes

Six tasks, one branch, one merge request. Each task is red-first, has its own
test command, and is reviewable on its own.

| Task | Bead / spec section | Deliverable |
| --- | --- | --- |
| 1 | Kraft-f3mv (§2) | `CLAUDE.md` + `AGENTS.md` stop telling a Kraft worker not to commit |
| 2 | Kraft-brq (§1), Kraft-i47n (§7) | commit contract moves into `_CTX`; `_ARTIFACT` loses the false claim |
| 3 | Kraft-fhd1 precondition half (§3) | `open_mr` refuses a dirty worktree |
| 4 | Kraft-nh5m (§4, first half) | `Forge.push`; `sync_mr` pushes before it rewrites the description |
| 5 | Kraft-nh5m (§4, second half) | `merge` refuses a branch ahead of its remote |
| 6 | §5, §6 | `on.mr.sync` gets its own node, after the review gate |

the injected instruction and the repo file must not say opposite things to the
same agent. Tasks 3–5 are independent of 1–2 and of each other. Task 6 depends
on Task 4 only in argument (the sync node is what pushes), not in code.

```python
async def _assert_clean(repo: Path) -> None:
    """Refuse to open a merge request over a worktree with uncommitted work.

    Untracked files are included on purpose: a source or test file the agent
    never `git add`ed is what went missing on work item 5163dd1b. Ignored files
    are excluded by git itself, so `.pytest_cache/` and `.engineering/sessions/`
    (.gitignore:54) do not trip it.
    """
    raw = await _run(repo, ["git", "status", "--porcelain"])
    dirty = [line[3:] for line in raw.splitlines() if line.strip()]
    if dirty:
        shown = ", ".join(dirty[:5])
        more = f" (+{len(dirty) - 5} more)" if len(dirty) > 5 else ""
        raise ForgeError(
            f"{len(dirty)} uncommitted path(s) in the worktree, which would not "
            f"reach the merge request: {shown}{more}"
        )
```

`line[3:]` is the porcelain v1 layout — two status columns and a space before
the path.

Then, as the first statement of `GlabCli.open_mr` (before the `git push` on
line 185) and of `GhCli.open_mr` (before line 233):

### The implementation

In `src/kraft/adapters/forge.py`, directly after `_assert_clean`:

```python
async def _assert_pushed(repo: Path, branch: str) -> None:
    """Refuse to merge a head the remote has never seen.

    If `origin/<branch>` does not exist, `_run` raises ForgeError of its own and
    the node fails loudly — the right answer for a merge with no pushed branch.
    """
    raw = await _run(repo, ["git", "rev-list", "--count", f"origin/{branch}..HEAD"])
    ahead = int(raw.strip() or 0)
    if ahead:
        raise ForgeError(
            f"local branch is ahead of origin/{branch} by {ahead} commit(s); "
            "merging would merge a head the forge has never seen"
        )
```

```python
    async def merge(self, *, repo: Path, branch: str, mr: MR) -> None: ...
```

`FakeForge.merge` (line 84) — signature only, body unchanged:

```python
    async def merge(self, *, repo: Path, branch: str = "", mr: MR) -> None:
```

`_measure_node` runs a node's tasks concurrently (`asyncio.gather`,
`src/kraft/executor.py:389`), so today's `tasks: [on.mr.sync,
on.human_review.requested]` can push before the review brief is written — and
after Task 4 that push is the thing merge is checked against.

The sync node goes **after** the gate: `_gate_artifact` (`src/kraft/api.py:620`)
finds a pending gate's document by scanning the gate node's *own* tasks for a
binding with `artifact:`, so moving the gate onto a sync-only node would leave
`human_review_approval` with no review brief to show.

Nothing keys on the node id — gates resolve by name (`_gate_node_index`,
`api.py:616`) and the SPA renders the gate name, not the node
(`frontend/src/components/Gate.tsx:20`, `views/WorkItemDetail.tsx:376`).
