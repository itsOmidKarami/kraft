1"""Optional Docker isolation for a worker subprocess (Kraft-rki). 

2 

3`--disallowed-tools` is the agent CLI policing itself at Kraft's request, not 

4a sandbox: it does not stop a worker that spawns a shell directly, and a 

5command-scoped allowlist does not help either -- an allowlisted `pytest` 

6still executes a `conftest.py` the implementation node itself wrote, in the 

7same host process, as the invoking user. What a `sandbox:` value looks like 

8is `policy.SandboxPolicy`'s, and which one an item runs in is 

9`dispatch.item_sandbox`'s; this module is how a command actually runs inside 

10one. 

11 

12Isolation here is two halves, and the second is the load-bearing one. The 

13mounts (`docker_argv`) keep the container out of everything it has no 

14business writing. But a worker's own worktree gitdir must stay writable for 

15it to commit at all, and that is where every file git redirects hooks and 

16config through lives -- so `harden_host_git_env` pins `core.hooksPath` (and 

17the other program-valued config keys) for every git Kraft runs, which makes 

18what a worker writes there unable to execute regardless of which redirect 

19file it used. 

20 

21Read docs/superpowers/specs/2026-09-13-worker-sandbox-docker-design.md for 

22the design this implements. 

23 

24Off by default: `docker_argv` is only ever called for an item something 

25sandboxes, with a value its model already validated. 

26"""

57def submodule_refusal(who: str) -> str: 

58 """Why a sandbox and submodule members are refused together (Kraft-dshto, 

59 Ruling 180): one sentence, the same at load, connect, intake, doctor and 

60 for an item already in flight. `who` names what set the sandbox. 

61 

62 A container must write its worktree's gitdir to commit, and a submodule's 

63 gitdir lives inside it (`<worktree gitdir>/modules/<sm>`), so a worker can 

64 plant a hook, `core.sshCommand` or a filter driver there. `push` runs 

65 unhardened, and nothing pins the other two, so host git would run them 

66 as the operator."""

68 f"{who} sets a sandbox, and a sandboxed item cannot mount submodules: a " 

69 "sandboxed worker can write each submodule's gitdir and plant hooks or " 

70 "core.sshCommand there, which host git runs as you when Kraft pushes the " 

71 "submodule (Kraft-dshto). Drop the sandbox, or work on one repository"

89def docker_argv( 

90 cmd: list[str], 

91 cwd: str | Path, 

92 sandbox: dict, 

93 results_dir: str | Path | None, 

94 env: dict | None = None, 

95 name: str | None = None, 

96 result_path: str | Path | None = None, 

97 cidfile: str | Path | None = None, 

98) -> list[str]: 

99 """Wrap `cmd` to run inside `sandbox['image']` instead of directly on the host. 

100 

101 Mounts `cwd` (the git worktree) at its original host path, so every 

102 relative path the agent's own prompt already names stays meaningful 

103 unchanged inside the container -- nothing downstream of this has to know 

104 the process ran in one. Runs as the invoking host uid:gid so a container 

105 default of root does not leave root-owned files behind in the worktree 

106 for a later host-side step to trip over -- `--security-opt=no-new-privileges` 

107 and `--cap-drop=ALL` are what keep that true: without them, a setuid-root 

108 binary in the operator's image (`su`, `mount`, `sudo` all ship in most base 

109 images) lets the worker regain root inside the container and write 

110 root-owned or setuid-root files into the bind-mounted worktree anyway. 

111 

112 Everything else the container can reach is mounted read-only with exactly 

113 the paths this session must write carved back out read-write, rather than 

114 mounted read-write with the dangerous paths shadowed read-only: a 

115 shadow list is a list of the escapes someone thought of (`.git/hooks`, 

116 then `.git/modules/<sub>/hooks`, then `.git/worktrees/<id>/modules/...`), 

117 and the container only has to find the one nobody listed. 

118 

119 `results_dir`: read-only, because a hook legitimately *reads* its 

120 neighbours there (its own `<session>.review.md`, the previous fix 

121 session's result file), but a session writing another session's 

122 `<other>.json` would forge that session's status and findings. Only this 

123 session's own `result_path` is mounted back read-write. `None` for a 

124 launch that is no session and has no results to read (a repository's 

125 `setup_command`, `builtins.run_setup_command`): nothing is mounted. 

126 

127 `<repo>/.git`: read-only, with `objects/`, `refs/`, `logs/` and this 

128 worktree's own gitdir (`<repo>/.git/worktrees/<id>`) read-write -- what a 

129 commit from inside a linked worktree actually writes. That worktree 

130 gitdir has to be read-write wholesale: a commit rewrites HEAD, the index 

131 and per-worktree refs through lockfiles beside them, so the directory 

132 itself must be writable, and every file git redirects config and hooks 

133 through (`commondir`, `config.worktree`, `modules/<sm>/config`) lives in 

134 it. Those are not enumerated here -- `harden_host_git_env` is what makes 

135 them harmless, by pinning `core.hooksPath` and friends on every git Kraft 

136 itself runs, so whatever a worker plants in a file nobody listed still 

137 has nothing to execute it. 

138 

139 A Kraft worktree's `.git` is a file pointing at that gitdir (`git 

140 worktree`'s own layout), outside `cwd` -- without the mount every git 

141 command inside the container fails to find it. That file lives inside 

142 the read-write `cwd` mount, though, so it is shadowed read-only on top: 

143 otherwise a sandboxed worker rewrites it to point at a gitdir of its own 

144 making, complete with a `hooks/` it populates itself, and the next 

145 host-side git command run in the worktree executes that hook as the 

146 invoking host user. 

147 

148 `env` is `run_task`'s own `env=` argument -- e.g. `PYTHONDONTWRITEBYTECODE` 

149 for a fix-loop re-measure -- which is otherwise silently dropped: only 

150 `FORWARDED_ENV` crosses into the container by default. Passed through as 

151 literal `-e NAME=VALUE`, unlike `FORWARDED_ENV`'s bare `-e NAME` (which 

152 copies from docker's own process env, never written to disk). 

153 

154 `cidfile`: docker writes the container's id there once it has created 

155 the container, and leaves no file when it never got that far -- the one 

156 thing that tells docker's own launch failure from the sandboxed 

157 command's (`subprocess._docker_launch_failed`, Kraft-6ltwh). 

158 """ 

159 cwd = str(cwd) 

160 argv = [ 

161 "docker", 

162 "run", 

163 "--rm", 

164 "-u", 

165 f"{os.getuid()}:{os.getgid()}", 

166 "--security-opt=no-new-privileges", 

167 "--cap-drop=ALL", 

168 "-v", 

169 f"{cwd}:{cwd}", 

170 "-w", 

171 cwd, 

172 ] 

173 if results_dir is not None: 

174 argv += ["-v", f"{results_dir}:{results_dir}:ro"] 

175 if result_path is not None: 

176 argv += ["-v", f"{result_path}:{result_path}"] 

177 argv += _gitdir_mounts(Path(cwd)) 

178 if name is not None: 

179 argv += ["--name", name] 

180 if cidfile is not None: 

181 argv.append(f"--cidfile={cidfile}") 

182 for env_name in FORWARDED_ENV: 

183 argv += ["-e", env_name] 

184 for env_name, value in (env or {}).items(): 

185 argv += ["-e", f"{env_name}={value}"] 

186 argv.append(sandbox["image"]) 

187 argv += cmd 

188 return argv

192#: linked worktree writes. None of them is ever executed by git (objects and 

193#: refs are data, `logs/` is the reflog), so read-write here does not hand the 

194#: container host code execution the way `hooks/` or `config` would. 

195_WRITABLE_COMMON_GITDIR = ("objects", "refs", "logs")

198def _gitdir_mounts(cwd: Path) -> list[str]: 

199 """`-v` arguments for the repo gitdir a worktree's `.git` file points at. 

200 

201 Empty when `cwd` has no `.git` at all (never expected for a real 

202 invocation, but this is not the place to raise over it) or already has an 

203 ordinary `.git` directory of its own -- that one is inside `cwd`, already 

204 mounted with it, and nothing extra is needed. 

205 

206 The `is_dir()` guards below are read-write *carve-outs*, not read-only 

207 shadows: a path that is missing stays covered by the read-only mount of 

208 its parent, so a container that creates one gains nothing. (An earlier 

209 revision guarded read-only shadows this way, where a missing path meant 

210 no shadow at all and the container could just create it.) 

211 """ 

212 git_path = cwd / ".git" 

213 if git_path.is_dir(): 

214 return [] 

215 try: 

216 text = git_path.read_text() 

217 except OSError: 

218 return [] 

219 if not text.startswith("gitdir:"): 

220 return [] 

221 # `.git` itself lives inside the read-write `cwd` mount. Left alone, a 

222 # sandboxed worker repoints it at a gitdir it builds inside the 

223 # worktree -- HEAD, objects/, refs/, a config with hooks -- and the next 

224 # host-side git command run there executes the worker's hook as the 

225 # invoking host user. It never legitimately changes for the life of the 

226 # worktree, so shadowing it read-only costs nothing. 

227 mounts = ["-v", f"{git_path}:{git_path}:ro"] 

228 gitdir = Path(text.removeprefix("gitdir:").strip()) 

229 # `<repo>/.git/worktrees/<id>` -> common gitdir `<repo>/.git`. Only that 

230 # one subdirectory is this session's to write; every sibling worktree's 

231 # gitdir stays read-only under the common mount. 

232 common, worktree_gitdir = ( 

233 (gitdir.parent.parent, gitdir) if gitdir.parent.name == "worktrees" else (gitdir, None) 

234 ) 

235 # `logs/` does not exist in a freshly cloned repo, and git creates it on 

236 # the first ref update -- which it cannot do under the read-only mount, 

237 # failing the commit. Creating it here is what git itself would do a 

238 # moment later. 

239 try: 

240 (common / "logs").mkdir(exist_ok=True) 

241 except OSError: 

242 pass 

243 mounts += ["-v", f"{common}:{common}:ro"] 

244 for name in _WRITABLE_COMMON_GITDIR: 

245 path = common / name 

246 if path.is_dir(): 

247 mounts += ["-v", f"{path}:{path}"] 

248 if worktree_gitdir is not None: 

249 # A commit from this worktree writes all over its own gitdir (index, 

250 # HEAD, COMMIT_EDITMSG, per-worktree refs, lockfiles), so this one is 

251 # read-write wholesale -- with the exceptions below. 

252 mounts += ["-v", f"{worktree_gitdir}:{worktree_gitdir}"] 

253 # `commondir` is a file inside that read-write gitdir naming where 

254 # `hooks/` and `config` actually resolve to (the common gitdir 

255 # mounted above). Left writable, a worker repoints it at a directory 

256 # of its own inside the worktree, carrying its own `config` and 

257 # `hooks/pre-commit`, and the next host-side git command run here 

258 # runs that hook as the invoking host user -- the same escape the 

259 # read-only `hooks/`/`config` mounts exist to close, reached through 

260 # the one file that redirects to them. It always exists once a 

261 # linked worktree is created, but is created here too rather than 

262 # guarded with `exists()`, so the shadow can never be dodged by a 

263 # worker that deletes it first. 

264 commondir = worktree_gitdir / "commondir" 

265 try: 

266 commondir.touch(exist_ok=True) 

267 except OSError: 

268 pass 

269 mounts += ["-v", f"{commondir}:{commondir}:ro"] 

270 # `config.worktree` is the other file inside this read-write gitdir git 

271 # reads as part of its config stack -- whenever 

272 # `extensions.worktreeConfig = true` (`git sparse-checkout set` turns 

273 # this on), git reads it in addition to the common gitdir's `config`. 

274 # Left writable, a worker plants `core.hooksPath` there just as easily 

275 # as through `commondir`, and the next host-side `git commit` this 

276 # worktree runs executes that hook as the invoking host user -- the 

277 # same escape, a second file wide. Created here rather than guarded 

278 # with `exists()` for the same reason as `commondir`: it must not be 

279 # dodged by a worker that deletes it first. 

280 worktree_config = worktree_gitdir / "config.worktree" 

281 try: 

282 worktree_config.touch(exist_ok=True) 

283 except OSError: 

284 pass 

285 mounts += ["-v", f"{worktree_config}:{worktree_config}:ro"] 

286 return mounts

289#: Config a repository must not be able to set for a git *Kraft itself* runs, 

290#: because each of these values is a program git executes. 

291#: 

292#: A worker's worktree gitdir is read-write by construction -- a commit writes 

293#: its index, HEAD, lockfiles and per-worktree refs, so the directory holding 

294#: them cannot be read-only, and every file git redirects through lives in 

295#: that same directory (`commondir`, `config.worktree`, `modules/<sm>/config`, 

296#: and whichever one the next git version adds). Enumerating them one shadow 

297#: mount at a time is a list of the escapes someone thought of; this is the 

298#: other side of the same problem, and it does not need the list: whatever a 

299#: worker plants, the host-side git that would have run it is launched with 

300#: these pinned instead. 

301#: 

302#: `/dev/null` as a hooks *directory* resolves every hook to `/dev/null/<name>`, 

303#: which is not a file, so git finds no hook to run. `core.fsmonitor` names a 

304#: program git spawns on `status`; empty is "unset", git's own default. 

305#: 

306#: `diff.external` is deliberately *not* here even though it is the same kind 

307#: of vector: git reads an empty value as the empty command and dies 

308#: ("cannot run : No such file or directory") on every `git diff`, which is 

309#: half of what Kraft does with a worktree. Nothing safe to pin it to exists, 

310#: so that one stays covered by the mounts -- the config files git could read 

311#: it from are the common gitdir's `config` (read-only mount), `config.worktree` 

312#: and whatever `commondir` redirects to (both shadowed read-only). 

313_HOOK_PINS = ( 

314 ("core.hooksPath", os.devnull), 

315 ("core.fsmonitor", ""), 

316) 

317 

318#: Host git never walks into a repository nested in a worktree (Kraft-nx4id). 

319#: 

320#: A worker can build a git repository of its own anywhere in the worktree it 

321#: writes and commit a gitlink to it -- no `.gitmodules`, no declared member. 

322#: That repository's config is the worker's: `filter.<x>.clean`, a textconv, 

323#: an `ext::` remote, anything with a name git will not let `-c` enumerate. 

324#: The main worktree's config is safe to read (the common gitdir is mounted 

325#: read-only, `config.worktree` and `commondir` are shadowed, and git reads no 

326#: `config` from `<gitdir>/worktrees/<id>` itself); a nested repository's is 

327#: not, so what has to hold is that host git never *enters* one. Each of these 

328#: is a way it would, from config the operator (not the worker) may have set: 

329#: `submodule.recurse` makes checkout, reset and rebase recurse, the 

330#: `recurseSubmodules` pair makes fetch and push run inside a submodule with 

331#: its own remotes, `diff.submodule=diff`/`log` and `status.submoduleSummary` 

332#: run diff and log inside it, and `diff.ignoreSubmodules` is the default for 

333#: every `status`/`diff` below -- `dirty` compares only the commit a gitlink 

334#: records, which git reads without spawning anything in the nested repo. 

335#: That last one is only a default: a `.gitmodules` the worker writes can 

336#: override it per path, which is why the calls that compare a worktree also 

337#: pass `SUBMODULES_UNENTERED` on the command line. 

338_NO_RECURSION_PINS = ( 

339 ("submodule.recurse", "false"), 

340 ("fetch.recurseSubmodules", "false"), 

341 ("push.recurseSubmodules", "no"), 

342 ("diff.submodule", "short"), 

343 ("status.submoduleSummary", "false"), 

344 ("diff.ignoreSubmodules", "dirty"), 

345) 

346 

347_HARDENED_GIT_CONFIG = _HOOK_PINS + _NO_RECURSION_PINS 

348 

349#: For every host `status` and worktree `diff` Kraft runs in a worktree: a 

350#: gitlink counts as changed when the commit it points at moves (Kraft-qlsf 

351#: needs that much), but git never runs `status` inside it to look for 

352#: uncommitted edits -- that child process is what loads a planted repo's 

353#: config and runs its filters (review-g1 finding 1). On the command line, 

354#: because a worker's `.gitmodules` can override `diff.ignoreSubmodules`. 

355SUBMODULES_UNENTERED = "--ignore-submodules=dirty"

365def harden_host_git_env(env: MutableMapping[str, str] | None = None) -> None: 

366 """Pin `_HARDENED_GIT_CONFIG` for every git this process ever spawns. 

367 

368 `GIT_CONFIG_COUNT`/`_KEY_n`/`_VALUE_n` is git's own environment form of 

369 `git -c key=value`, and carries `-c`'s precedence: it beats the system, 

370 global, repo *and* worktree config files, so a `core.hooksPath` a worker 

371 plants in any of them loses. Setting it on the server's own environment 

372 once covers every git Kraft runs -- `builtins`, `adapters.forge.git`, 

373 `adapters.forge.run`, `config.git_read`, `index.ingest`, the worktree 

374 teardown in `api.routes.lifecycle` -- and every git those spawn in turn 

375 (a submodule's, a rebase's), without each call site having to remember. 

376 Doing it per call site is what left `git worktree prune` and 

377 `git submodule update` running a worker's hook while `git commit` had 

378 `--no-verify`. 

379 

380 Kraft's own worker sessions inherit it too (they are children of this 

381 process), so a repo hook does not fire on an agent's commits either -- 

382 the same thing `adapters.forge.git` already asked for explicitly with 

383 `--no-verify`. 

384 

385 `adapters.forge.git.push` is the one exception, running with 

386 `unhardened_git_env()` instead: see that function for why. 

387 """ 

388 _pin(os.environ if env is None else env, _HARDENED_GIT_CONFIG)

391def unhardened_git_env() -> dict[str, str]: 

392 """A copy of the process env with `harden_host_git_env`'s hook pin lifted. 

393 

394 For `git push` alone: by the time Kraft pushes, the commit is already 

395 made and the worktree gitdir's hooks are either read-only-mounted 

396 (sandboxed) or none of a worker's business to have tampered with in the 

397 first place (unsandboxed) -- so the pinned `core.hooksPath=/dev/null` 

398 is no longer buying anything there, only breaking real hooks a human 

399 installed, like git-lfs's pre-push (Kraft-rki). 

400 

401 Only that pin: `_NO_RECURSION_PINS` stay, so an operator's 

402 `push.recurseSubmodules=on-demand` still cannot make this push run 

403 `git push` inside a repository the worker nested in its worktree, with 

404 that repository's remotes and `core.sshCommand` (Kraft-nx4id). 

405 """ 

406 env = dict(os.environ) 

407 _pin(env, tuple(p for p in _HARDENED_GIT_CONFIG if p[0] != "core.hooksPath")) 

408 return env

418def nested_repos(worktree: Path) -> dict[str, str | None] | None: 

419 """Every path in `worktree` host git could treat as a repository of its 

420 own, mapped to the commit its gitlink records -- None for an untracked 

421 one, which `git add -A` would stage as a gitlink. None when git cannot 

422 read the worktree at all. 

423 

424 Read without entering any of them (Kraft-nx4id): `ls-files -s` is the 

425 index alone, and `ls-files --others` lists an untracked directory holding 

426 a `.git` as `path/` without opening it -- neither parses the nested 

427 repository's config, let alone runs anything from it.""" 

428 staged = _ls_files(worktree, "-s") 

429 untracked = _ls_files(worktree, "--others", "--exclude-standard") 

430 if staged is None or untracked is None: 

431 return None 

432 found: dict[str, str | None] = {} 

433 for entry in staged: 

434 meta, _, path = entry.partition("\t") 

435 mode, sha, _ = meta.split(" ", 2) 

436 if mode == "160000": 

437 found[path] = sha 

438 for path in untracked: 

439 if path.endswith("/"): 

440 found[path.rstrip("/")] = None 

441 return found

444def _gitlinks_at(worktree: Path, rev: str) -> dict[str, str] | None: 

445 done = subprocess.run( 

446 ["git", "ls-tree", "-r", "-z", rev], cwd=worktree, capture_output=True, text=True 

447 ) 

448 if done.returncode != 0: 

449 return None 

450 links = {} 

451 for entry in done.stdout.split("\0")[:-1]: 

452 meta, _, path = entry.partition("\t") 

453 mode, _, sha = meta.split(" ", 2) 

454 if mode == "160000": 

455 links[path] = sha 

456 return links

459def planted_repos(worktree: Path, base: str | None) -> list[str] | None: 

460 """The nested repositories in a sandboxed item's `worktree` its worker 

461 made, which no host git may be let near -- or None when git cannot say. 

462 

463 A sandboxed item declares no submodules (Ruling 180 refuses the pairing), 

464 so none of these is Kraft's: an untracked nested repository, a gitlink 

465 whose directory holds a `.git` (git enters those), and a gitlink the 

466 branch added or moved since `base`. A gitlink `base` already had, left 

467 unpopulated, is the repository's own and inert -- git has nothing to 

468 enter -- so it does not stop a sandboxed item on a repo with submodules.""" 

469 found = nested_repos(worktree) 

470 at_base = _gitlinks_at(worktree, base) if base else {} 

471 if found is None or at_base is None: 

472 return None 

473 return sorted( 

474 path 

475 for path, sha in found.items() 

476 if sha is None 

477 or os.path.lexists(worktree / path / ".git") 

478 or (base and at_base.get(path) != sha) 

479 )

482def planted_refusal(who: str, paths: list[str]) -> str: 

483 """Why a sandboxed item with a nested repository stops (Kraft-nx4id).""" 

484 return (

493async def teardown(session_id: str) -> None: 

494 """`docker rm -f` this session's container, best-effort. 

495 

496 The one place a session's container is torn down, called from every path 

497 a session can *end* on -- `run_task`'s `finally` (normal exit, pause, 

498 skip, timeout) and `reattach`'s (a session adopted or resolved after a 

499 Kraft restart). The pid Kraft signals is `docker run`'s own client 

500 process, not the container: the container is parented by the docker 

501 daemon, so a killed -- or restarted-away-from -- client leaves it running 

502 with the worktree still mounted (Kraft-rki). 

503 

504 Safe to call for a session that never had a sandbox at all: the name 

505 (`container_name`) simply matches nothing, and `docker rm -f` on an 

506 unknown name is a no-op this swallows. That is deliberate -- the callers 

507 are "a session ended" points, and making them each first work out whether 

508 this one was sandboxed is how a path gets missed. Errors (already gone, 

509 docker not installed) are not this function's to raise: a container that 

510 is already down is the success case. 

511 """ 

512 try: 

513 proc = await asyncio.create_subprocess_exec( 

514 "docker", 

515 "rm", 

516 "-f", 

517 container_name(session_id), 

518 stdout=subprocess.DEVNULL, 

519 stderr=subprocess.DEVNULL, 

520 ) 

521 await proc.wait() 

522 except OSError: 

523 pass
