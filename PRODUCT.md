# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Developers who hand coding tasks to the agent they already use (Claude Code, Codex, Cursor, Antigravity, OpenCode, Amp, Gemini CLI) and want to step in only where a decision is theirs. Each Kraft instance is single-user: the same person files the work, approves it and owns the machine it runs on.

## Product Purpose

Kraft is a local orchestrator that takes a coding agent from spec to pull request, stopping only when a decision is the person's: approving the spec, approving the plan, reviewing the change, and the final call before merge. Between those stops it runs on its own in an isolated git worktree and branch, with tests, repairs and retries bounded by caps on attempts, time and spend. Success is a person who hands a task over and walks away, instead of babysitting a session to the end.

## Positioning

Chain templates are data, and gates are enforced in code: an agent cannot start past a gate, skip one, or approve its own work. Kraft is not another coding agent; it runs the one the person already uses and adds the process a single session cannot hold.

## Operating Context

- One local process per machine, bound to loopback by default; reachable from a phone through a tunnel.
- Surfaces: the web UI (board, item page, review page, analytics, templates, settings; a phone layout below 768px), the `kraft` CLI (verbs grouped as item, view, repo, admin), MCP tools for agents, and a terminal UI (`kraft console`) for the board, an item, the server, repos and add-ons.
- Work items move through a chain of nodes and gates; the board groups them as Needs you, Running, Not started and Done.
- Repos are connected with their test and setup commands; add-ons extend the template library from git collections.
- The console is opened for a quick check-in between tasks, when the server, an add-on or a repo misbehaves, as an always-on pane, and over SSH on a machine running Kraft.

## Capabilities and Constraints

- Statuses, actions and stop reasons are computed by the server (`src/kraft/vocab/`); which actions an item allows comes from the server, not from each surface.
- Caps stop runaway work and hand the person the trace.
- The console is local-instance only: it runs on the machine where the server runs.
- Undecided: whether bare `kraft` opens the console in the next major release (tracked as Kraft-idm43).

## Brand Commitments

- Name: Kraft (German for force; its English cousin craft means skill).
- One vocabulary: statuses, actions and stop reasons use the same words on every surface.
- The server's own words: refusals and errors are shown as the server words them, not rephrased per surface.
- Plain, sentence-case wording ("Needs you", "approve spec", "failed at tests").

## Product Principles

- The decision is the person's; everything else runs on its own.
- Show what needs the person first.
- Every surface tells the same truth in the same words.
- Bounded, never runaway: caps stop work and explain why.
- Local and single-user first.

## Accessibility & Inclusion

- Contrast floors hold in every look, as the web's theme generator and its contrast tests enforce.
- Colour never carries meaning alone: every coloured state also has a word or a mark.
